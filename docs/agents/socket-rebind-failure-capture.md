## Recording and provenance

Keep at most 32 KiB of encoded fixture events in memory. On failure only, add at most 64 KiB of runtime goroutine text and emit one JSON summary, capped at 256 KiB, to ordinary test output before cleanup. Report dropped events, encoding errors, stack truncation and finalization scope. If finalization wins while an admitted rebind attempt has no observed result, mark the summary incomplete and identify the address, unavailable result and elapsed time since entry; elapsed time is not a completed operation duration. Finalization does not wait for the bind to return. A missing summary after a process timeout or interruption is incomplete evidence; the normal Go timeout stack and available command output can still survive. Passing reports are discarded. No fixture-owned files or persistent local reservations are added.

Reuse `.github/scripts/http-capture.py` for the normal and race unit commands, retaining its eight 32 MiB slots (256 MiB total), output quota, child exit status, checksums and run ID. The unit-source option excludes only `integrationtests` from source patch/status/untracked queries and records this exclusion explicitly. It requires that directory to be absent, matching the existing unit workflow's deliberate deletion. Other tracked changes remain in the bounded patch; other untracked files make source provenance incomplete. Do not silently treat a full integration checkout as this tested source scope. The Go summary carries the matching wrapper run ID, arguments and relevant environment; direct local test output without the wrapper lacks full source provenance.
