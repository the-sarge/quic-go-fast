# Preserved capture-check child evidence

## Accepted contract

This is the user-approved one-PR contract for [#718](https://github.com/the-sarge/quic-go-fast/issues/718). It extends the [HTTP capture contract](http-failure-captures.md) and the [hotswap capture contract](hotswap-failure-capture.md). `TestHTTPCaptureFixtureFailure` and `TestHTTPCaptureHotswapPassingCleanup` run the captured fixtures as child processes with `QUIC_GO_HTTP_CAPTURE_DIR` pointed at a private `t.TempDir()`. A natural child failure, such as the 318-record #188 hotswap capture from 2026-09-22, used to be deleted with that directory, and only a truncated assertion quotation survived. Completion means installed and verified preservation. It does not resolve #188 or #151. #151 stays open and keeps waiting for natural evidence. #188 closed on 2026-10-05, folded into the #717 darwin correction; preservation still retains a recurrence under its [reopen criterion](https://github.com/the-sarge/quic-go-fast/issues/188#issuecomment-5988020304).

When a capture check's own assertions fail and the outer process has `QUIC_GO_HTTP_CAPTURE_DIR`, the check preserves the child's evidence in a new slot of that outer directory before the private root is removed. Passing checks are unchanged: the controlled-failure capture stays private and is removed. With the outer directory unset, only a log line is added; it names the private root and the variable that would have preserved it. The checks' fixtures, arguments, timeouts and assertions are unchanged, so a natural child failure still fails its parent.

Non-goals are the darwin wildcard-socket correction (#717), #151's idle-timer contract, any #188 repair, changes to the command wrapper, workflows, CI upload or retention, and preservation when no outer directory is set.

## Representation and evidence

The preservation code and its regressions are maintained verification aids owned with the #151/#188 capture fixtures; their payoff is that the next natural capture-check failure is retained. Retire them with those fixtures. This document is process metadata. There is no production change and no new dependency. The existing recorder owns slot reservation, quota, byte budget, checksums and completeness reporting; preservation reuses `openHTTPCapture` and `finish` rather than adding an allocator. The supported domain is these capture checks on the existing integration matrix, with example-level coverage. Contract closure is not triggered.

The approved blast radius is test-only. A preserved slot draws from the same eight-slot pool, so a failed check uses one of the slots a CI job has left for later failures. The checksum now hashes every regular file in a slot, one line per file in the CI finalizer's line format and byte order; the finalizer's own rewrite can order lines differently on Windows. An ordinary slot holds only `capture.jsonl`, so its `SHA256SUMS` bytes are unchanged. The new subprocess regression adds about one second to the self suite.

Finite evidence is one red/green cycle at two seams. `TestHTTPCaptureCheckPreservation` re-executes the binary as a capture check whose child fails naturally before the controlled seam; it shows the parent still fails, the preserved slot's provenance and full child capture (matched against the child's own checksum), and the outer-unset log line, and runs the real reconnection fixture's passing check to show no outer slot appears; if that real check fails, its temporary outer directory is itself preserved into the retained one. The idle fixture is not used there, so the suite gains no second exposure to its intermittent #151 early-idle failure. `TestHTTPCaptureCheckPreservationQuota` and `TestHTTPCaptureCheckPreservationBudget` show quota refusal without overwriting and visible budget truncation. `TestHTTPCaptureAttachSourceFailure` shows that a source read failure, during the copy or the read-ahead, keeps the copied prefix, records the error as dropped and lets later attachments and finalization continue. One guard-deletion mutation of the failed-check guard turned the passing-check case red. Existing `TestHTTPCapture` cases discharge inherited storage obligations. No platform campaign, repetition or stress gate is allocated.
