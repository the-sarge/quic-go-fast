# Maintained-code and test-helper conventions

This guide codifies the [archived conventions survey](x-devonthink-item://562E78F3-42C7-48B4-998E-52263ADC7874) from audit revision `a5bb7f9145755a6c40482eda8cdde4c9a68b4dbf` for [issue #72](https://github.com/the-sarge/quic-go-fast/issues/72). Representative sources were rechecked at `94bd804347a959acf6aa42dfd003a1ecb686f367`. The survey records historical observations, including defects subsequently fixed; it is not a current defect list.

## Scope and authority

Maintained production code, behavioral tests, generators and reusable tools are the scope for future targeted maintenance. **Enforced** below means an existing configured tool check; **contract** means an accepted repository decision; **observed** means a local practice to follow when relevant, not a new universal lint rule. Read the current configuration and nearby package code before changing anything. This documentation does not authorize a style sweep or change implementation.

Preserve public API and wire compatibility ([ADR 0001](../adr/0001-upstream-compatibility.md)) and the declared `github.com/quic-go/quic-go` module identity ([ADR 0002](../adr/0002-adopt-through-module-replacement.md)). Preserve packet-emission ownership: the private emission module owns construction through the concrete packer, recovery registration and output handoff; the connection goroutine owns protocol state and the send worker owns socket I/O ([ADR 0004](../adr/0004-packet-emission-ownership.md)). Conventions do not move those responsibilities.

Closed experiment scripts, captures, profiles, receipts and historical prose are frozen evidence, including experiment helpers outside `docs/audits/`. Preserve their bytes, paths and hashes; use the [archive index](../audit-evidence.md) and each experiment's contract to identify them. Do not format, regenerate or modernize them in a maintenance sweep. Generated output and frozen evidence are different classes. Issue [#18](https://github.com/the-sarge/quic-go-fast/issues/18) governs cleanup before separately authorized collector reuse; the finite evidence scopes of [#44](https://github.com/the-sarge/quic-go-fast/issues/44) and [#46](https://github.com/the-sarge/quic-go-fast/issues/46) remain intact. A new maintained tool needs its own scope rather than silently converting historical evidence into a validation dependency.

## Existing enforcement

[`.golangci.yml`](../../.golangci.yml) is authoritative for enabled linters, formatters and exclusions. It configures `gofmt`, `gofumpt` and `goimports`; dependency rules reject Ginkgo/Gomega in favor of standard Go tests, restrict random-number and RSA imports, and apply package-specific HTTP/3 and `quicvarint` restrictions. Generated-file handling, `internal/qtls`, test-file and path exclusions are intentional; do not describe the rules as exception-free.

The [lint workflow](../../.github/workflows/lint.yml) checks module tidiness, generation, compiler assertions and static analysis, and rejects `//go:build ignore` in Go files. The [generation script](../../.github/workflows/go-generate.sh) checks that regenerated output matches committed files. The optional [pre-commit hook](../../.githooks/README.md) checks staged Go formatting and vendor-fixture module tidiness in an isolated checkout; standard-test and helper conventions remain owned by the configured linters and code review. Error grammar, helper prefixes, comment density and universal script strict mode are not separately enforced by these checks.

## Error grammar and failure boundaries

**Observed:** errors generally use concise lower-case wording; `quic:`, `http3:` and `http:` prefixes provide context at the relevant boundary. Preserve official protocol/field capitalization and meaningful local differences. For example, [`client.go`](../../client.go) returns `quic: tls.Config not set`, while [`http3/client.go`](../../http3/client.go) combines unprefixed internal sentinels with contextual public errors. Typed transport/application errors and local sentinels serve different callers. Avoid mechanical prefix, capitalization or punctuation rewrites of externally observable errors; preserve error identity and wrapping behavior unless the task intentionally changes them.

**Observed:** invalid peer input, I/O and expected operational failures normally return errors; impossible internal accounting and invalid programmer-supplied encoding parameters may panic. [`send_stream.go`](../../send_stream.go) guards negative outstanding-frame accounting. [`quicvarint/varint.go`](../../quicvarint/varint.go) uses a typed `varintLengthError` panic for out-of-range integers and string panics for invalid requested lengths; preserve its typed form and performance rationale. An input-validation defect is not justified by this panic convention. Logging dialects differ between transport, HTTP/3 and qlog; logging or process exit is not a substitute for an API's failure contract.

## Naming, constructors and layout

**Observed:** exported `New...` names construct values, `Dial...` and `Listen...` perform network operations, and private `new...` names assemble objects. `get...` also appears in access and fixture helpers. Follow nearby receiver names and vocabulary rather than imposing one prefix across packages. [`client.go`](../../client.go) distinguishes address convenience dialing from dialing on a caller-owned socket; [`connection_test.go`](../../connection_test.go) legitimately has both `newServerTestConnection` and `getLongHeaderPacket`. Do not rename public entry points or introduce an options framework for uniformity.

Production code and colocated package tests, explicit wire/qlog schema structures and platform-suffix variants are normal here. Repeated schema fields or platform implementations alone do not justify abstraction. Preserve generated and Go-derived provenance headers; change maintained generator inputs and regenerate outputs through their declared commands. In particular, [`sys_conn_buffers.go`](../../sys_conn_buffers.go) is handwritten generator input, whereas `sys_conn_buffers_write.go` is generated output.

## Tests and helpers

**Enforced:** use standard Go tests under the configured dependency restrictions. **Observed:** descriptive `Test...` names, testify `require`, targeted tables and explicit local fixtures are common; assertion-library choice and helper prefixes are not universal rules. Mark reusable setup/assertion helpers with `t.Helper()` so failures point to callers. Keep helper names descriptive of setup, action or assertion, following the package's vocabulary.

Share narrow mechanics such as GSO decoding or repeated setup when they actually repeat; retain scenario-local assertions, explicit buffer ownership and cleanup, and real packet construction. Preserve real-packer coverage at emission entry points: do not replace it with mocks of the packer or copies of production decision logic. The [emission entrypoint test plan](../adr/2026-09-08-emission-entrypoint-tests-plan.md) owns that coverage boundary. A generic fixture framework is not the goal of a helper cleanup.

Modern concurrent unit tests use `testing/synctest`; integration tests retain real UDP/TLS boundaries. Choose synchronization that demonstrates the behavior under test and wait for helper workers to finish before releasing their buffers/resources. Virtual-time sleeps inside a synctest bubble can express the intended timing behavior; do not remove them merely because real-time polling elsewhere needs repair. Preserve the existing integration and captured-evidence contracts rather than converting every test to one timing model.

## Maintained scripts and comments

**Observed:** maintained Bash entry points declare their interpreter and failure handling, but differ in strictness: [the ClusterFuzzLite build script](../../.clusterfuzzlite/build.sh) uses `set -euo pipefail`, while [key generation](../../internal/testdata/generate_key.sh) and the Go generation script use `set -e`. For new maintained Bash tools, prefer a Bash shebang and `set -euo pipefail`, with intentional nonzero outcomes handled explicitly; this is guidance for future work, not a claim of existing universal enforcement or permission to rewrite archived scripts. Reusable Python tools should expose arguments and ordinary functions with a clear entry point. Keep one-shot archived analysis in its historical form.

**Observed, with API/ownership contracts:** comments explain protocol/RFC choices, unsafe or platform behavior, lifetime, ownership and performance tradeoffs; public API comments describe caller-visible behavior. Place the explanation near the constraint it protects, as in [`packet_emission.go`](../../packet_emission.go). Correct contradicted maintained prose in the task that owns the behavior; do not impose a comment-density quota or delete useful explanations as noise. Historical experiment prose continues to describe its recorded revision.
