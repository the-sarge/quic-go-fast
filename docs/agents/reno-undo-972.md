# Default-Reno all-spurious cutback undo

Status: approved by the operator on 2026-10-22 through Planit for [#972](https://github.com/the-sarge/quic-go-fast/issues/972). This is the current implementation and review contract. Review chronology, dispositions and exact candidate receipts belong in the PR discussion. Dependencies #970 and #961 are merged; adaptive thresholds are not a prerequisite.

## Outcome and invariants

Default Reno restores only its latest fully resolved cutback, using [ADR 0011](../adr/0011-recovery-registration-prefix.md)'s typed identities and complete eligible-send frontier. The Reno controller owns the current cutback and a constant-sized snapshot of the prior window, slow-start threshold, ACK credit and cutback state. A prior prefix snapshot is not a competing independently updated frontier. Eligible ACKs can clear the snapshot's recovery status so restoration cannot revive recovery already exited relative to that prior boundary. HybridSlowStart retains its independent receive round.

Every actual loss supporting the candidate contributes unresolved debt, including additional cuts suppressed by the active boundary. Membership is strictly after the saved prior cutback, when present, and at or before the current cutback prefix. Losses already reflected in the saved state do not support this candidate. Missing Initial/Handshake evidence and evicted or expired application receipts leave debt unresolved. The counter does not infer completeness from retained-history occupancy. Once it reaches zero, consume the candidate and restore saved state; if the window has grown above the saved value, consume the candidate and leave the grown state intact. No loss statistics, frame actions or flight subtraction are reversed.

The handler supplies admitted, once-only, unexpired typed receipts through the existing private controller interface. The legacy tracker remains limited to 64 application-space number/time records; 0/1-RTT share identity. Diagnostics preserve matching-record consumption before strict three-PTO send-age cleanup. Undo separately checks that send time is not strictly before the cleanup cutoff before admitting a receipt. Existing validation precedes receipt discovery, including on late-only and reordered ACK branches. Late-only restoration refreshes qlog window metrics.

Current-ACK legacy CE validation and newly declared losses precede spurious receipts. Recovery's existing zero-lost-byte callback denotes validated CE; real congestion losses carry their positive packet length. CE invalidates pending undo even if the extra cut is suppressed, and a CE-only cut creates no candidate. A new real accepted cutback supersedes the previous candidate. Preserve legacy ECN's advancing-largest and nonempty-newly-live guards, including typed retired anchors.

Retry, Initial/Handshake discard and rejected 0-RTT invalidate the controller candidate without moving recovery's current prefix. Retry and rejected 0-RTT clear disposed legacy application history. Migration retains its history reset and fresh Reno sender. Existing direct controller timeout/migration resets also invalidate undo. BBR's new compatibility callbacks are inert: rich feedback, ordinals, delivery accounting, episodes, CE/ProbeRTT caps, persistent congestion and lifecycle reset dispatch retain their existing owners and 32,768-outcome/4,096-retained-delivery bounds.

## Boundary and design cost

One product PR covers `internal/congestion`, the affected handler receipt/lifecycle paths, generated congestion mocks, colocated maintained tests, domain/decision documentation and Unreleased notes. [ADR 0012](../adr/0012-reno-spurious-loss-undo.md) records the narrow ADR 0009/D04 amendment. ADRs 0001/0003/0004, public APIs, wire contracts, controller selection, parameters, emission ownership, frame/buffer lifetimes and unreliable DATAGRAM semantics remain binding. Frozen assessment/prototype artifacts remain unchanged reference evidence, not CI inputs.

The controller snapshot and debt counter add synchronous, constant sender storage, with no new execution context, side channel, dependency or per-packet field. A BBR evidence dependency or retained reconstruction ledger was rejected because either adds retention and cross-owner consistency obligations; revisit only after an explicitly approved ownership redesign. Upstream's shared numbering/history rewrite was rejected because it changes closed transport contracts; revisit only if those contracts are reopened. Splitting the coherent private callbacks and undo behavior was rejected on merit. No material blast-radius choice remains untraced inside this boundary.

Adaptive thresholds, frontier redesign, mandatory ordinals/maps, BBR model/evidence replacement, new APIs, broad emission refactoring, benchmarks, performance claims and native qualification are non-goals.

## Representation, artifacts and evidence budget

The supported input domain is decoded structurally valid ACK ranges admitted through the existing handler lifecycle and trusted registered typed callback facts. The wire parser owns range syntax, the handler owns unsent/skipped validation and retained receipt identity/age/consumption, and Reno owns candidate membership, debt and restoration. Malformed in-memory ACK structs, arbitrary unregistered peer numbers, and calls into already-discarded spaces are outside this caller contract. Universal runtime obligations apply to every admitted identity, supporting callback and once-only receipt in that domain. Finite maintained tests provide behavioral evidence, not exhaustive protocol-history proof.

Contract closure is triggered for restoration safety: incomplete or stale feedback can erase a real congestion response across independent loss, CE and lifecycle paths. The finite semantic matrix below owns the evidence scope. One representative positive case per behavior and negative case per materially different failure mode is sufficient; use existing focused tests for preserved prefix, ownership and BBR families. No mutation campaign, fuzz expansion, extra platform matrix, statistical repetition or recursive verification of the verification aids is authorized.

Runtime undo is shipped behavior. Completeness, CE, age and disposal guards are required safety enforcement. Maintained regressions are explicitly approved verification aids and merge gates: their payoff is preventing unsupported congestion restoration and repeated lifetime actions; recovery/congestion maintainers own them until equivalent coverage replaces them or the behavior is retired. Generated mocks support existing tests and do not define runtime authority. This contract, layout observations, receipts and journal are process/traceability metadata.

## Acceptance criteria

- [ ] Maintained real-handler/default-Reno tests prove the one-loss and all-loss cases restore 38,400 → 26,880 → 38,400 bytes in the frozen setup, including saved slow-start threshold, ACK credit and correct prior prefix. Cover proof after recovery exit and a window already larger than the saved value; undo never shrinks that window or reactivates recovery on an old ACK.
- [ ] A remaining genuine loss prevents undo. Every suppressed loss callback remains part of completeness; genuine Initial/Handshake loss cannot be canceled by application receipts. Superseding cutbacks discard old eligibility, and new genuine losses in the same ACK as old proof retain the newer 18,816-byte reduction under the frozen scenario.
- [ ] Real ECN-tracker tests establish validation and cover applicable CE before, with and after spurious proof, including a suppressed additional cut and present/retired anchors. Old proof cannot cancel CE; duplicate/reordered feedback cannot restore or cut twice. Retain the legacy ECN guards and #961 typed-anchor semantics.
- [ ] Duplicate/overlapping receipts are consumed once. Expiry, disposal, missing history and 77 losses exceeding the 64-record bound prevent incomplete restoration. Preserve three-PTO cleanup and constant bounded proof state without retaining payloads or adding a per-packet mapping ledger.
- [ ] Prefix tests preserve strict equality, absent spaces, shared 0/1-RTT identity, overlapping Initial/Handshake/application numbers, excluded registrations before/after the eligible frontier and interleaved spaces. Suppressed callbacks cannot move the boundary, MTU ACK eligibility remains correct, and HybridSlowStart keeps its independent round boundary.
- [ ] Retry, key discard, rejected 0-RTT and migration invalidate stale undo proof without resurrecting disposed packets. Preserve pooled lifetimes, exactly-once flight/frame retirement, emission ownership and the prohibition on application DATAGRAM retransmission.
- [ ] Existing BBR tests preserve complete/mixed/superseded/missing-episode undo, delivery/ordinal accounting, CE/ProbeRTT caps, persistent restart/deduplication, PTO outcomes and lifecycle resets. The slice is independently correct under existing fixed thresholds; adaptive thresholds are not required for it to land.
- [ ] Fresh maintained regressions, affected recovery/congestion suites, race tests, vet and relevant repository CI pass at the candidate HEAD. Run emission/coalescing and 0-RTT/TLS integration checks as affected by the final callback/lifecycle diff. Record final sender/packet layout and target; no per-packet growth is attributable to undo and no performance improvement is inferred from layout.
- [ ] Document this separately accepted default-Reno behavior in maintained domain/design documentation and release notes, including a narrow ADR 0009/D04 amendment beyond #961's ordering correction. Preserve ADRs 0001/0003/0004, controller selection, public/wire contracts and BBR sidecar ownership. Leave frozen assessment/prototype evidence unchanged.
