## Capture boundaries and interpretation

`http_capture_helper_test.go` installs an independent recorder in `TestHTTPServerIdleTimeout` and `TestHTTPReestablishConnectionAfterDialError`. It is enabled in ordinary runs without DEBUG. Each connection trace records its endpoint role, initial connection ID and client dial attempt where applicable. Connection observations retain addresses and local pointer identity. Typed transport events include Initial/Handshake packets, recovery/PTO progress, handshake state and close causes; HTTP events and fixture milestones distinguish handler activity, response headers and application body consumption.

The idle-timeout callback records each dial, its result and successful connection publication. The fixture-local atomic pointer retains the latest connection across the single GET's sequential retries, so observation cannot block a retry or select an obsolete first connection. The fixture records body-copy and body-close outcomes. HTTP debug records observe timer start, stop/reset and fire, endpoint addresses and handshake completion state. Stop/reset observations do not assert that an already running callback was canceled. The reconnection fixture explicitly records its deliberate first-dial sentinel and subsequent real dial attempts. It checks response headers only; its `body_not_consumed` event is not a body-completion claim.

Capture lifetime continues after `DialAddrEarly` returns. Early success is not handshake completion. `pre_teardown` is written before the existing client/server cleanups; subsequent observations have phase `cleanup`. The recorder's final cleanup cancels and joins its own connection watchers. A watcher reports observed connection closure or its final handshake/cause snapshot, without extending network deadlines or waiting for a live connection to finish. Existing fixture shutdown bounds remain unchanged. The separately repaired retry handoff no longer waits for an observation consumer. Other process interruptions can still prevent cleanup; completed direct writes remain available.

Event admission, synchronous encoding while borrowed event storage is valid, and persistence share serialization with finalization. No capture lock spans network I/O or connection observation waits. Finalization rejects later observations. This borrows #308's admission principle without modifying or depending on the corruption fixture's capture lifetime or socket recorder. A clean terminal means that admitted records within this recording window were retained, not that later protocol events are impossible or that every producer has closed.

These are connection-level observations, not a pre-demultiplexing packet capture. Missing events do not establish that a packet was never sent or received. Timestamps report observer execution and do not provide a total causal order across endpoints. No TLS secrets or raw packet payloads are captured. Existing qlog schema encoders own their event fields.

## Storage, provenance and CI

`QUIC_GO_HTTP_CAPTURE_DIR` selects an exclusive capture directory. Direct local tests default to `quic-go-http` under the OS temporary directory. The recorder atomically reserves one of eight `slot-N` directories. A slot permits at most 32 MiB including reserved summary/checksum space; eight slots bound the directory to 256 MiB for recorder-owned artifacts. Directories use owner-only permissions and Go capture files use mode 0600. Passing, intact test captures remove only their own files and reservation. Failure, incomplete recording, and interrupted runs retain their slots. Quota exhaustion is reported rather than deleting earlier evidence. Users can archive and remove retained slots when finished with them; there is no automatic age-based local deletion.

CI's command-output recorder reserves slots from the same pool. Its log budget is 31 MiB with the remaining MiB reserved for bounded source patch, metadata, result and checksums. Event records have a 256 KiB encoded-line ceiling; oversized events are omitted and counted rather than producing invalid JSON fragments. The event capture reserves 8 KiB for its terminal and 1 KiB for checksum output. A job can exhaust the pool after repeated failures or interruptions; later attempts report missing recording. This is an explicit finite retention limit, not a claim that arbitrarily many failures fit.

The [command wrapper](../../.github/scripts/http-capture.py) preserves the child's exit status and forwards its output to the existing JUnit pipeline. `run.json` binds the command and environment to actual checkout HEAD/tree (including synthetic merges), platform, Go version, run identity and source patch hash. `source.patch` records bounded tracked local instrumentation; untracked files make `source_complete` false. The verbatim output retains the actual `-test.shuffle` seed, independently of the requested `-shuffle=on` setting. Captures carry the matching run ID, test binary arguments, QUIC version, timescale and source status. Direct local tests without the wrapper lack a retained full command log/seed; dirty source without the matching patch is incomplete provenance. Use the wrapper on a committed source revision for attributable local evidence.

For example, with an absolute capture directory in the environment:

```sh
python3 .github/scripts/http-capture.py --label local-v2 run -- go test -count=1 -v -timeout=5m -shuffle=on ./integrationtests/self -version=2
```

`SHA256SUMS` hashes exact retained bytes. Each test writes its hash after cleanup, and the unconditional CI finalization step hashes available files again, including captures interrupted before cleanup. A checksum does not establish complete evidence. Check `capture_finished`, `dropped`, `encoding_errors`, `complete_recording_window`, `result.json` byte counts/truncation/errors, metadata completeness, and stderr recording errors. A missing result, terminal or checksum indicates incomplete finalization; output errors may prevent writing their own status. Quota failures appear in command output. File writes survive ordinary process termination without a userspace recording buffer, but power loss, an interrupted last line, runner loss and canceled artifact upload are outside the guarantee. Synchronous filesystem operations assume a responsive ordinary local filesystem; there is no hard deadline for a stalled disk syscall.

The integration workflow records its existing self-suite invocations, including QUIC v1/v2 and the existing GSO/ECN variants, without changing their flags or test timeouts. Upload runs on all job outcomes independently of DEBUG, with 14-day retention. Command logs are also retained for passing runs; successful test capture slots are released. Download the `http-<os>-go<version>-race<mode>` artifact together with the full GitHub job log.
