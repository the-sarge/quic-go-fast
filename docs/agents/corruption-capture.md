## Capture design

The corruption fixture appends a separate JSONL handshake prefix to disk while events occur, finalizing at Dial return before teardown. The existing bounded failure tail remains available for later transfer failures. A successful fixture deletes its prefix; failures and process interruption retain it. CI collects the configured directory on all job outcomes independently of DEBUG/qlog. Locally the directory defaults to `quic-go-corruption` under the OS temporary directory; `QUIC_GO_CORRUPTION_CAPTURE_DIR` overrides it. Files use unique names and owner-only permissions.

The prefix contains scenario/toolchain/environment metadata, phase transitions, qlog, original datagram bytes and parsed coalesced packet boundaries before mutation, exact selected byte changes, and observed proxy/endpoint socket results. Endpoint observation preserves the concrete socket's syscall/OOB support and uses the existing batch-read mechanism. Socket-write success remains distinct from endpoint read and protocol processing. Event timestamps are observations and do not promise total causal ordering.

The persisted prefix ends at the synchronized Dial finalization boundary. It contains observations appended before that boundary, not every operation that might have started earlier and completed or reached its observer later. Raw socket bytes and OOB control data identify batch submissions separately from individual datagrams. Each observed receive-batch call records its result count/error and a per-socket batch identifier; each returned datagram names that batch and its index/count. Packet boundaries are parsed on original proxy datagrams before replacement; parse errors retain the raw bytes and the unparsed range. The normal short-header remainder is the final packet in a coalesced datagram.

Records are written directly to the file without a userspace buffer. The prefix has a 32 MiB event budget and a 256 KiB data limit per record, with a reserved terminal summary and explicit incomplete evidence. Missing finalization, overflow, encoding errors or write errors invalidate a claim of complete capture. Successful system writes survive ordinary process termination; this does not guarantee power-loss durability, runner survival or successful artifact upload after cancellation. The final line can be partial if interrupted mid-write. No finite diagnostic system guarantees every possible cause; completeness applies only to these recorded boundaries.

Synchronous serialization and disk writes affect scheduling. This observer effect is accepted for this diagnostic aid and must be disclosed when interpreting a capture. No deadlines or random distributions are adjusted to compensate. Raw encrypted datagrams enable byte/boundary inspection and correlation, not deterministic replay of live TLS, UDP timing or scheduling. Do not capture TLS secrets.

## Reading a retained capture

Retrieve the job's `corruption-<os>-go<version>-race<mode>` artifact as well as its complete job log. Captures are retained for 14 days by the configured upload step. A successful fixture removes its file; a failure, incomplete cleanup or output error can leave one. A retained file alone does not prove a Dial failure: inspect the test name, scenario, phase and terminal outcome.

Verify the `capture_start` record, valid complete JSONL lines, and `dial_finished` outcome. Cleanup before a Dial return is explicitly described as `fixture cleanup without Dial completion`; do not treat that as a completed Dial. Check for `capture_limit`, `[capture record truncated]`, qlog `encode_error`, nonzero `dropped_or_truncated`, file-error messages and missing/partial finalization. A clean terminal record is a recording-boundary statement, not a proof that every causal variable was observed.

For a Dial timeout, compare the recorded absolute context deadline with the phase and recovery events. Correlate original proxy datagrams and selected changes with socket submissions, proxy forwarding results, endpoint reads and protocol receipt/drop/ACK/CRYPTO events. Preserve source addresses: immediate replacements still bypass the normal proxy delay and originate from the endpoint socket. A batch write is not a datagram, a successful write is not a read, and a read is not authenticated packet processing. Only make a missing-recovery claim when the requisite timer, keys, outstanding data and sending eligibility are established by retained evidence.
