# Owned Datagram admission (#1292)

[Capability issue #1292](https://github.com/the-sarge/quic-go-fast/issues/1292) implements the retained ownership mechanism from [wiremux pipeline investigation #2304](https://github.com/GridSwarm/wiremux/issues/2304). This additive capability keeps the declared upstream module identity and ordinary APIs compatible. It does not select a jumbo product contract, change packet packing or qualify a release.

`Conn.SendDatagramOwnedContextV1` validates and admits a caller-owned payload through the existing 32-entry Datagram queue, with the same peer/path size validation, unreliable delivery and context-error/no-admission guarantee as `SendDatagramContext`. The context must be non-nil. Success transfers the allocation: the caller must never access or reuse it afterward. An error leaves it caller-owned. Empty payloads remain valid. Existing `SendDatagram` and `SendDatagramContext` continue to copy and protect callers that mutate or reuse their payload after return.

`Conn.SealDatagramAdmissionV1` lets an exclusive owner permanently fence Datagram admission before connection teardown. It takes an opaque caller-supplied cause (nil defaults to `net.ErrClosed`) and the existing queue send mutex, then publishes the first terminal cause and wakes blocked operations. No later admission crosses that fence after it returns. Already admitted Datagrams remain unreliable. Enabled receives still drain queued or later incoming payloads; an empty receive returns the first terminal cause. An owner keeping the connection live must manage receive draining or proceed with teardown to avoid filling the existing receive bound shared with packet processing. Reliable streams, protocol state, packet emission and connection lifetime keep their existing owners. Calling the seal repeatedly, or later closing the connection, is safe. Disabled send/receive support retains its own validation error even with an initialized queue; an absent queue is a separate harmless no-op case.

Ordinary `datagramQueue.CloseWithError` keeps its existing non-locking precondition: connection shutdown and the established blocked-add/closure regression can publish closure while the send mutex is already held. A queue-owned `sync.Once` supplies first-cause, idempotent publication. Only the new explicit admission seal acquires the send mutex. Do not move that lock into ordinary Close or add a second terminal state owner.

Wiremux can select both capability methods together to transfer the single framed copy it already owns directly into this queue. Its native intermediate queue/pump and second payload copy then disappear; its old-fork and ordinary-carrier fallbacks remain unchanged. The fork still owns queued payloads through packing and buffer serialization. No pool, additional queue, sampler or goroutine is introduced, and queued payload capacity does not increase.

The original four physical captures in [comparison issue #2301](https://github.com/GridSwarm/wiremux/issues/2301) and [report PR #2302](https://github.com/GridSwarm/wiremux/pull/2302) remain unchanged. The old-pin disposable prototype reached 7.999313/7.999470 Gbps locally with 0.00857%/0.00662% deficit versus current queue controls 5.508190/5.891656 Gbps. Those values establish local feasibility, not physical qualification of current main or an additive gain estimate for each removed operation. The wiremux append-only ledger retains source, predictions, raw inventories and the rejected first close implementation.
