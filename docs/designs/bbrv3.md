# Opt-in BBRv3 for sustained bulk transfers

Status: accepted design, subject to implementation qualification. This is the design artifact for [Settle the implementation-ready BBRv3 design](https://github.com/the-sarge/quic-go-fast/issues/558), within [Design opt-in BBRv3 for GridCast bulk transfers](https://github.com/the-sarge/quic-go-fast/issues/552). It specifies future behavior; no BBR controller or campaign is implemented by this document.

The owner accepted the source-precedence policy and ProbeRTT choice individually, then explicitly delegated the remaining technical decisions: “I need you to think through each of the grilling questions, carefully evaluate, and make the best recommendations. I will accept them all.” The choices below are the agent's recommendations accepted through that delegation, not claims of separate human interviews or measured superiority. Performance adoption remains the owner's later decision under the accepted evidence plan.

## Outcome and boundaries

Provide a built-in BBRv3 sender optimized for sustained STREAM and DATAGRAM traffic over variable WAN paths. Reno remains the default. Each sender selects independently; its peer needs no BBR support or new transport parameter. Existing API method signatures, keyed Config literals, module identity, wire behavior, packet ownership, managed endpoints and platform capability boundaries remain intact. The selected controller also governs reliable control traffic sharing the connection.

The deliverable is an implementation-ready contract, not production qualification. Required tests and the accepted native campaign must establish correctness, performance and resource cost before shipping. GridCast/wiremux changes, a cross-repository execution program, releases and rollout remain outside this effort. Existing evidence is sufficient to select the approach; there is no additional pre-implementation experiment required by this design. Failures of the explicit invariants below reopen the affected choice rather than being excused as advisory performance results.

## Selection and compatibility contract

Add the following optional structural methods, using only existing Go types so a consumer can capability-detect them while still compiling against upstream:

```go
// On *quic.Config:
SetCongestionControlV1(name string) error
CongestionControlV1() string

// On *quic.Conn (read-only, immutable selected identity):
CongestionControlV1() string
```

The setter accepts exactly `"reno"` and `"bbrv3"`. A zero-valued/unconfigured Config selects Reno; an empty string passed explicitly, an unknown name or a nil setter receiver returns an error without mutation. The Config getter returns `"reno"` for an unset or nil Config. No arbitrary controller factory, public tuning fields, environment switch or transport-wide precedence layer is introduced. The Conn getter reports the actual selected controller throughout its lifetime, including after close; it requires no model-state read or synchronization with ACK processing.

Store only a private scalar selection in Config. This additive struct evolution preserves keyed literals and existing fields/methods, but positional Config literals must be converted to keyed literals; the compatibility claim does not include struct layout or positional field-count stability. Treat this narrow source-compatibility exception as part of the accepted API decision and disclose it in the eventual release notes. Set it before passing the configuration to Dial/Listen or returning it from GetConfigForClient; concurrent mutation is unsupported, as with other configuration fields. Clone and every config reconstruction, particularly populateConfig and per-client preparation, must copy it. Effective connection configuration is independent of later setter calls. A non-nil GetConfigForClient result is a complete replacement configuration: an unset result selects Reno, while cloning the listener config preserves BBR. Existing nil callback/default behavior remains unchanged. Setter validation ensures the private selection is representable without adding a new invalid-input path to prepareConfigForClient.

An explicit BBR request on a library lacking the setter must return a visible error in the consuming adapter. Do not silently claim BBR while running Reno. Default/upstream operation requires no optional call. A structural `interface { SetCongestionControlV1(string) error }` assertion is sufficient; downstream code need not name a fork-only Go type. The main application still owns the module replacement under [ADR 0002](../adr/0002-adopt-through-module-replacement.md).

Each connection creates a private built-in policy instance; a path reset creates fresh mutable BBR state while retaining the selected identity. Shared Config pointers never share congestion state. Keep the existing Reno notification ordering and pacer policy intact. BBR-only evidence, loss statistics and persistent-congestion handling must not silently alter default Reno behavior. Correcting Reno's historical CE/loss statistic is separate maintenance.

## State ownership and private boundaries

The connection goroutine owns recovery, delivery sampling, model updates, pacing decisions and path/model transitions. Emission owns construction, registration and owned queue handoff under [ADR 0004](../adr/0004-packet-emission-ownership.md). Socket workers own I/O and buffer retirement. Registration remains before asynchronous submission; no successful-write event becomes transport delivery or moves recovery to a worker.

Use a private event adapter in recovery with two dispatch paths: unchanged legacy Reno callbacks and rich BBR events. Capture transport facts once. BBR's sampler/model live in internal/congestion; recovery passes value records, never imports its packet internals in the reverse direction. Allocate the BBR sidecar only on opted-in connections. Do not enlarge every pooled packet with a full BBR snapshot. A side table owns fixed-size records keyed by packet-number space and packet number, plus a monotonically increasing connection-wide transmission ordinal. 0-RTT and 1-RTT share the application space; path generation and sample generation are distinct from both identities.

The semantic private surface is Send(snapshot), Feedback(event), Retire(identity, reason), SetLimitation(reason), Reset(reason, generation), SetPacketSize(bytes), and read-only send allowance/deadline. Method/type spelling can follow local conventions; their information and lifetime contracts below are fixed. The event contains ACK receive time, space, prior/post flight, delivered/lost packet values, RTT eligibility, ECN result, path/sample generations and any persistent-congestion event. Borrowed scratch is valid only until the synchronous call returns. No frames, payload buffers or pooled packet pointers enter controller storage.

Worker credit feedback is a separate synchronized byte-accounting object. It contains queue reservations/completions and generation identity, not delivery/model state. Workers may return credit and signal availability; only the connection reads it into policy. Completion aggregation must be lossless even if wakeups coalesce. Stopping the worker releases remaining reservations exactly once without waiting for ACKs. No per-packet successful-send timestamp API is required.

## Byte domains, identities and clocks

Model rates use congestion-controlled QUIC packet bytes per second, including recorded packet overhead and each retransmitted transmission. Those bytes differ from UDP/IP link bytes and unique application goodput. Pending queue credit counts complete UDP payload bytes, including coalesced packets and all GSO segments; do not charge IP/UDP headers to the controller's delivery counter. Every GSO member remains an individual QUIC packet identity. Small packets retain actual length.

Use monotime for all control intervals. Registration time is the actual connection-owned registration observation, even when several constructed packets share it. It includes subsequent local residence in measured RTT and delivery intervals. It is not a wire-departure estimate. Do not retrofit a later syscall timestamp into an earlier delivery snapshot. The accepted model shows both usefulness and bias; native qualification must report queue limitation, pending bytes and registration-to-submission residence using bounded diagnostic instrumentation with dropped-observation counts if sampled.

Use checked/saturating integer multiply/divide, floor byte-rate estimates, ceiling pacing deadlines and explicit validity flags. Reject nonpositive intervals and nonmonotonic inputs. Preserve accumulated fractional pacing debt so very low rates eventually send. Check rate/counter overflow before conversion; saturation cannot become permission for an unlimited burst. Debug conversion to existing bits/second helpers is explicit and never changes the model's units.

Let M be the current effective maximum ordinary UDP payload permitted by packetization on this path. BBR's packet-equivalent floors use M, rather than TCP's fixed MSS or the pre-fallback initial size. Handshake size fallback can decrease M; successful PMTU discovery can increase it. Recompute floors, quantization and future send limits without rescaling measured byte rates or historical packet lengths. A changed M cannot enlarge a previously imposed CE allowance except to the new minimum needed for progress. Clamp pending/pacing admission immediately on decreases; preserve any already committed excess as debt. Path-validation probes and MTU probes remain distinct.

## Delivery sampling and limitation

For each congestion-controlled ack-eliciting packet, including DATAGRAM-only packets, record registration time, ordinal, path/sample generations, length, delivered-byte snapshot/time, send-epoch origin, cumulative real-loss snapshot, pre/post flight, outstanding-evidence volume and limitation marker. ACK-only packets and path-validation probes/placeholders create no bandwidth or congestion-loss samples. DPLPMTUD probes contribute actual ACKed bytes when received; exclude them as rate/RTT candidate anchors and from congestion-loss volume/ranges when lost. Their ordinary flight accounting remains recovery-owned.

Before inserting a packet, start a new send sampling origin only when there is no live or retained unresolved delivery evidence and no pending local work in the current generation. Loss-adjusted flight reaching zero is insufficient. Expiry/forced eviction is explicit evidence loss; it is not receipt or proof of idleness. When the last retained record expires, a later send may start a new sample generation; stale-generation ACKs cannot construct cross-generation samples. Monotonic delivered totals do not rewind.

On an accepted logical ACK, count the first acknowledged receipt of every eligible current-generation live or retained packet exactly once, independent of whether recovery still charges its flight bytes. Choose the newest eligible acknowledged transmission by ordinal for the draft-style sample; break same-time ties by ordinal, not ACK range order. Compute the delivery difference over the greater send interval and ACK interval using its frozen snapshot and the final event delivery total. If this chosen snapshot is invalid, reject the rate sample rather than select a faster older sample. Reject intervals shorter than the current measured raw minimum; do not apply an unmeasured initial estimate as this rejection threshold. A packet with no retained snapshot contributes no invented BBR delivery or rate evidence; diagnostics record the exclusion. Recovery's own ACK/frame actions remain valid.

For RTT filtering, use the existing recovery eligibility rule's newly ACKed candidate and its raw registration-to-ACK duration. Do not subtract peer ACK delay in BBR's RTT filters. Continue existing ACK-delay handling in recovery's separate RTT/PTO estimator. Do not re-read LatestRTT as if it were a new measurement. Exclude path/MTU probes and old generations. Before a qualified ACK, use the existing 100ms initial estimate only for initial control-rate calculation. A restored RTT estimate or Retry measurement does not seed a measured BBR minimum. This conservative choice can retain receiver delay and local queuing in BBR's estimate; the native evidence must expose that limitation.

Application/flow-control supply exhaustion sets a delivery boundary `delivered + unresolved_evidence_bytes` (at least `delivered + 1`) when otherwise permitted ordinary packing finds no eligible data. Preserve the reason and snapshot the marker on subsequent sends until delivered bytes pass the boundary. Mark ProbeRTT samples limited intentionally. Limited samples may raise the bandwidth maximum but do not lower it or advance the Startup plateau counter. Congestion-window, pacing, queue/CPU, receive-work-yield, recovery-history pressure and anti-amplification stops are not evidence of application exhaustion; record them separately. A no-data enum default or one empty queue cannot establish limitation.

Genuine idle restart requires observed application exhaustion, zero current flight, no unresolved delivery evidence and zero pending queue credit. Flow-control blocking is supply-limited for rate filtering but does not qualify as genuine application idle. Resume with at most one send quantum of pacing credit and preserve the draft's idle-restart suppression of unnecessary ProbeRTT entry. Idle time does not release ECN caps. Conservative false negatives are preferable to treating an intentionally constrained or queued sender as idle.

## Event order, losses and retained evidence

Build a complete event before BBR dispatch: snapshot pre-event flight; identify new ACKs including late-only ACKs; preserve recovery/frame actions; validate ECN separately; identify actual losses; copy all required metadata before retirement; finalize post-event flight. Process real-loss inputs in ordinal order before the single ACK/model update, consistent with the draft's per-loss and per-ACK separation. Accumulate delivered bytes before constructing that event's rate sample. Apply CE and persistent-congestion overrides after model transitions and before exposing sending allowance. A timer-only loss event has an explicit monotonic time, no fabricated ACK sample and no bandwidth-round advancement. Keep legacy Reno ordering unchanged.

Count contiguous lost ranges using original packet numbers within one space and the relevant feedback round, deduplicating adjacent runs across callbacks/events. A skipped number, ACKed packet, excluded probe or space boundary separates ranges. Six callbacks do not establish six discontiguous ranges. Preserve real lost bytes for the draft's per-flight/round predicates; CE contributes zero lost bytes/ranges. Packet-timed model rounds use delivered-at-send boundaries from the draft; transmission ordinals resolve cross-space ordering and recovery boundaries, not wall-clock approximations.

Live BBR records are bounded by the existing 25,000 tracked-packet ceiling; ordinary recovery's 20,000 outstanding limit still applies. Retain payload-free tombstones for real loss and PTO extraction, at most 4,096 per connection. Expire each at retirement plus `min(3 * unbacked_off_PTO_at_retirement, 30 seconds)`; when full, evict the oldest ordinal. A fixed-capacity ordinal eviction structure and keyed lookup must not allocate one goroutine/timer per packet. Maintain the expiry deadline in the connection loop so idle traffic cannot retain records indefinitely. Lifetime and count bounds are chosen memory/accuracy trade-offs, not measured optimal sizes.

Expiration, space disposal, rejected 0-RTT, Retry, path replacement and close remove records without delivery or congestion loss. Clear borrowed scratch immediately after dispatch. Reuse event buffers capped at live-plus-tombstone capacity; release excess retained capacity on path reset/close. ACK ranges query retained keys, never iterate enormous absent packet-number intervals. Record occupancy, bytes allocated, eviction and missing-history counters. At any budget breach, reject optional evidence or backpressure sending; never drop mandatory live recovery ownership to make room.

Enter a loss-recovery episode on the first real congestion loss, saving the draft's prior cwnd and model bounds and the largest registered ordinal. Losses of later transmissions extend the recovery boundary and invalidate an earlier all-spurious inference. ACKing a transmission beyond that boundary exits the episode; restore saved cwnd only through current model, CE, ProbeRTT and persistent-congestion caps. Do not add a Reno multiplicative window cut on top of draft BBR loss bounds. PTO alone neither enters this episode nor halves anything.

Enable spurious-loss undo only when every real-loss member of the latest still-relevant episode is subsequently acknowledged with retained evidence, with no intervening irreversible reset, persistent-congestion event or superseding loss episode. Track the episode's exact finite membership; tombstone eviction or missing evidence disables undo. Undo restores only the saved loss-derived bounds/cwnd according to draft maxima and resets the plateau detector; it does not rewind delivered counters, resend frames or remove CE limits. A late ACK can still count once as delivery even when it cannot justify undo. Never infer complete repair from an unrelated late ACK.

Persistent congestion is detected by the BBR recovery adapter from ACK-confirmed loss evidence across packet-number spaces, using [RFC 9002 section 7.6](https://www.rfc-editor.org/rfc/rfc9002.html#section-7.6): measured RTT at send, two lost ack-eliciting endpoints, no intervening acknowledged packet and the specified duration with threshold three. Maintain a send-outcome ledger capped at 32,768 fixed-size entries, ordered by transmission ordinal and covering ACK-only transmissions as well as sampled packets. Evict oldest entries on pressure; a compact prefix summary may retain only a contiguous, fully classified span and its first/last lost ack-eliciting endpoints. Unresolved, evicted-without-proof or disposed gaps break the proof; later feedback cannot retroactively bridge an unknown gap. ACK-only receipts also break a candidate span even though they are not sampled. Timer loss can accumulate evidence, but PTO count is never a substitute and the reduction is established on ACK processing. Qualification must include spans crossing spaces and bounded-history pressure.

Deduplicate persistent-congestion reports by the ending lost-transmission ordinal, so the same span cannot repeatedly reset the new model. On proven persistent congestion, reduce effective cwnd to two M, clear bandwidth/minimum filters and loss-undo state, preserve independent CE safety state, restart in Startup with a two-M initial window and pacing seed based on recovery's current RTT estimate. Start a fresh sample generation; retained earlier packets can still drive recovery but cannot inflate the new model. Suppress the usual four-M BBR floor until at least one new-generation ack-eliciting transmission is acknowledged; subsequently allow ACK-driven growth under model/CE caps. Old ACKs cannot restore the pre-outage window. This is the explicit QUIC replacement for TCP RTO handling.

## Baseline algorithm and ProbeRTT disposition

Implement draft-06's Startup, Drain, ProbeBW phases, bandwidth filters, ACK-phase filter aging, aggregation compensation, loss attribution, inflight bounds and idle logic unless overridden here. Do not port QUICHE's queue-threshold ProbeUP exit or its ignored inflight-hi defaults. Use the draft's gains: Startup approximately 2.77 (its exact defined expression), Drain 0.5, ProbeBW Down 0.9, Cruise/Refill 1 and Up 1.25; ordinary cwnd gain two, Up 2.25. Retain the draft's three qualifying plateau rounds/25% growth, Startup six-range and 2% loss conditions, 0.7 loss-bound retention, 15% inflight headroom and defined recovery-round eligibility. These are source algorithm settings, not performance promises.

Initial BBR cwnd is `min(10*M, max(14720 bytes, 2*M))`, following the QUIC recommended initial window; leave Reno's existing 32-packet setting untouched. After measurement, BBR's ordinary four-M minimum applies except the explicit persistent-congestion restart. Retain the fork's maximum congestion-window/history limits as a resource cap and report when limiting; no larger window is silently introduced to win a high-BDP benchmark. A result limited by the current maximum is a disclosed limitation.

Translate Reno-coexistence probe rounds to `min(63, max(1, ceil(min(BDP, effective_cwnd)/M)))`. The draft's comparison of a byte-valued helper to round count is resolved explicitly in packet equivalents. Preserve randomized 2–3 second probe waits and randomized initial round offset using the repository's approved randomness facility; inject deterministic randomness in tests. Do not adopt the unmerged ACK-phase removal proposal.

Keep five-second ProbeRTT scheduling and the ten-second minimum filter. At the start of each eligible ACK update, before updating bandwidth/minimum filters, save `old_probe_cap = max(4*M, floor(old_model_bandwidth * old_min_rtt / 2))` when an old measured minimum exists. If that event causes ProbeRTT entry, initialize its saved cap from this value; otherwise use the ordinary newly computed draft target. During the entire probe, the target is the smaller of the saved cap and each new half-BDP target, floored at four M. The saved cap can decrease, but a newly inflated RTT or bandwidth estimate cannot increase it during that probe. Clear it on exit/reset. This hybrid selects the safeguard from proposal `fe9a2c9cd06c46cf92d19ee275e22d06f7f413b4` without selecting its single-filter scheme or cadence.

Begin the hold after recovery flight is at or below the effective probe target and local pending work fits that target; require both a newly completed packet-timed round begun there and `now > hold_start + 200ms`. Apply this to all normal exit paths, including a send after idleness; lifecycle teardown/reset is disposal, not successful probe completion. Restore the draft's saved window only through current caps and preserve the draft's next-probe scheduling/filter stamp rules. Independent CE limits survive ResetShortTermModel and ProbeRTT restoration. A probe with a remembered inflated estimate may still leave a queue; a genuinely longer path may be temporarily underfilled. Both are explicit qualification cases, not guarantees hidden by the safeguard.

## Classic ECN response

Enable ECT(0) through the existing eligible metadata path and validator. Never use ECT(1)/L4S, Google's low-latency threshold policy or a marked-byte estimator in this version. On a path with established capability, any eligible positive validated CE delta is congestion, including sustained 100% CE. Testing outcomes retain the existing validation/failure policy; all-CE testing and all-CE feedback after capability are different cases. Capability failure stops outgoing ECT, preserves receive reporting, and does not stop loss-based BBR.

Choose a binary response retaining **0.5** of the pre-event effective pacing rate and flight allowance, with persistent independent caps. The 0.7 alternative and proportional/ABE candidates remain rejected for the initial profile because their milder response has no supporting coexistence measurements here. Half retention is a conservative engineering choice, not a BBR standard or proof of fairness. It can reduce goodput on long-RTT paths; the accepted campaign must show that cost. An optional 0.7 comparison can use remaining campaign reserve only, without removing required cases or changing the chosen shipping profile silently.

The validator produces accepted cumulative ECT(0)/ECT(1)/CE packet counts and exactly-once deltas, eligibility, feedback watermark and generation context. Maintain a marking ledger independent of sampler tombstones, capped at 4,096 range records. A record compresses only consecutive packet numbers with the same actual sent codepoint, path generation, ACK-accounting status and an affine transmission-ordinal mapping; otherwise start or split a record. Record Not-ECT holes from path probes and coalesced short-header packets, and distinguish skipped/unregistered numbers. Numeric membership in a capable epoch is not evidence of marking. Retain actual marking and ordinal anchors for late feedback until a prefix is completely accounted for by individual ACK evidence and accepted cumulative counts; compact only such a prefix into cumulative offsets and its ordinal boundary. If insertion or ACK-induced splitting would exceed the budget, fail marking to Not-ECT before losing evidence and disable new CE/release claims requiring the unavailable detail. Keep accepted cumulative totals and independent existing caps; unknown membership never fabricates newly ACKed marked counts or a response epoch. Unresolved old marking prevents revalidation rather than accumulating unbounded path history. Start with 1-RTT outgoing ECN only, matching the existing path. Do not derive byte marks from packet counters. Never pass invalid/missing/ambiguous evidence as a zero-mark observation.

Do not retain ReceivedAck's early return before examining eligible late-only feedback. Advance ECN validation only on ACKs advancing the accepted largest-ACK watermark, following RFC 9000's reordering guidance. If that ACK refers only to retired marked packets, use independent marking evidence; a live recovery packet is not required. Repeated/lower-largest reports do not cause validation failure or duplicate cuts; defer their counts until a later eligible advancing report. A final count-only update with no advancing anchor may remain unconsumed, recorded diagnostically. This deliberately conservative limitation avoids inventing an attribution rule for reordered counters. On unrecoverable marking evidence, stop ECT rather than pretend validation succeeded.

For a first eligible CE event, take pre-event effective rate R and `F = min(effective_cwnd, max(prior_flight, 4*M))`. Set `CE_flight = max(4*M, floor(F/2))` and `CE_rate = min(R, max(M / T, floor(R/2)))`, with checked rational arithmetic and `T = max(measured_raw_min_rtt if available else recovery_smoothed_rtt, 1ms)`. For an event that also proves persistent congestion, derive CE caps from the pre-event values, then apply the stricter two-M restart; CE cannot restore the prior window. The two-M persistent-congestion restart overrides the four-M floor. If the pre-event effective allowance is already lower because of another cap, the composed result must never increase it. Retain measured bandwidth/RTT knowledge; a cap is not a claim that physical capacity halved.

Record the largest registered ordinal as the CE response boundary. Further eligible CE anchored at or before that boundary is consumed diagnostically without another multiplicative cut. A later eligible CE anchored beyond it cuts again using the then-effective allowances and records a new boundary. The anchor is progress evidence, not identification of which packet was marked; aggregate delayed feedback can conservatively attribute an old mark to a later event. Record that approximation. Counter progress without a retained ordinal is not eligible to relax limits or create a guessed new response epoch.

A CE event exits Startup to Drain and marks full bandwidth reached; it aborts Refill/Up to Down. Down/Cruise retain their draining/cruising behavior under the caps. ProbeRTT continues its measurement with the stricter allowance and retains CE state on exit. While CE caps are active, no new Refill/Up is allowed. Loss and CE from one event compute their proposals from the same pre-event state; apply the stricter resulting allowance, not the product of unrelated multiplicative cuts. Loss still updates every real-loss statistic and recovery fact. Spurious-loss undo never removes CE evidence.

Caps persist through ordinary model updates, ACK aggregation, lower-bound reset, idle/restart and ProbeRTT. A recovery round begins only after an ACK has passed the latest CE response boundary; no pre-response round counts. After one complete such round with no actual congestion loss or new CE and valid advancing ECN feedback, allow one recovery step per subsequent clean round: increase the flight cap by `max(M, floor(CE_flight/16))` and the rate cap by `max(M/T, floor(CE_rate/16))`. Latch loss, CE, missing/ambiguous feedback and supply limitation across the whole round; an isolated clean ACK cannot erase them. Require non-supply-limited traffic for these increases. A round with unavailable feedback, ambiguous attribution or ProbeRTT limitation cannot release the caps. If ECN has definitively failed and outgoing traffic has switched to Not-ECT, use clean ACK/loss rounds beginning after that switch for this gradual recovery; otherwise an ECN failure could freeze the connection indefinitely.

Compare caps against the controller's current uncapped Cruise rate/window target, including current loss bounds. Remove both only once both have reached those targets on a clean round; restart the ordinary ProbeBW wait in Cruise with a fresh schedule. Do not jump to a saved pre-CE peak or grant immediate ProbeUP. New CE resets recovery progress. This roughly six-percent-per-round recovery above the packet floor is chosen to avoid both an immediate rebound and thousands of one-packet rounds on high-BDP paths. It is an explicit experimental extension requiring state-trace and coexistence qualification; it is not a measured optimum.

Validation-failure release rounds must continue to honor any still-eligible already-validated CE feedback from transmissions before failure; failure is not a reason to discard an independently accepted congestion event. No sender-generated CE honesty probes are added. Existing consistency validation cannot prove receiver honesty. Preserve independent loss response and diagnose invalid feedback; stronger receiver-misreporting defenses would be a separate protocol/security design, particularly because platform support for sending CE is not uniform.

## Pacing and pending local work

Use a private BBR pacer with the model's 1% pacing margin; do not pass BBR through Reno's extra 5/4 rate gain or ten-packet minimum burst. Choose `Q = max(2*M, min(65536 bytes, floor(effective_rate * 1ms)))`, the draft-style quantum. Whole-datagram assembly must fit Q and available pacing/window/queue allowance; no ordinary one-datagram overshoot. Packet-sized rounding may leave unused credit. A coalesced datagram is admitted as a whole using its complete byte size.

Pace registration opportunities with a token/debt balance capped at Q, initialized to Q, debited by actual UDP payload bytes admitted and replenished at the effective rate. Deadline uses exact deficit/rate rounded up to the monotonic clock unit; do not inherit Reno's software 1ms minimum delay. At high rates the 64KiB quantum needs sub-millisecond opportunities, while actual OS wakeup precision remains a measured limitation. On rate/quantum decreases, clamp unused credit immediately. Delayed wakeups cannot accumulate more than Q. While stopped for queue capacity, retain no extra catch-up credit beyond Q. Always check both recovery flight and local credit; low actual OS wakeup precision may lower throughput but never authorizes a larger unreported burst.

Bound ordinary pending local work at **2Q bytes**, including producer reservation, queue entries, worker-dequeued groups, in-service GSO/sequential fallback and already accepted prefixes until completion is accounted. Reserve before packing; release unused construction allowance and return committed byte credit exactly once when the worker relinquishes the corresponding buffer after known completion/error/disposal. Return credit after local acceptance or known rejection, not dequeue and not peer ACK. Accepted-prefix handling may release its known prefix separately; it must never resend it. Unknown-progress fatal errors preserve the existing no-retry rule and close the send path. These credit completions do not refund recovery flight or invent delivery/loss.

When Q decreases below existing pending bytes, stop admitting ordinary work until debt drains; do not cancel or rewrite registered packets. Thus the instantaneous queue bound is the admission-time bound until existing reservations complete. It includes retained old-generation queue debt during migration. An I/O batch can combine pending work up to the available 2Q budget, so the maximum submitted group is not necessarily Q. The additional allowance is declared, rather than hidden in eight queue entries. Account two quanta as BBR's user-space offload allowance; do not subtract the same bytes from recovery flight or add another copy of the queue budget elsewhere.

The bound is on user-space pending bytes, not kernel/NIC bytes or actual wire bursts. Over an interval h, a stalled worker can expose its already pending bytes plus newly admitted pacing credit (at most Q plus rate integrated over h); kernel buffering can still combine submissions. Native traces must report this distinction. Tight credit can reduce throughput under worker delay, as the prototype showed. Two Q is the selected compromise; increasing it later requires evidence and a recorded profile change, not automatic platform-specific tuning.

ACK-only traffic and authorized PTO probes retain their existing congestion/pacing exemptions but still respect bounded queue capacity and existing anti-amplification/probe limits; they wait for local credit when necessary. Charge their UDP bytes to pending credit and pace ordinary data only from its own debit balance. A DPLPMTUD probe may exceed ordinary M/Q: permit one isolated probe reservation sized to the probe only when ordinary pending is zero, then admit no other queued work until it completes. This bounds its exceptional debt without deadlocking MTU discovery. Synchronous path-validation sends keep their existing bounded probe rules, remain excluded from the sampler and do not masquerade as ordinary quantum traffic.

## Lifecycle and migration

| Event | Selected contract |
| --- | --- |
| Initial/Handshake key discard | Retire that space's snapshots and tombstones without loss/delivery; retain valid same-path model evidence. Boundaries referencing discarded evidence cannot later justify undo. |
| 0-RTT rejection | Retire rejected 0-RTT snapshots without loss/delivery, invalidate intervals containing discarded evidence by advancing sample generation for future snapshots; existing 1-RTT recovery remains intact. Do not reset the shared packet-number generator. |
| Retry | Dispose Initial/0-RTT BBR records and create fresh model/sample state with the same selected identity. Preserve recovery's existing Retry RTT measurement and packet-number semantics; do not seed a BBR measured minimum from Retry. Retain pending queue credit until completion. |
| PTO extraction | Retain a bounded payload-free snapshot for possible late delivery, tagged as PTO retirement. Do not add congestion loss, a recovery episode or a TCP RTO cut. |
| Ordinary loss / late ACK | Apply the bounded retention and conservative undo rules above; recovery frame retransmission remains independent. |
| Persistent congestion | Apply the explicit two-M new-generation restart; no old-window restoration from old ACKs. |
| Path reset / rebinding that invokes recovery reset | Keep BBR identity; replace the model, measurement filters and sampling/undo state, and clear old path-local CE caps. Do not restore a previously visited path's model in this version. |
| MTU change on same path | Update M and future quantization/floors; keep byte-valued historical evidence. A failed oversized MTU probe does not become congestion loss. |
| Close / fatal worker failure | Stop admissions, join/clean up as existing ownership requires, release all sampler and local credit storage exactly once; ignore later model feedback. |

For a same-connection path reset, tag all future registrations and queue entries with the new path generation. Keep old queue debt visible until its worker completion; old diagnostic records cannot mutate the fresh controller. Preserve the client's old-queue drain/join and the server's existing rebinding semantics. Do not promise that pre-reset queued traffic vanishes: server entries can use the destination current at syscall time. Block new ordinary congestion-controlled admission until the old-generation local queue debt is zero, preserving required control/probe exceptions within total credit. Actual kernel residence remains unknown and is a migration-test obligation.

ECN counters continue across paths in the application packet-number space. On reset, stop ECT immediately for new admissions, retain all cumulative sent/accepted counter state, and enter a drain state. Let S be the total ECT-marked registrations before that stop. Revalidation is allowed only after all old-generation queue entries complete and a valid advancing report accounts for exactly S marked receipts (`ECT0 + ECT1 + CE == S`, with the original consistency checks). No additional ECT packets are admitted while draining. This establishes a counter fence under the existing peer-consistency trust model; it does not identify individual CE packets. Old/mixed CE never becomes fresh-path model evidence.

After that fence, use the accepted totals as offsets, begin a fresh ten-packet path validation on the current generation, and validate new increments against newly marked sends while retaining global cumulative sanity checks. Do not zero on-wire counters or inherit capable status. An old-path marked packet lost or an unavailable advancing report can prevent the fence forever: continue Not-ECT and loss-based BBR for the rest of that connection rather than guess. A fresh connection can validate normally. If no packet was ever marked, the counter fence is immediate after old local queue debt drains. If endpoint capability is unavailable, do not attempt validation. Further resets restart this conservative procedure, never erase its unresolved old-mark total.

This deliberately trades ECN availability after some same-connection migrations for trustworthy attribution. GridCast's pinned migration creates a fresh authenticated connection, so its adoption path starts fresh validation rather than inheriting this counter ambiguity. Native qualification must still demonstrate same-connection fallback/revalidation on both client replacement and server rebinding.
