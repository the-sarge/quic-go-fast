# v0.62.1-fast.4 release record

This is the source preparation record for `v0.62.1-fast.4`, based on upstream quic-go `v0.62.0`, with Go `1.26.0` or newer and the unchanged `github.com/quic-go/quic-go` module identity. The [changelog](../../CHANGELOG.md#v0621-fast4--release-candidate) describes the changes since fast.3. This library distributes source through the Go module proxy and has no binary or container release assets.

Publication follows the [release runbook](../runbooks/release.md). The [GitHub release](https://github.com/the-sarge/quic-go-fast/releases/tag/v0.62.1-fast.4) becomes the immutable publication receipt only after the candidate gates succeed. Until then this document makes no claim that a tag, release, future workflow result or public module version exists. A failed tag gate stops publication and requires a new version; an existing tag is never moved or replaced.

## Changes and compatibility

- HTTP/3 request parsing now follows `net/http` request-target conventions. Ordinary and Extended CONNECT handlers receive path-only URLs and use `Request.Host` for authority; regular CONNECT retains authority form. Invalid path forms are rejected. Applications that read authority from `Request.URL.Host` for ordinary HTTP/3 requests must migrate.
- HTTP/3 stream, request and datagram boundaries now return applicable stream and application failures as `*http3.Error`, possibly wrapped. Callers must use `errors.As` and `errors.Is` rather than direct type assertions or raw QUIC error matching. QUIC control-stream setup errors, EOF, context errors, transport errors and `quic.ErrWouldBlock` retain their existing categories.
- Immediate client close accounts for 1-RTT encryption overhead before coalesced Initial padding, preventing the reported close-packet buffer overrun without changing close semantics or public APIs.
- When `http3.Transport` receives a caller-supplied `quic.Config` with `MaxIncomingStreams` equal to zero, it now clones before applying the private `-1` client default instead of writing that default into the caller's object. Separate direct and callback configuration preparation consistently clips numeric values while preserving the documented direct-input compatibility writes, callback ownership, defaults, negative stream sentinels and version-selection behavior.
- Closed outgoing paths cannot admit new initial or retry probes, `TransportError.Unwrap` omits nil members, and managed lease binding has one endpoint-owned admission operation. These changes preserve the existing public API and wire contract.

The integration-test qlog helper now gives concurrent same-second transports exclusive files, without changing the shipped qlog packages. The dependency graph is unchanged from fast.3. The candidate adds no platform, performance, packet-loss, raw-socket handback or application-adoption claim. The external packet-I/O, fixed-peer and managed-endpoint contracts and rollback instructions remain those documented for [fast.3](v0.62.1-fast.3.md).

## Support and validation boundaries

Unit CI tests Linux, macOS and Windows on Go 1.26.x and 1.27.x. Integration CI tests Linux on both versions and macOS and Windows on Go 1.27.x, with additional Linux race coverage. Targets accepted by the cross-compilation script but not executed in those lanes are build-only; Android remains excluded and iOS validation compiles library packages only. Interop images are validation outputs, not published release assets. Generic CI does not prove native offload engagement.

Before publication, the selected full commit on `main` must pass unit, integration, lint, cross-compilation and interop-image workflows at that exact commit. A fresh `govulncheck ./...` must record its scanner version, Go version, host target, reachable findings and any uncalled module advisories. A separate consumer must build QUIC and HTTP/3 through an application-owned replacement at the candidate commit, then repeat against the public tag and verify the downloaded module version, confirm its origin commit matches the annotated tag's peeled commit, and verify its checksum and archive boundaries.

The intermittent macOS dial, initial-request, reconnection and server-hotswap investigations remain open: [#151](https://github.com/the-sarge/quic-go-fast/issues/151), [#169](https://github.com/the-sarge/quic-go-fast/issues/169), [#188](https://github.com/the-sarge/quic-go-fast/issues/188), [#241](https://github.com/the-sarge/quic-go-fast/issues/241) and [#301](https://github.com/the-sarge/quic-go-fast/issues/301). The historical server-first packet-loss investigation [#44](https://github.com/the-sarge/quic-go-fast/issues/44) also remains open. Passing runs do not establish infrastructure causality or arbitrary-loss recovery. Evaluate the prerelease against application workloads before adoption.

## Adoption and finite evidence

Keep imports under `github.com/quic-go/quic-go`. Each consuming application's main module must select the explicit fork version through a replacement; replacements in dependencies do not propagate. Continue using the published `v0.62.1-fast.3` until this candidate is published, then select the exact new tag and inspect `go list -m -json github.com/quic-go/quic-go` to confirm the replacement. Avoid `@latest`, which can select an inherited upstream tag.

This preparation adds no publisher, maintained evidence collector or new validation framework. The evidence terminates at one exact-source gate, one fresh vulnerability scan, one consumer build at the candidate revision, immutable annotated-tag publication, successful tag workflows, and one public-module consumer verification. Release notes must record the tag object and peeled commit, workflow URLs, scanner and Go versions, module checksum and archive identity, compatibility boundaries, and the absence of assets.
