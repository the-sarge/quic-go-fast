# v0.62.1-fast.7 published release record

The published prerelease is `v0.62.1-fast.7`, based on upstream quic-go `v0.62.0`, with Go `1.26.0` or newer and the unchanged `github.com/quic-go/quic-go` module identity. Dependencies are unchanged from fast.6. Public API changes are additive `V1` methods, plus one narrow source-compatibility exception for positional `Config` literals. The [changelog](../../CHANGELOG.md#v0621-fast7--2026-10-05) describes the rollup. This library distributes source through the Go module proxy, without binary or container release assets. The [GitHub release](https://github.com/the-sarge/quic-go-fast/releases/tag/v0.62.1-fast.7) holds the final validation and provenance receipts.

The operator selected source `55ea687d68c9c6f33785a1875374ec6a0d7570e8`, the `main` commit recording the [dial-owner drain merge #704](https://github.com/the-sarge/quic-go-fast/pull/704), after GridCast had tested that commit through its CI. Later `main` changes, including single-family client socket binding [#726](https://github.com/the-sarge/quic-go-fast/pull/726) and the HTTP/3 idle-timer start [#730](https://github.com/the-sarge/quic-go-fast/pull/730), are not included.

## Changes and compatibility

`Config.SetCongestionControlV1("bbrv3")` selects a built-in BBR draft-06 sender per configuration; `Config.CongestionControlV1` and the immutable `Conn.CongestionControlV1` report the selection. Reno remains the default, and connections that do not opt in are unchanged. The [BBRv3 program](../adr/2026-09-24-bbrv3-program.md) and [ADR 0009](../adr/0009-opt-in-bbrv3.md) describe the design.

BBRv3 in this release is experimental and must not be selected for production traffic. It has not passed native qualification ([#599](https://github.com/the-sarge/quic-go-fast/issues/599)). A qualification attempt and local reproduction found severe goodput and resource regressions against Reno in this implementation ([#666](https://github.com/the-sarge/quic-go-fast/issues/666)); corrections are under investigation and are not part of this release. The selection API is available so consumers can build against it; it makes no performance claim.

Adding the private selection field changes `Config`'s field count, so positional (unkeyed) `Config` literals no longer compile and must be converted to keyed form. Keyed literals, existing fields, methods and runtime behavior are unchanged. ADR 0009 records this exception to the source-compatibility promise and requires this disclosure.

The connection-admission extensions are opt-in; transports that do not configure them keep ordinary behavior. Each method's doc comment is the contract.

- `Transport.ConfigureNetworkAdmissionV1` installs receive and send predicates on the transport's packet connection. Rejected input is dropped before any QUIC or non-QUIC dispatch, and every socket submission is checked again. The restricted profile disallows `Conn.AddPath` and preferred-address adoption. It does not authenticate peers.
- `Transport.ConfigureSetupAdmissionV1` and `Transport.ConfigureDialSetupAdmissionV1` bound accepted and dialed connection setup with a caller-owned reservation and deadline, acquired before connection allocation. `Conn.TransferSetupReservationV1` releases a reservation to the established connection. Refused client attempts are remembered for a bounded time so trailing Initials cannot re-acquire capacity.
- `Transport.CandidateGroupV1` groups transports whose connections race as candidates. Selecting a winner fences new connections and unknown-connection-ID responses, discards the losers' queued work, closes and revokes them, and drops late input without stateless resets, including server-queued Initials and 0-RTT packets.
- `Transport.ConfigureReceivePhasesV1`, `Conn.OpenReceivePhaseV1` and stream `ReadReceivePhaseV1` gate DATAGRAM delivery and label stream bytes with the receive phase in which the connection admitted them.

These extensions were built for [GridCast's G30 work](https://github.com/GridCastIO/gridcast/issues/1329). CI now pins Go 1.27.1 and 1.26.8 exactly with `GOTOOLCHAIN=local`; the module's `go 1.26.0` minimum is unchanged. Test reliability changes cover the setup-admission and candidate-group tests, Q6 test transport cleanup and the macOS dial-owner probe's output drain ([#581](https://github.com/the-sarge/quic-go-fast/issues/581)).

## Support and limitations

Unit CI tests Linux, macOS and Windows on Go 1.26.8 and 1.27.1. Integration CI tests Linux on both versions and macOS and Windows on Go 1.27.1, with additional Linux race coverage. Targets accepted by the cross-compilation script but not executed in those lanes are build-only. Managed ECN and path-MTU qualification from fast.6 is unchanged. Generic green CI does not establish native offload engagement or BBRv3 performance.

Open investigations include macOS socket rebind after cancellation [#241](https://github.com/the-sarge/quic-go-fast/issues/241), Ubuntu path-MTU counts [#322](https://github.com/the-sarge/quic-go-fast/issues/322), the combined HTTP/3 convenience-server lifetime [#424](https://github.com/the-sarge/quic-go-fast/issues/424), macOS migration packet counts [#434](https://github.com/the-sarge/quic-go-fast/issues/434), the Darwin 25 ECN receive timeout [#528](https://github.com/the-sarge/quic-go-fast/issues/528) and `Transport.Close` read-loop waiting [#719](https://github.com/the-sarge/quic-go-fast/issues/719). The HTTP/3 server idle-timer fix for [#151](https://github.com/the-sarge/quic-go-fast/issues/151) merged after the release source and is not included.

## Adoption and rollback

Keep imports under `github.com/quic-go/quic-go`. Each consuming application's main module selects this explicit fork version:

```sh
go mod edit -replace=github.com/quic-go/quic-go=github.com/the-sarge/quic-go-fast@v0.62.1-fast.7
go mod tidy
go list -m -json github.com/quic-go/quic-go
```

Replacements in dependencies do not propagate. Avoid `@latest`, which can select inherited upstream tags. Verify application workloads before adoption. Rollback selects `v0.62.1-fast.6` in the same application-owned replacement and runs `go mod tidy` again; it removes the `V1` methods above, so callers using them must be reverted first.
