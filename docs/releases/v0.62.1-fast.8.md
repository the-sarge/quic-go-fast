F5 saturation may refuse ACK-carrying packets; the residual dequeue-to-push window remains. F1 does not count receive-phase withholding/invalidation or protocol violations. F11's guard also trips on a genuine oversized single datagram while URO is on; merged reads at or below the ceiling can be undetectable. Managed readers preserve above-20-KiB whole-datagram behavior where documented; ordinary Linux oversized input retains its 1,452-byte prefix. These limits are not enlarged into a jumbo-datagram guarantee.

## Segmentation and platform switches

The short-segment cap is 64, retaining compatibility with older Linux kernels and the tested Windows USO shape; the 20 KiB send buffer usually binds earlier at consumer payload sizes. `QUIC_GO_DISABLE_SHORT_GSO_SEGMENTS=true` disables only short equal-size gluing. `QUIC_GO_DISABLE_GSO=true` disables segmentation and `QUIC_GO_DISABLE_GRO=true` disables receive coalescing (Windows URO included). Existing receive permission, endpoint capability and platform qualification still apply. Darwin batched sends retain `QUIC_GO_DISABLE_SENDMSG_X` and the private-syscall build-tag opt-out. A green generic platform suite does not prove native offload engagement.

## Corrected BBR and subsequent recovery

The frozen BBR implementation in fast.7 is replaced by the [corrected r9 production port](../agents/bbr-production-port.md): C1–C3 recovery-service corrections, C4 draft-06 conformance, bounded ECN feedback, quantum-release pacing, kept per-packet allocation/work reductions, Linux netpoller kick and BBR queue depth. Discovery scratch is released after each ACK range and reset. Later corrections retire ECN ledger records below the reported span, mark supply limitation only when a gap costs sending time, follow draft-06's loss prefix, and separate latest-stop diagnostics from active limitation. The bundle subsequently gives every controller queue depth and cap 32.

Shared recovery now uses registration order across packet-number spaces ([#981](https://github.com/the-sarge/quic-go-fast/pull/981)), fixes spurious-loss discovery/history hygiene ([#985](https://github.com/the-sarge/quic-go-fast/pull/985), #970), and restores the latest fully proved spurious default-Reno cutback with its slow-start state and ACK credit ([#988](https://github.com/the-sarge/quic-go-fast/pull/988), #972). Genuine loss, validated CE, lifecycle disposal, bounded history and independent BBR feedback remain protected. The Reno sender grows by 72 constant bytes in #972's recorded darwin/arm64 layout; this is not attribution of the historical #871 RSS increase.

BBRv3 remains **experimental, opt-in and unqualified**. `Config.SetCongestionControlV1("bbrv3")` selects it; Reno remains the default. Historical readiness and exceptions apply only to their recorded revisions. Fresh Linux readiness and advancement under [#990](https://github.com/the-sarge/quic-go-fast/issues/990) block publication. This fixture does not exercise F8's batched-send cap (nor gluing through its nil batch callback), and does not qualify macOS or Windows. Full Q2 qualification [#599](https://github.com/the-sarge/quic-go-fast/issues/599) is a later campaign. Adaptive loss thresholds [#971](https://github.com/the-sarge/quic-go-fast/issues/971) are excluded and deferred until after publication; parent #962 stays open.

Carried historical costs include the quantum-release S5 drop-tail overflow increase (0.13% → 0.84% in its recorded experiment), Linux run-loop wake increase, and DATAGRAM sender CPU increase from the BBR queue change. These are bounded historical observations; new readiness must report its own values and flags without inheriting an exception.

## Other changes since fast.7

The [complete release comparison](https://github.com/the-sarge/quic-go-fast/compare/v0.62.1-fast.7...a8013b22c623330ce166c5135c3b5966f8b1fcb2) ends at the preparation base; the final comparison must end at the pinned release SHA. In addition to the bundle and BBR/recovery work:

- QUIC: restrict [GSO-error fallback (#817/#809)](https://github.com/the-sarge/quic-go-fast/pull/817) to writes with nonzero segment size; unsegmented errors return after one submission without disabling GSO. Bind address-helper client sockets to a single family; wait for the receive loop when created-socket closure fails; keep MTU discovery disabled after path changes when disabled/unsupported; restrict handshake-size fallback to unset InitialPacketSize and trigger at the second eligible PTO, including Version Negotiation recreation; validate Version Negotiation connection IDs and discard it after Retry; bound default handshake admission, implicit incoming-stream allocation and path-probe history; enforce per-path amplification limits; retry server path validation within bounded attempts; reject DATAGRAM sends after closure and preserve canceled receives/cancellation causes; reject oversized packets before serialization (#979); ignore reliable-boundary updates after cancellation.
- HTTP/3: start the server idle timer after handshake completion; incrementally buffer response/trailer headers and bound incomplete request-header resources; reject truncated Content-Length bodies; retain and close evicted connections; clean up multipart files; close and join both combined-helper servers; reject requests on ended tracked connections; close for detected frames after trailers, reset malformed trailer streams and own initial request headers through lazy decoding.
- Qlog: create exclusive private trace files, normalize invalid UTF-8 and order concurrent events. Examples bound server resource use and client response size/duration.
- Validation: deterministic cancellation, shutdown and packet-order fixtures; dual-stack test port selection, timeout budgets, capture retention, BBR observation and CI/toolchain updates. Proxy socket switching now orders admission with packet reads (#983). Historical campaign records remain frozen.

The additional always-available `Conn.PathMTUSettledV1() <-chan struct{}` signal closes once when first-path discovery settles, cannot run, the connection leaves that path, or the connection ends. It does not reopen on migration and is not a permanent MTU guarantee. All other new versioned capabilities and defaults are in the slice table; existing controller selectors remain opt-in. Existing keyed APIs and module identity are retained; fast.7's positional `Config` literal limitation remains.

### Assessment of intervening changes

The journal commits change no shipping code. #969 changes server path-validation retries/timers; #974 changes reliable stream cancellation; #976 changes qlog concurrency; #983 changes the integration proxy used by tests. The test-only #991 retained Windows startup-fixture bind errors and registered cleanup earlier. Their evidence does not claim a precise Windows host-policy cause or a statistical flake-rate guarantee. Their reviewed regressions and exact-candidate workflows supply correctness evidence, not new consumer performance results. #979 changes construction refusal before serialization and therefore touches the emission boundary. #981/#985/#988 change shared recovery and default Reno; #988 also adds constant controller storage. These are explicitly included by the release scope, not silently treated as measured by `642f014e` or `1c4a28b7`.

No intervening change alters the eleven selected slice defaults or reverts their decided behavior. The consumer decisions permit those slice implementations and retain their revision-specific evidence and limitations. Fresh #871 and #990 must measure the actual assembled candidate, including the packet/recovery changes; their scope does not replace downstream platform/adoption measurements or establish a new consumer throughput result.
