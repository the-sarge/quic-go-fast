# Ordered recovery lifecycle follow-up for N3 #1202

The latest measured composition remains the [canonical geometry diagnostic](2026-11-05-native-canonical-geometry-prototype.md): 78.1% baseline goodput and 124.3% CPU/useful byte, still outside both targets. This follow-up investigates the remaining construction/registration/completion ownership and carries a small, proved simplification. It does not claim a new measured result or change the stopped implementation contract.

## Rejected canonical history slots

The candidate would replace native history's packet-pointer slots plus `unresolvedLocal []bool` with pointers to the existing never-reused local registrations. Live packet access would follow `registration.packet`; pending outcome plus retained-span membership would replace the bool vector. This is a concrete projection-removal idea, unlike a lifecycle facade around unchanged ledgers. Rank and ECN evidence cannot simply disappear: authenticated ACK may qualify an unresolved token, packet-distance exclusions persist independently, and ECN/rich/ACK-carrier readers have lifetimes beyond protocol history.

The simple representation fails an existing executable characterization at source `990a7a4de712de0c4c4ce89b8e75f3158dd13d33`. `TestLocalIteratorCharacterization` retains an old history iterator across Retry, nested readers and 128 replacement registrations, and requires original PNs `[0, 1]` and original accepted metadata. Retry clears `registration.packet` while intentionally leaving the old packet-pointer backing visible to that reader. Resolving the next entry through the registration would therefore hide original PN 1. Retry also runs retransmission `OnLost` callbacks before replacing the old history, making the intermediate view significant. Independent review corrected an earlier suspicion: the pinned `retireLocal` ECN failure chain itself has no callback; the Retry and old-reader examples are the established obstructions.

Keeping a second historical packet pointer grows a canonical row from 56 to 64 bytes. Keeping the pointer behind a separate retired flag instead makes retained tokens hold packet/frame state longer, unless reader pinning, snapshots or a further lifetime mechanism is introduced. A shared probe marker additionally needs marker-aware mutation rules because existing close paths clear frame fields. None of these is the originally proposed removal of a small vector with unchanged lifetime rules. The candidate is parked, with no source patch or workload.

Precise profile location attribution matters to this decision. The current native memory profile estimates 120,613,784 allocated bytes / 630,621 objects for `appendPacket`'s bool-vector allocation, versus 946,023,669 bytes / 588,664 objects for its packet-pointer slice. Removing the bool vector would not remove the entire roughly 1.067 GB history-allocation row: the targeted leaf is about 2.17% of 5.571 GB total sampled allocated bytes. These are whole-role estimates, not exact counts or window allocation rates. A co-located membership bitmap remains a separate small representation possibility, not an adopted prerequisite or proof of gap closure.

## Exact empty-prefix scan simplification

At the point `detectLostPackets` reads current history, no packet can enter its transition body when the lowest retained PN is invalid or strictly greater than `largestAcked`. The original iterator either ends or breaks before eligibility, packet-distance, loss logging or frame callbacks. A return immediately after the existing `lossTime = 0` therefore removes only unused RTT-delay arithmetic and iterator setup in that state. Equality must still scan; an earlier retained packet cannot be ignored merely because the completing packet is newer. The predicate is read fresh on every call, after any caller-side ECN/congestion callbacks, with no cached deadline or RTT assumption.

All caller behavior remains: per-packet begin/finish congestion feedback, ECN/rich qualification, deferred undo and fresh eager loss-alarm calculation. Empty rich feedback is not a no-op: it still invokes `pendingBytes` and mutates recovery episode and one-shot state. The guard belongs inside the existing scan instead of bypassing those transitions or batching them at member/group end. It also applies to the baseline recovery path; any later performance comparison must keep that shared effect visible.

The scan guard is frozen separately at `2c319d852387b6a91fa14c6939cf98d636347317`, based on the measured `990a7a4` source. Its archive SHA-256 is `9d40f4a8a6071a63263192621eaa30bed60d6e46a1490d8bcedff295ac2efff9`. The six-line source change passed focused behavior characterizations before (0.183 seconds) and after (0.131 seconds), including the previously proposed reentrant RTT counterexample. Cases cover legacy/local empty histories, stale deadlines, equality, earlier eligible packets across holes, accepted/uncertain outcomes, rich pending-byte callbacks and one-shot state, and timer calculation using a callback-updated RTT. The full recovery race suite passed in 74.268 seconds, the full root package in 11.998 seconds, and vet/tidy-diff/diff checks passed. Independent implementation review found no blocking defect. This is a preserved source-level simplification, with no new minimax observation or measured gain.

## Generated-code basis for construction work

An offline Linux amd64/v1 Go 1.27.3 build of exact source `990a7a4`, with `ordinarycost`, CGO disabled, no trimpath and read-only offline modules, demonstrates eight 128-byte metadata copies through the inspected ordinary construction/registration/logging chain: 1,024 logical copied bytes per successful packet, plus three 128-byte clears in `appendPacket`. The logging wrapper copies metadata before the detailed logger checks whether logging is enabled. The value copies apply to both baseline and native. The native prepared route additionally forwards wide arguments through its preparation and local-registration adapters, although baseline also has one recovery forwarding wrapper. Cold stack-growth spills were excluded from the per-packet census.

These are copies of metadata, not payload/frame backing. Recovery packet field stores are first initialization, and the prepared packet already reuses its object and STREAM backing. Neither another full recovery initialization nor a second prepared-packet allocation was demonstrated. A replacement that continues passing the same large value or unchanged wide adapters has no established benefit. Direct native construction into owned final facts may remove actual transfers, but it needs a small immutable post-registration receipt because callbacks can ACK, retire and pool the recovery packet before later path/CID/GSO observations. Escape behavior and actual resulting code must be checked; instruction counts do not quantify the CPU saving or close the target gap.

This inspection used a local cross-built test binary and a locally built matching objdump tool because the installed distribution lacked that executable. Neither inspected program was executed. The local test binary SHA-256 is `61e68bc7b3ccea0270d051d5032942eb19e74aaafe3a62c71e84838f253273c8`; it is not a rehash of the remote measurement binary. Reproduction commands, build metadata, disassemblies, location census and hashes are preserved alongside the source and behavior evidence in `/Users/josh/diagnostics/quic-go-fast/issue-1202-pipeline-2026-11-05/lifecycle-proof-v1/` with a 36-file SHA-256 manifest. Local validation and offline compiler inspection add no minimax workload; its existing cumulative ledger remains 203 invocations / at least 3960.420260018 measured host-seconds.

## Disposition

Retain the canonical geometry and earlier useful components, reject the disproportionate history-lifetime rewrite, and carry only the semantically equivalent scan guard from this question. Generated-code inspection now establishes concrete transfers for the construction-facts investigation; the next design must remove them while preserving callback lifetimes, rather than merely changing function signatures. The overall redesign remains incomplete, with writer isolation, exact outcomes, callback-visible state and the original product targets intact. [N3 #1202](https://github.com/the-sarge/quic-go-fast/issues/1202) stays stopped and [draft PR #1230](https://github.com/the-sarge/quic-go-fast/pull/1230) stays held.
