## NAPI source context

Linux documents `gro_flush_timeout` as the repoll delay and `napi_defer_hard_irqs` as the number of empty polls tolerated before returning to hardware IRQs. Global busy-poll settings do not alone exclude socket-specific busy polling. [Kernel NAPI documentation](https://docs.kernel.org/networking/napi.html#software-irq-coalescing)

In pinned upstream Linux v7.0, `napi_complete_done()` converts the timeout with `ns_to_ktime`; 20000 therefore means 20 microseconds. Setting only that timeout to zero disables this software deferral timer path even when `napi_defer_hard_irqs` remains 1. It also changes GRO flushing behavior. It does not remove hardware moderation, driver scheduling, a missed-schedule repoll, or every possible NAPI invocation. The upstream default helper selects 20000 and 1 on non-PREEMPT_RT builds, and upstream `r8169` calls that helper. [NAPI completion and defaults](https://github.com/torvalds/linux/blob/v7.0/net/core/dev.c#L6344) · [r8169 initialization](https://github.com/torvalds/linux/blob/v7.0/drivers/net/ethernet/realtek/r8169_main.c#L5423)

The privileged sysfs store uses `netdev_set_gro_flush_timeout()`, which updates the netdevice, every attached NAPI and saved per-NAPI configurations. It does not cancel an already-armed timer. A hypothetical reversible experiment would preserve per-NAPI values as well as the sysfs value, restore and verify them on all exit paths, and exclude the transition interval. Merely restoring 20000 would overwrite any earlier per-NAPI override. Changing both knobs is unnecessary to disable this timeout path. [Sysfs store](https://github.com/torvalds/linux/blob/v7.0/net/core/net-sysfs.c#L498) · [Setter propagation](https://github.com/torvalds/linux/blob/v7.0/net/core/dev.h#L256)

The installed kernel is `7.0.0-30-generic`; its installed headers confirm the NAPI fields. Matching Ubuntu implementation source is not installed, so the implementation statements above are explicitly upstream v7.0 context rather than a byte-for-byte audit of the running kernel.
