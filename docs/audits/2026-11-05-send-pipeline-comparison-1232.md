# Send-pipeline comparison for issue #1232

**Recommendation:** use this analysis now as input to the larger redesign: retain the independent native writer, carry forward compact construction/recovery ownership, and next test sharing structural facts across an already-produced packet train. Evaluate readiness inside that isolated writer before considering connection-owned native calls. The five stacks demonstrate cheaper representations and execution paths, but none of the inspected integrations provides the complete accepted responsiveness and outcome contract by simply deleting our writer/completion boundary.

**Status:** analysis for [send-pipeline comparison (#1232)](https://github.com/the-sarge/quic-go-fast/issues/1232), supporting [N3 redesign (#1202)](https://github.com/the-sarge/quic-go-fast/issues/1202) and [efficiency program (#1193)](https://github.com/the-sarge/quic-go-fast/issues/1193). Researched 2026-11-05. No implementation, dependency, activation or acceptance-threshold change is made here. [Explicit-engine proposal (#115)](https://github.com/the-sarge/quic-go-fast/issues/115) remains a related architectural alternative, not a prerequisite. Findings below describe inspected source; transfer proposals and consequences are identified as inference.

## Starting evidence and required behavior

The latest usable matched diagnostic when this analysis began was `d68633ed668653401520985914cda7ee831b99e9`: **76.2% baseline useful throughput and 127.0% baseline CPU/useful byte**, against at least 95% and at most 110%. Native calls/useful byte are approximately equal. The CPU ceiling leaves **0.172046660 ns/useful byte** to remove. These are local measurements from the [event/lifecycle receipt](2026-11-05-native-event-lifecycle-prototype.md), not throughput comparisons with other stacks. The newer `c0138fc27529dc73a439c4a04a0b9c2cf27feb3f` construction-metadata candidate passes correctness checks, but its paired baseline recorded 21.612077677 seconds of foreign CPU on the monitored test CPUs and SMT siblings. Its [receipt](2026-11-05-native-construction-metadata-prototype.md) makes no comparative performance claim.

The follow-up [compact metadata/ownership experiment](2026-11-05-native-metadata-projection-prototype.md) at `eaaea71fb5685659ba734f8923ed36f022b758a8` now supplies a clean pair at **76.6% goodput and 125.6% CPU/useful byte**. It verifies smaller member/registration records and removes per-turn grant allocations, but still fails both targets. The cost arithmetic below refers to the d686 starting evidence; the follow-up receipt owns the current 0.158192302 ns/byte gap. No foreign-source inference is promoted to a measured component effect. The subsequent [canonical member geometry prototype](2026-11-05-native-canonical-geometry-prototype.md) at `990a7a4de712de0c4c4ce89b8e75f3158dd13d33` removes duplicated native buffer geometry and grouped inline resets. Its clean pair reaches 78.1% goodput and 124.3% CPU/byte, leaving 0.147581579 ns/byte; the improved ratios accompany slower absolute results in both modes and do not establish an isolated performance gain.

The [preparation-owned construction follow-up](2026-11-05-native-owned-construction-prototype.md) at `302ccab12fa200f013259aded0d61aefbef449c8` applies the encoding-into-final-metadata direction: the native ordinary path removes the confirmed full-packet forwards without enlarging the persistent packet or allocating a new preparation handle. Failure cleanup and callback-visible reads remain covered by paired tests. Shared helpers add work to the baseline too. Both new timing observations are contaminated on the fixture CPUs and sibling threads, so neither this structural improvement nor the apparent CPU ratio establishes a performance gain; the latest clean status remains the canonical geometry result.

The [accepted endpoint contract](../adr/2026-10-24-multipath-endpoint-plan.md#endpoint-ownership-contract) separates pre-I/O reservation/policy from evidence of network submission. It requires accepted, uncertain and proven-unsubmitted outcomes; per-member native-return eligibility times; ordered connection-owned recovery effects; bounded storage; fair shared admission; absolute expiry and revocation; and buffers retained until actual native return. ACK-before-return can settle delivery but cannot release the native borrow. Its “Send-route adaptation and probe accounting” section explicitly prohibits connection event loops from waiting for native completion; its recovery section keeps connection no-progress timers effective during sustained local backpressure. These are accepted behaviors. Per-buffer messages, duplicate descriptors, repeated scans and a particular channel/mutex arrangement are implementation choices.

## Runtime, fairness and failure differences

| Concern | Observed source behavior | Consequence for this redesign (inference) |
| --- | --- | --- |
| Writable readiness versus actual native stall | Quinn/Noq return from a Pending send and continue connection timer/event work. Their actual call executes on the same connection owner. Tokio-quiche awaits flush outside timer selection; prolonged writable waiting can itself defer connection RX/timers/close. picoquic and XQUIC run native calls synchronously on their serialized engine. [Quinn ordering][q-driver] [Quiche timer ordering][c-timer] [picoquic loop][p-loop] [XQUIC engine][x-engine] | A readiness-driven design can avoid normal socket-capacity blocking. It cannot promise that the calling connection remains responsive through an unexpectedly stalled syscall/callback. An independent endpoint timer preserves endpoint fault publication, not that connection's ACK/recovery/close execution. |
| Multiple shared-socket waiters | Quinn gives each sender its own waiter; Tokio supports multiple `writable()` futures. A single poll-style write waker can be overwritten. Quiche's generic socket trait documents the latter limit; XQUIC's demos have incomplete writable continuation despite the API hook. [Quinn interface][q-waiter] [Tokio][tokio-ready] [Quiche trait][c-socket] [XQUIC API][x-api] [Client][x-ready] [Server][x-server-ready] | Include readiness registration, missed-wakeup protection, spurious readiness, disarming and cancellation in the proposed implementation and cost. “Nonblocking” is not a complete shared-socket scheduler. |
| Fairness and bounds | Quinn limits newly produced datagrams per drive to 20 but uses unbounded endpoint/connection channels. Quiche bounds each batch; its 16 × 64 KiB per-thread scratch cache bounds free buffers, not all borrowed buffers. XQUIC can repeat full 32-packet bursts on one path. [Quinn limits][q-limits] [Channels][q-channels] [Quiche pool][c-pool] [XQUIC bursts][x-send] | Per-call batching limits do not prove bounded endpoint retention, weighted service, or maximum queue age. Preserve explicit endpoint byte/slot accounting and fair turns; an uncontended fast path must not bypass queued participants. |
| Cancellation, route change and close | Quinn/Noq may retry an old prepared descriptor after rebind/close events. Quiche close awaits another flush before final cleanup. picoquic's stop wakes its normal wait and then joins its network thread, which still needs native return. XQUIC close/path timers run on the engine. [Quinn events][q-events] [Quiche close][c-close] [picoquic stop][p-stop] [XQUIC engine][x-engine] | Logical expiry and native-buffer release are distinct. Retain immutable route/generation checks before dispatch and actual-return fencing after entry; a queued stale route cannot silently become a new route. |
| Prefixes, uncertainty and fallback | XQUIC processes positive sendmmsg prefixes but exposes no uncertain-range type. Quinn's Linux GSO error lowers future capability without a complete per-member retry/result protocol. [XQUIC][x-send] [Quinn][q-unix] [Quiche helper][c-mmsg] [AF_XDP][p-xdp] | Borrow the explicit evidence-boundary idea. Do not treat an arbitrary error as zero submission or replay an uncertain prefix. [Noq][n-builder] [quiche][c-encoding] [picoquic][p-pool] [XQUIC][x-pool] | Keep c013's existing pooled packet preparation and unique canonical completion identity. [Noq invariants][n-invariants] [picoquic guard][p-fast] | Cache only facts whose validity survives all intervening callbacks. | Nonblocking attempts and explicit readiness in the isolated writer | Native backpressure waits and avoidable retry wakeups; potential integration simplification. The clean profile attributes 0.016714 ns/B to connection handoff, 0.025636 to outer result consumption, 0.041560 to local completion and 0.050143 to endpoint control. Even the unrealistic sum of deleting those four entire disjoint owners is about **0.134053 ns/B**, below the 0.172047 gap. This arithmetic is not a speedup prediction: some work is mandatory, effects can interact, and samples cover whole-role execution. It does show why “remove one goroutine” is not yet a sufficient cost argument. Construction and registration remain plausible CPU targets. Measure connection active time, blocked/queued residence and cross-owner overlap to establish which part limits useful throughput; the cost sum does not prove the throughput critical path. ## Remaining local work and deeper alternatives

Pinned `c013` source gives concrete places to inspect, not established savings: `packet_emission.go:276–283` prepares recovery metadata only for ordinary local path-zero non-DATAGRAM work without path credit; `internal/ackhandler/sent_packet_handler.go:374–409` still snapshots ACK targets, initializes fields and derives ack-eliciting status after packing. Those facts may be produced during encoding only if their existing observation point is preserved. `native_group_diagnostic.go:19–35,90–104` maintains native member rows, flattened buffers, packet-range metadata and token rows, while `native_ordinary.go:876–941` maps results back to records/tokens. Some projections separate necessary lifetimes; their multiplicity alone is not proof of waste. The source archive in the construction receipt preserves these unpushed diagnostic locations.

A more substantial ownership option is a writer-owned native-storage object with an exclusive producer-fill lease, then sealed immutable geometry and independent compact recovery/result storage. Much of this already exists: owned native rows avoid cloning and the writer directly claims successors. Adopt only a demonstrably eliminated projection/reset/notification, not a new state vocabulary. A still deeper option is an immutable encoding plan finalized by the connection and executed by an isolated writer: protocol decisions, packet numbers, exact lengths, keys/nonces and frame ownership must be fixed before transfer. Pure encoding offload could relocate work without reducing it, add retained plaintext and constrain concurrency; mutable cipher state and failure disposition need separate design evidence. Neither option is selected or measured here. Retaining execution isolation leaves room for a larger representation redesign.

## Contract alternatives and recommendation

| Alternative | Classification and visible consequence | Alternative preserving the current contract |
| --- | --- | --- |
| Treat preparation as sent; suppress ordinary native errors | Actual contract change. Local socket residence can affect RTT/loss origins; proven-unsubmitted traffic may be treated as network loss. It removes work partly by changing what is reported and accounted. | Retain tentative local registration and exact ordered native reconciliation; compact their records and reuse facts. |
| Send directly from connection after an uncontended endpoint reservation | Platform assumption plus contract change under actual stalls. It can remove a writer round trip, but that connection cannot process ACK/recovery/migration/ordinary close while native code occupies its sole owner. Keeping an endpoint fault timer does not repair that. | Keep isolated writer execution. A scoped prompt-return backend could be a future explicit tradeoff, but cannot retrospectively offload a call already stuck on the connection. No such relaxation is adopted here. |
| Use one GSO preparation time for all member outcomes | Actual contract change where actual native-return eligibility is required. Long local residence can make recovery eligible too early and change timing provenance. | Share immutable group geometry, retain existing member-qualified native facts and ordered effects. |
| Replace endpoint bounds/fairness with task scheduling | Contract change under overload; memory, queue age and close behavior become runtime/application dependent. | Keep bounded admission and fair request turns; simplify bookkeeping at state changes and remove empty progress work. |

**Next prototype:** a narrowly scoped construction-train representation on the current isolated-writer candidate. First enumerate the duplicate structural lookups and metadata-population passes in the frozen source; retain only a change with an explicit validity interval and measurable target. Use the existing prepared packet and immutable native members as the ownership boundary. Do not introduce a second packet builder, bulk-delay registration, enlarge queues, or move connection-owned callbacks into the writer. If source inspection finds no material redundant construction work, retain that representation and target remaining registration/projection work instead. Readiness is a subsequent backend experiment, not a prerequisite or an assumed remedy for equal-syscall-rate CPU excess.

Supporting evidence must show fewer targeted operations/allocations or descriptor copies per useful byte, lower corresponding construction/registration cost, and clean matched whole-pipeline results with unchanged native calls/byte and workload semantics. Include readiness/runtime cost if changed. Falsifiers are unchanged net CPU, work merely moving to completion/control, increased retained memory, lower goodput, or divergent observable callback/state traces. Existing correctness obligations cover inter-member ACK/policy/path changes, EAGAIN and spurious readiness, accepted/uncertain prefixes, early ACK before return, expiry/cancel/close, fair queued successors and an actual stalled native call. Demonstrate endpoint progress and connection protocol progress separately. These are existing obligations, not new gates or an expanded workload budget.

Retain useful smaller improvements even if they do not close the whole gap. Keep [N3 #1202](https://github.com/the-sarge/quic-go-fast/issues/1202) stopped and [draft PR #1230](https://github.com/the-sarge/quic-go-fast/pull/1230) held until the composed candidate satisfies the unchanged targets and its implementation contract is audited. This analysis changes the redesign's inputs and prioritization; it does not establish performance qualification or a dispatchable issue graph.
