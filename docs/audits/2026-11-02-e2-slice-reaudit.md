## Self-grill and design decisions

1. Can local completion be demonstrated before native routing? Yes. `SentPacket`, `ReceivedAck`, loss/PTO operations and lifecycle methods already expose the real recovery boundary. A private atomic registration/completion interface can deliver complete behavior with typed native facts and an enforced Reno/no-ECN constructor. No socket or protocol worker is required. This overturns the earlier blanket claim that every caller/disposal split is necessarily non-green: the endpoint adapter remains one slice, while recovery is independently usable in a closed fixture domain.
2. Can rich evidence be added by postponing registration? No. `bbr_recovery.go` indexes increasing packet numbers in registration order, and its PTO/persistent-span shortcuts additionally rely on monotone times. Insert once at original registration and qualify in place. Keep return time distinct, and use conservative evidence segments so unknown or nonmonotone eligibility cannot be treated as an ordered persistent-congestion interval. Existing work-bound suites remain preservation evidence; no full-ring ACK scan is accepted.
3. Can ECN be fixed with a single skip around feedback? No. Ordinary testing ranges and rich mark ranges carry identity, membership, totals and watermarks. Holes from local non-submission and early authenticated receipts must retain exact marking identity; deferred cumulative feedback needs bounded sufficient state and explicit degradation. Both existing controller modes must share the same local-transmission meaning.
4. Can Retry use detach and reconstruct a participant? No. Endpoint detach is terminal disposal, while Retry needs old native completion to reach a tombstone without reviving protocol history. E2 integration cancels an epoch while retaining completion ownership. E2A supplies the terminal protocol transition first; E5 still owns transport-wide shutdown/join.
5. Does this change congestion algorithms or public support? No. New qualification state supplies or excludes evidence to the existing algorithms. An implementation that needs formula/response changes or weakens shared delivery identity must stop. Native qualification stays in E6 and activation in R19.

## Slice audit rationale

Each slice has one mutation owner per fact, typed representation, explicit intermediate constructor restrictions and their removal slice, a bounded dispatch import list, classified artifacts and allocated evidence. The plan's shared matrix covers authority completeness and the admitted negative cases. Fresh-instance construction replaces a persisted restart obligation because the library has no persisted schema. The split adds three PRs and no new runtime execution context; the 16-scenario and single-race ceilings remain shared. No new operational, mutation or platform qualification campaign is added.

The endpoint parent becomes nine slices and the program 34; E2 keeps issue #1016 and E3's existing dependency, so downstream cross-track topology stays intact. E4 remains independent. R3 may overlap recovery/emission files and therefore still requires isolated worktrees and current-main reconciliation, not a convenience blocking edge. Q2 remains deferred and is not reintroduced as an E prerequisite.
