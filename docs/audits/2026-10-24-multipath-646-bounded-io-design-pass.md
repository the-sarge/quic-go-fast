# Issue #646: bounded native I/O design pass

Date: 2026-10-24. Scope: documentation only. Parent design revision: `d42bf04359578fa836531891a9b2e0f3f32265fc`; production baseline remains `f35df9d7b016a06174288901f3337ccc2fd7347c`. The owner asked to update the design and sizing for bounded native I/O, make another design pass and run another RAS consideration. No implementation, prototype, benchmark or qualification campaign is authorized or reported here.

## Direction and prior evidence

Adopt bounded native send completion for the initial supported multipath profile, optionally accelerated by cancellation with equivalent completion semantics. This supersedes F3 in the [second consideration response](2026-10-24-multipath-646-second-consideration-response.md), which proposed accepting indefinite retirement under existing I/O contracts. The first two review runs remain historical evidence: `20261024T203020-3c1065e096b8b452ba7fc89b` at `d63dd743ce896e577603cac4ca37df0608706aa3`, and `20261024T211358-95949b13efe81498dc2b5581` at `2d2d947aee3717e67dabc5732f4038a63fee495f`. The eight second-run recommendations were manually addressed at the parent revision; they do not constitute an independent review of this new mechanism.

The [current design](../designs/quic-multipath.md#bounded-native-io-and-endpoint-ownership) owns the proposed contract. This note records its rationale, bounded paper traces and cost allocation. Bounded native-I/O support is the direction chosen for design work; exact API names, default and maximum write budgets, resource limits, supported platform revisions and implementation acceptance remain D0 gates.

## Source evidence and implications

- [External packet I/O](../../external_packet_io.go) requires concurrent-call support, accepted-prefix results and borrowed buffers only until return. It has no cancellation or return deadline. Retrofitting those obligations into V1 would change existing providers' contracts. Initial multipath rejects these registrations, including custom forwarding wrappers, while ordinary unregistered transport behavior remains intact.
- [Managed endpoint](../../managed_packet_endpoint.go) joins active lease operations and forwards deadline methods to its underlying endpoint. A native helper does not bound arbitrary wrapper policy/locking before or after forwarding. Managed and custom wrapper support requires a separately designed and sized capability contract.
- [Send worker](../../send_queue.go) synchronously calls the sender, and ordinary Close drains and joins it. [Send connection](../../send_conn.go) includes direct validation writes, ordinary writes, GSO fallback and first-send retries. Existing worker cutoff checks cannot interrupt a call already underway. Multipath's path fence and the new endpoint completion owner must cover these distinct routes.
- [Transport](../../transport.go), [server](../../server.go) and [cached close handler](../../closed_conn.go) include sends outside ordinary per-connection worker traffic. Shared endpoint deadline authority must include these routes and public Transport.WriteTo, not just the newly added path workers.
- [Darwin batch submission](../../send_conn_sendmsg_x_darwin.go) uses RawConn.Write and deliberately returns from its raw callback without waiting for writability; fallback and any surrounding serialization still need qualification under the whole-operation budget. Linux/macOS OOB and Windows sends use native UDP methods through their adapters. No platform completion bound was experimentally demonstrated in this pass.
- Go's [PacketConn deadline contract](https://pkg.go.dev/net#PacketConn) applies to pending and future writes on the socket. It does not provide per-path deadline ownership or a hard real-time scheduler guarantee. The proposed coordinator serializes actual native submissions, installs one current request deadline, and finishes its accounting before handing the endpoint to another request.

## Paper traces

These are manual contract/state traces, not executable tests or proof that an implementation satisfies the bound. B is a finite positive transport budget; one absolute admission deadline covers queue wait and every native attempt. The accepted implementation must qualify its finite completion overhead/tolerance on each supported platform.

| Case | Required transition and observable consequence |
| --- | --- |
| Retirement while A is queued behind another connection | Revoke A's generation and remove/invalidate its queued work without waiting for unrelated FIFO service. A has made no syscall. Release its existing reservations exactly once and return reliable information to the established delivery owner. No protocol-path slot is released before its fence and retained-state admission. |
| A is inside a native send when retirement begins | Revoke future A work; leave its current token, payload and recovery ownership intact until native return by its existing deadline. The connection loop remains responsive. A different endpoint can keep sending; B on the same endpoint can wait for the remaining budget. No PATH_ABANDON for A can precede cessation of all A submissions. |
| A batch accepts a prefix, then a tail or GSO fallback blocks | Retain the original deadline across all attempts; check revocation before each new syscall. Record the definite prefix and any uncertain submissions separately. Do not turn uncertain data into an immediate fallback retry. Finish ownership accounting before signaling the fence. |
| A times out; B and connection C share its socket | Attribute A's request failure locally, successfully clear/replace its expired deadline, and then dispatch B or C under their own tokens/deadlines. A's timeout is not Transport.Close. No stale A cancellation/completion may expire B's write. A fatal socket/deadline-control failure instead affects every path using that endpoint, including paths of C. |
| Queue capacity is exhausted or a queued request expires | Reject full-queue admission before ownership transfer. Complete an expired admitted request as definitely unsubmitted. Keep reliable delivery ownership and DATAGRAM drop/error observability correct; do not allocate a goroutine or an unbounded secondary queue as a capacity escape. |
| Ordinary peer or non-QUIC WriteTo on an opted-in server endpoint | The explicit transport-wide write grant applies even without multipath negotiation. These writes pass through the coordinator and receive finite completion/errors. A send error may terminate that ordinary peer's own connection, but does not implicitly destroy its neighbors. Unregistered transports retain existing behavior. |
| Target is a custom PacketConn, external callback, managed lease or unqualified platform | Reject local multipath configuration/attachment before advertisement, routing registration, path-ID consumption or credit mutation. Do not use a hidden native descriptor to bypass wrapper policy. Ordinary mode remains available under its existing registration contracts. |
| Deadline implementation fails or native call never returns despite qualification | Stop new endpoint admissions and report the fault. Do not claim fence completion, reuse the slot, free borrowed memory or secretly close a caller-owned/shared socket. Keep unresolved ownership within existing caps; preserve safe survivors on other endpoints. This is a qualified-contract failure, not the supported indefinite-retirement behavior proposed previously. |
| Local I/O fence completes but peer withholds replacement credit | Local progress is complete, yet replacement remains blocked on credit/CID exchange or validation. Retained-state admission and protocol timers still apply. Do not label B a bound on restoration of redundancy or complete transport detachment. |

Paired endpoints add; they are correlated planning scenarios, not independent confidence intervals.

## Review and handoff boundary

The next consideration must stress-test the native support restriction, complete shared-socket ownership, absolute deadline/retry semantics, error attribution, default-off preservation and completeness of the incremental allowance. It must distinguish a concrete contradiction from the explicitly unchosen B/default, queue budgets, platform qualification and broader D0 choices. This is one owner-requested additional consideration, not an implementation/fix loop. Its synthesis is evidence for another decision, not authority to implement.

Before implementation handoff, settle the proposed API and deadline grant, finite B/default/maximum and qualification tolerance, endpoint queue/count/control budgets, local timeout and endpoint-fatal error identities, and exact OS/Go support matrix. Establish a feasible native test method for a blocked send/timeout on each claimed platform; a fake sender alone cannot qualify native cancellation. Check bounded writer overhead and fairness on shared endpoints, plus default-off equivalence. If those obligations do not fit the allowance, resize or narrow the profile before packaging implementation slices.
