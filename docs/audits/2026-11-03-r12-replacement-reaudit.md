## Accepted design

Keep child #1032, its private typed domain and one independently green product PR. No exported method, new platform, controller formula, wire format, worker or persisted state enters the slice. Replenishment exists only on the private endpoint route. The credit-only R8 fixture keeps its initial window, because it has no recovery or fence to retire.

**Slot and grant.** A terminal path leaves `paths` only once its signal proves the fence resolved and it holds a history unit. A path that committed already holds one. A retired path zero or a retired unused ID reserves one then, and stays charged while none is free. When a slot is free, no unused ID remains in the grant and a further unit is free, the registry raises `localMax` by one, queues `MAX_PATH_ID` and calls `issueWindow`. `issueWindow` takes the next never-issued ID when both maximums allow it, under the same keys-then-CIDs order. The unit gate is what makes retained capacity block replacement. It withholds the grant, so a peer's packet cannot reach a decline of an ID the registry could not have served. A later admission that loses the unit to another charge still refuses with `ErrMultipathResourceLimitV1`, and it never evicts or shortens retention. Abandonment of a granted but unissued ID moves the next ID past it, so no ID is reused.

**Tombstones.** IDs are monotonic, so a released ID needs no record. Final reclamation deletes the terminal, its receipt and its RTT object. A frame naming an ID below the next-ID counter that has neither a slot nor a terminal is ignored, while an ID above the grant keeps its protocol violation. Per-send scans read members rather than IDs, in ID order.

**One history pool.** Commitment, a pending terminal and later old generations all take units through one reserve/release pair. R13 adds its generation charge on that pair with no new accounting.

**Final reclamation.** The live slot can leave at the signal, but the terminal keeps its record, keys, recovery, receive tracker and any unit until one gate passes: retention has elapsed, the signal has been sent, every local result is consumed, and a final drain has left no outstanding frames. The fence alone is not enough, because the endpoint can report it resolved after a result publishes and before the connection consumes that result, and an Accepted result then leaves frames that only a retained terminal can drain. A pending result wakes through endpoint completion, so the elapsed deadline arms no timer while one is pending. A terminal that reaches this gate without ever obtaining a unit has nothing left to retain, so it reclaims at once, frees its slot and releases no unit. Retention never waits on capacity.

**Recovery and receive history.** Recovery admits a new ID when its live capacity allows and the ID exceeds every earlier one, with at most four nonzero contexts, which the history pool already bounds. Each is marked retired at the signal, the same boundary as its keys, so live capacity tracks the slots. Final reclamation removes the context and its receive tracker. Erased IDs cannot be told apart, so recovery keeps one bounded policy: an absent ID at or below the largest admitted is ignored, including a skipped ID that was never admitted, and one above it keeps its violation. Late-receipt stores keep their aggregate: path zero keeps its half and the four nonzero contexts share the other half equally. A missing receipt already cannot discharge undo or create delivery.

**Path zero.** Path zero retires through the same terminal owner whenever another live, eligible path survives. Otherwise received abandonment or CID exhaustion keeps its prompt connection close, and that rule now covers whichever path is last. The ordinary sender stamps zero's existing established epoch on path-zero requests once admission exists, so R9's revoke, fence and signal ordering covers them, while a connection without admission keeps its nil epoch and branch. Each service pass drains a terminal path zero through recovery's existing probe queue, as R10 does for other paths. The scheduler stops offering zero at its terminal transition. If no path is then eligible, because a survivor's endpoint is quarantined or it has no usable destination CID, emission reports hard-blocked and packs nothing. A nil route never reaches the packer with zero retired. At the terminal transition, a retiring primary passes to the lowest live survivor, and the stable RTT observation moves to the primary once zero has retired. It keeps its last source when none remains. Path zero's retained PTO joins the largest-PTO snapshot while it stays a member. Final reclamation releases its routing and reset tokens and clears the legacy alias map, so close cannot re-register them. Its keys stay in crypto, sealing refused, because `a.paths[0]` is the legacy accessor's entry, so crypto's retained limit stops counting it.

**Receipts.** Replacement allows more concurrent terminals than the two receipt slots in send metadata, and a slot overflow silently loses a first acceptance, so the unanswered timer never arms. Metadata carries a slice of receipts, nil for ordinary packets, appended without duplicates only when a packed frame is `PATH_ABANDON`. Every abandonment in a packet is therefore recorded, and ordinary sends allocate nothing.

**Attachments.** A transport's attachment charge survives its last member until R13 can detach it, so the eight-attachment cap also bounds `connRunners` and the sender's targets.

**Declared seams.** A close after path zero retires packs nothing and logs the failure, until R14 closes via survivors. The emission close owner refuses before packing, so it reads no released CID state and consumes no packet number. A released zero's last RTT keeps contributing to crypto's retention and spacing snapshots. It stops changing at that point, so this can only lengthen those finite timers, and removing it would mean reworking the same legacy accessors rejected below. A primary endpoint fault still fails the connection, until R13/R14. The client never sends `PATHS_BLOCKED`, which the plan permits. A request waits within its context for credit or CIDs, and an endpoint still resolves a peer's `PATHS_BLOCKED` with credit or issuance. R15 owns promotion policy, so the primary only moves when a primary retires.

## Rejected alternatives

Moving retirement into a new state machine or giving each replacement a fresh recovery root would duplicate the terminal owner and aggregation, which the slice forbids. Keeping a released recovery indefinitely would give late ACKs an answer, but its memory would grow with replacements, and its frames have already returned to their logical owners. Treating every ACK for an absent ID as ignorable would drop the protocol violation for IDs above the admitted range. Widening the receipt array would add cost to every ordinary send. Holding the zero charge for the connection's life would avoid the zero release, but it would permanently shrink a pool the plan sizes for repeated replacement. Removing path zero's crypto entry would remove the retained-count special case, but it would require reworking every legacy accessor that reads `a.paths[0]`, for no behavior a client can observe. Giving path zero a route value would remove the nil meaning from ordinary connections' hot path, which R10 deliberately kept. Splitting path-zero retirement into its own slice would leave the slice's RTT obligation unreachable. Each is rejected on merit.
