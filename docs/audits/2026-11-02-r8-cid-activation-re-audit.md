Source-review verification at that head confirmed C-002, C-004, C-005 and C-006 and their duplicate evidence, but identified an activation case still violating C-001. No replacement runtime review has run.

The precise invariant is that retained CID/token evidence grants reset-detection authority only when the corresponding CID is in use and unretired. The first semantic class was direct private admission/retirement of unused records. The second is activation from ordinary state: `enableMultipathCredit` calls `connIDManager.Get` for length validation, `Get` can rotate from sequence zero to a queued CID and register its token, and `enablePathCIDs` unconditionally marks the selected current CID used. Both classes meet the same received-CID eligibility owner, and the accepted activation family had to cover the second. The first correction therefore did not establish the central representation; ordinary selected identity was incorrectly treated as use evidence. The shared repeated-root rule stops further runtime fixes/verification until this scoped repair is published.

At runtime head `9fb2e1dd2617608e6ec672b1330ef44b8fa969d4`, the bounded source census has three ordinary-state current-identity producers: `newConnIDManager`, `ChangeInitialConnID` and `updateConnectionID`. Existing `SentPacket`, called through `Conn.noteEmissionRegistration`, supplies connection-owned packet-use evidence. `Get` selects and may rotate but cannot establish use merely by returning an identity. Private activation transfers that state; per-path admission, active-record reselection in `addPathCID`, retirement, expiry and close are the remaining private transitions. Newly admitted records start unused; selecting an existing record preserves its actual use state. The two consumers are transport reset-token lookup and `IsActiveStatelessResetToken` in failed-decryption handling. Existing migration/probe allocation remains excluded from private activation, and R9 owns nonzero live-path use. No persisted state is introduced.

Disposition: scoped same-child repair. The received-CID owner retains an explicit use fact over every current-identity producer and records use at the existing emission-registration callback. Activation validates without a rotating getter, transfers the fact rather than inventing it, and disarms a legacy-registered token if its selected CID is unused. One private eligibility predicate controls registration, matching and cleanup. The normative row covers used current, selected-but-unused current, queued/unused and retired records against both consumers; existing scenarios are amended within the accepted 16-scenario inventory. Actual whole-datagram abandonment acceptance remains the separate immutable worker receipt already published in PR #1114. No new worker, queue, public callback, protocol parser, endpoint fact or socket-acceptance policy is introduced.

A guard against only the reported sequence-zero rotation would leave a CID selected earlier by another getter call incorrectly armed. Treating every current CID as used repeats the failed assumption. Moving detection policy into transport lookup would duplicate the CID owner's semantic state and miss the connection's second detector. Those alternatives are rejected in favor of the existing serialized CID owner and one use/eligibility representation. Ordinary/default-off externally observable behavior is preserved; the added fact is consumed by private activation. Maintained regression aids keep their existing owner and retirement policy, and no new evidence artifact or operational campaign is required.

The accepted representation remains typed configuration/control events, current CID state and one explicit owner fact; the guarantee remains universal within the private R8 profile. Outcome, shipped artifacts, authority, blast radius, 24k dispatch-context ceiling, 16-scenario inventory and focused race gate remain unchanged. R9 (#1029), R12 (#1032) and R15 (#1035) retain their existing integration and policy scope. Runtime PR #1115 is frozen with its changes preserved until this documentation revision reaches main and the child plan pointer is synchronized.
