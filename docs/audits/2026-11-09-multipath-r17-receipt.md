## Owners and limits

The transport integration suite owns the maintained job, scenario driver and receipts; retirement requires equivalent independent coverage or feature removal. `peer.c` supplies bounded application callbacks and opaque UDP forwarding/conditioning against the same pinned library. Picoquic retains all peer QUIC parsing, protection, recovery and path authority. The Go fixture uses the accepted V1 config/transport/path surface under the one existing internal activation guard. Cancellation joins the peer and returns native grants through their existing APIs. No runtime feature or public activation is introduced.

The Go-client abandon/reopen example uses a bounded opaque replacement-tuple gate and a typed path-zero ACK receipt for a CID2-carrying transmission before delivery to the independent server. This establishes only that controlled processing order; it does not query current CID inventory, prove indefinite availability or cover arbitrary packet reordering. The receipt handles recorder callback order and retransmitted control packets; its copied evidence and the driver's 64-datagram storage fail visibly on exhaustion. The asynchronous V1 caller and cancellation callback are joined before resource release, and the driver drains outside the application callback. The opposite role and original replay/late-feedback predicates remain unchanged. Historical failed attempts remain retained and unattributed; only the full fixed inventory on the final exact source can qualify this candidate.

The key-update case witnesses the pinned public rotation API applying fresh encryption keys before it queues the same-request OK, which is subsequently protected with the current 1-RTT context. The fresh-stream response, authenticated post-request path-zero useful transfer, unchanged observed path-one packet counts and later authenticated path-one resumption must all succeed. A one-bit phase transition is not required because ordinary concurrent updates can hide intermediate parity. This relies on the pinned adapter/library construction and protection order; it is not a complete generation inventory or proof of absolute silence. The invalid parity consumer and its unused observer/test were removed together; historical failures remain unclassified and preserved.

The unequal-MTU case keeps each path selected and supplies bounded useful packet/ACK progress while waiting for its existing finder: a fixed 256-byte public echo on 100-millisecond ticks, capped at 300 per path within the original shared 30-second context. Completion remains the owner-safe finder predicate, followed by the unchanged unequal PMTU and invalid-frame assertions. An already completed finder needs no traffic; trace events only recheck it. The caller owns and stops the ticker, and existing public stream deadlines bound synchronous I/O. This addresses a pending-probe progress prerequisite without changing recovery, forcing probe outcomes or asserting the cause of an earlier timeout.

Picoquic `01e124ebdf9fc50df307e01e71f2744471ddc470` with PicoTLS `bfa67875982afc4c24f21e146cef4747fa189c2f` remains the independent peer. Its positive-only multipath negotiation cannot establish the negotiated-zero oracle; the separately named normative and controlled evidence covers that gap without claiming independent interoperability. The cases do not claim universal draft conformance, arbitrary peers, every key-update direction, Internet failure-detection timing, unqualified platforms, performance qualification or public activation.
