# R8 terminal receipt scoped re-audit

R8 [#1028](https://github.com/the-sarge/quic-go-fast/issues/1028), under parent [#1013](https://github.com/the-sarge/quic-go-fast/issues/1013), retains its accepted bounded-credit/CID outcome and one implementation PR. The [current normative R8 contract](../adr/2026-10-24-multipath-reno-plan.md#r8) owns implementation and finite evidence. This receipt records the preflight trigger and routing decision; it does not introduce a second contract.

At source `8d6fa76727d486f8594bb305c0b77b352d96d075`, `Conn.handleFrame` has ordinary CID dispatch but no registry or unused-ID terminal transition. The connection parser also leaves the existing R2 multipath gate disabled; R8 private activation enables that gate and gains the real control dispatch while ordinary construction remains disabled. `packetEmission.registerPacket` registers before asynchronous I/O. `sendQueue.writeEntry` owns actual socket-write results, and `sendQueue.sendBatchEntries` owns prefix/fallback handling. Existing `sendMetadata` has no abandonment identity or success receipt. Therefore queue admission or packet registration cannot start the accepted unanswered-abandonment timer. Native endpoint completion and recovery-local completion exist as inactive support, but are not connected to this ordinary emission route. R9's E5 dependency supplies the later bounded multipath route; it does not discharge R8's unused-ID terminal obligation.

Disposition: scoped same-child repair. Extend the named blast radius to typed emission metadata and the existing sender's fact-only completion. Preserve the connection goroutine as membership, terminal and timer owner, CID managers as routing/reset owners, and the worker as socket-I/O owner. The exact supported scenario remains unused-ID control over path zero behind private activation. No public negotiation, consumed-path validation, replacement credit, endpoint admission policy or application-delivery semantics enter R8. Those boundaries remain with their named successor slices.

A synchronous owner-side send would remove a fact handoff but contradict ADR 0004's responsive connection loop and worker ownership. Moving retirement policy to the worker would duplicate protocol authority. Both are rejected on merit. A bounded immutable receipt carried by the existing handoff adds only late/duplicate/terminal fact reconciliation, with no new execution context or queue. The registry reads that fact and owns every timer transition. Isolating receipt-bearing datagrams from partial fallback avoids claiming acceptance from an error-only output interface; broader native-prefix integration remains R9/E5's existing boundary. Revisit that temporary restriction when R9 extends the same owner to its completed bounded-submission route.

The current plan records the relevant semantic matrix, 16-scenario ceiling and one focused race run. Blocking regression aids retain the existing transport-suite owner, profile, payoff and equivalent-replacement/feature-removal retirement rule. Other track contracts and native dependency edges are unchanged. No representation choice or operator decision is required. Publish this revision to main before synchronizing the exact child plan pointer and resuming R8 preflight.
