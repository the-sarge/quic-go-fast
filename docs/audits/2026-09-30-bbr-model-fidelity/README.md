# BBRv3 model fidelity and transport integration

**Date:** September 30, 2026, America/New_York. **Scope:** [Check BBRv3 model fidelity and transport integration](https://github.com/the-sarge/quic-go-fast/issues/668), under [Wayfinder map: explain BBR performance and decide the next qualification path](https://github.com/the-sarge/quic-go-fast/issues/666).

The frozen implementation has substantial transport work that the BBR algorithm does not require in this form, several selected adaptations whose costs need measurement, and model differences that need focused disposition. These findings define discriminating comparisons for [Explain the dominant causes of the BBRv3 regression](https://github.com/the-sarge/quic-go-fast/issues/669). They do not establish the dominant cause, select a correction, or judge algorithm suitability.

Full-run CPU includes setup, warmup and teardown; these values do not isolate steady-state work. ## Transport and sampling comparison

| --- | --- | --- |
| Delivery identity, bytes and ordering | Eligible ack-eliciting packets, including DATAGRAM-only traffic, carry copied snapshots and connection-wide ordinals. ACK-only and alternate-path probes do not produce rate samples; MTU probes may add delivered bytes but cannot anchor rate/RTT. One logical ACK accumulates first receipts, then uses the newest eligible ordinal and the longer send/ACK interval. This follows the selected local contract; no byte/bit conversion defect was found in these paths. [Sampler][sampler], [dispatcher][dispatcher] | Replay a bounded real ACK/registration sequence and independently recompute counters, anchor, interval and limited marker. Include equal-time batches, reordered/late ACKs and excluded probes; do not replace recovery with invented delivery. |
| Registration clock and raw RTT | The connection registers before asynchronous worker submission; BBR raw RTT includes local queue/worker residence and peer ACK delay. Recovery separately applies ACK-delay correction. This is an accepted timing approximation, not a discovered timestamp defect. The draft defines scheduled pacing departure time; local registration is deliberately the observation available here. [Design timing/RTT][design], [ACK RTT capture][ack], [worker][queue] | Measure registration-to-submission residence, deadline lateness, raw RTT and controller minimum together, with bounded observations and drop counts. | Application/flow limitation | Exhaustion is observed only after an otherwise permitted ordinary pack finds no eligible data; delivery boundaries use unresolved evidence, and the sender retains supply markers on subsequent registrations. [Observation owner][limitation], [sampler][sampler], [design][design] | Count stop reasons over time and markers on actual rate anchors. Compare continuous supply with controlled application and flow-credit pauses. The continuously offered fixture alone cannot establish that the transport never exhausts its immediate producer buffers. |
| Sampling epochs and genuine idle | Empty flight alone cannot reset an origin while retained evidence or local work remains. Genuine idle additionally requires observed application exhaustion and no evidence loss. Frequent sampling generations in the frozen snapshots are not themselves proof of genuine idle. [Dispatcher][dispatcher], [idle authority][sampler] | Record epoch changes with pre/post flight, unresolved bytes, pending credit and observed supply reason. Distinguish fresh sample origins from the stricter idle restart and detect whether invalid samples materially suppress model progress. |
| Recovery ACK service | The 32768-entry outcome ring retains ACKed/disposed history until overwritten or reset. `ack`, `confirmPTO` and the ACK-side persistent-span reducer scan its current count; this cost can remain after live flight becomes tiny and in a loss-free run. The prior profiles expose these functions. Bounded memory does not imply cheap ACK processing. This is an implementation strategy, not a required BBR model formula. [Outcome ledger][ledger], [retained-ACK path][dispatcher], [profiles][reproduction] | Count entries visited per ACK, ACK rate and ring occupancy over time; separately time/profile the three scans. Compare a semantically equivalent indexed/incremental experimental implementation, preserving exact episode membership, duplicate receipts, PTO confirmation, cross-space gaps and eviction. Merely skipping evidence changes correctness and cannot qualify as a competent correction. |
| Sender allocation | Every unblocked bounded opportunity refreshes M; `SetMaxDatagramSize` constructs a sender just to obtain initial-window arithmetic. Prior profiles attribute 67.86% STREAM and 34.27% DATAGRAM sampled sender allocation bytes to `NewBBRSender`, with refresh callers. This exercises [Avoid per-opportunity BBR sender allocation during packet-size refresh][allocation-followup]; the goodput/CPU/RSS effect remains unproven. [Admission][bounded], [size reducer][size], [profiles][reproduction] | Compare an arithmetic-only refresh at identical source/toolchain/workload, including unchanged and changed M. Measure allocated bytes, GC work, useful goodput, CPU/GiB, RSS and control latency. Preserve all size/floor/cap behavior. |
| Quantum utilization and batching | BBR emits at most one queue handoff per connection opportunity. Without GSO, `boundedDatagrams` stops after one datagram; Reno's ordinary loop can enqueue several before yielding. The managed endpoint explicitly reports GSO=false even when its platform supports native offload. This affects the frozen direct-managed fixture across platforms. Worker batch submission drains only entries already queued, so batching remains possible but its actual group size is unknown. [Bounded emission][bounded], [Reno loop][ordinary], [managed capabilities][managed], [worker grouping][queue] | Count handoffs, connection-loop passes, timer resets, queue wakeups and datagrams per actual socket submission. Compare bounded multi-datagram admission within the same Q/2Q limits while retaining receive/close fairness. Do not enable a different packet-I/O mode or enlarge Q and call the result a batching-only comparison. |
| Pacing and queue credit | Private fractional tokens apply one 1% margin, cap saved credit at Q, and compute ceiling deadlines without Reno's 1ms minimum. Ordinary local ownership is capped at 2Q through worker completion; reservations use a mutex and allocate per handoff. These are selected safety/cost trade-offs. The draft's quantum is a batching allowance, not a requirement to wake once per datagram. [Pacer][pacer], [local ownership][credit], [design][design] | Separate time waiting for pacing, recovery window, queue credit, worker service and CPU. At Q=65536, filling one quantum per millisecond is only 524.288 Mbit/s of packet bytes; sustaining more requires finer service or multiple opportunities, as the design already discloses. That arithmetic is not a measured macOS wakeup ceiling. |

[ECN owner][ecn] | Measure ledger occupancy, range fragmentation, allocations and CPU under representative advancing ACKs before optimizing. ## Model comparison

The source comparison maps Startup/Drain gains and plateau predicates, ProbeBW phases and filter aging, loss-derived bounds, ACK aggregation and cwnd quantization to the selected local profile. This is positive correspondence, not a complete equivalence certificate. The selected ProbeRTT safeguard, timed-plus-round exit, classic CE policy, initial cwnd and resource limits remain deliberate choices. | --- | --- | --- |
| Startup/Drain and ProbeBW | Gains, three qualifying plateau rounds, discontiguous-loss conditions, randomized probing and headroom are present. QUICHE's configurable Startup loss behavior and queue-threshold Up exit are not the selected policy; TCP's Drain behavior is also distinct. Four source differences lack an explicit disposition in the inspected design/controller-plan clauses. They warrant focused semantics checks before any proposed correction; their presence does not establish regression causality:

1. **All-spurious repair restores numeric bounds without restoring the loss-driven phase.** The undo record stores no phase, and `finishRecovery` restores bounds/window and resets plateau state without returning a loss-driven Startup/Up exit to Startup/Refill. [Local record and reducer][recovery], [reference restoration][draft-undo]. Drive qualifying loss out of each phase, then complete exact all-spurious evidence without CE/reset/ProbeRTT; compare phase and next allowance, with a mixed-loss negative case. Existing numeric undo coverage from Cruise does not settle these exits. This path requires actual qualifying loss and subsequent repair; the six loss-free frozen observations do not exercise it.

2. **The new RTT minimum influences the same ACK's phase decisions earlier.** Local Feedback saves the old probe cap, updates RTT, then handles general rounds/bandwidth/Drain/ProbeBW. The reference applies its RTT update after those phase decisions. Saving the old ProbeRTT cap is selected; the broader reorder is not explicitly dispositioned. [Local ordering][sender], [reference order][draft-order]. A source-derived oracle starts Drain at 100000 B/s, minimum 100ms and M=1200, with fewer than four completed Drain rounds; an otherwise valid ACK retains that rate, reports raw RTT 50ms and post-flight 7500 bytes. The old-minimum exit target is 10000 bytes, while the new-minimum target is 5000, above the 4800-byte output floor. Compare same-ACK phase/rate, then repeat with an expired increasing minimum. These are predicted branch outcomes, not executed measurements.

3. **General packet-round advancement is gated by rate validity.** Local Feedback returns through its invalid-rate path before advancing the general delivered-at-send round boundary. Some flight/time decisions still run, and ProbeRTT has separate receipt-based completion. The reference advances the packet round before testing positive rate. [Local validity gate][sender], [reference round update][draft-rounds], [ProbeRTT receipt gate][probe-rtt]. In Refill and Drain, provide otherwise valid current-generation delivered-at-send evidence crossing the boundary, but a rejected rate interval; compare rounds/phases with a valid-rate control. Count rejection reasons/frequency in the native workload before claiming prolonged Refilling or stale filter state. Missing-history/invalid-clock events are separate cases and cannot supply invented round evidence.

4. **Startup loss learns a long-term capacity that includes output quantization.** Local `inflightLong=max(inflight(1),latestVolume)` includes two-Q/four-M quantization; the reference's learned value uses unquantized BDP and recent delivered volume. The plan explicitly accepts quantized Drain and ACK output targets, which is distinct from learned loss capacity. [Local assignment/quantizer][sender], [reference Startup loss][draft-startup-loss], [controller plan][controller-plan]. Trigger a qualifying Startup loss when two Q exceeds both BDP and latest volume; inspect the learned cap before subsequent safe ACK growth, and compare later headroom/window allowances. Include high-BDP control and the output floor that may mask the difference. No qualifying loss is recorded in the six frozen observations.

Rate-validity gating and RTT-update order can engage without loss; the other two differences need loss triggers absent from those six retained runs. Existing tests and earlier prototype decisions are finite coverage, not proof that every translated state transition matches the authority. The comparison used descriptions and source behavior; it copied no upstream implementation code. The [earlier reuse/provenance investigation][baseline] remains authoritative context for any later proposal to reuse code.

## Handoff to causal diagnosis

The next investigation should start with the measured recovery-service and refresh-allocation leads, then distinguish per-datagram connection/worker service from pacing/model limitation. Each intervention should change one mechanism, keep the frozen receiver integrity boundary, and compare STREAM and application DATAGRAM separately against both original BBRv3 and matched Reno. Record negative or inconclusive results. Measure absolute useful delivery, CPU/GiB, allocated bytes, RSS and control latency with variability; preserve the map's existing readiness limits.

Source fidelity discrepancies need bounded receipt/event comparisons and explicit correction disposition even if they are irrelevant to the loss-free local symptom. Increasing queue allowances, changing classic-ECN policy, moving recovery to workers, or substituting a different controller would change the accepted contract and needs a separate design decision. No such change is selected here. The existing causal-diagnosis and correction-choice children already cover these questions; no additional implementation ticket or fog graduation follows from this source inventory alone.
