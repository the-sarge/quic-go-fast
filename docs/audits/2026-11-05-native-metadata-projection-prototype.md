## Changes and structural evidence

Admission arbitration now keeps value candidates and stores the selected lease in one endpoint-owned slot. Previously each eligible class allocated a 40-byte grant object, occupying a 48-byte allocator class, although only one selected grant survives. A focused characterization reproduced two allocations for a selection with data and control demand, then zero after the change. Ready/completed channels publish values, never a grant pointer. All temporary grant aliases end before release; successful admission and release clear the slot. Class selection, circular participant order, two-control-turn bound, lease start and expiry, capacity protection and wake ordering remain unchanged. The sparse iterator is unchanged: the allocation was the grant literal inside its callback, not an established iterator allocation.

A native member now owns a 56-byte outcome containing counts, byte result, error and time. Request identity, storage, member vector, publication timing and deadline-control error remain only in the 168-byte aggregate result. Actual 64-bit layout checks against the prior source and composed source show member rows falling from 240 to 128 bytes. Legacy leaf conversions retain exactly the fields their callers consumed. The writer initializes each attempted row once with its final facts, and on error initializes every untouched tail once with fresh unsubmitted counts and the failure's settlement time. It no longer initializes all rows eagerly and overwrites them after native return. In the healthy grouped writer sequence, datagram-count derivation falls from four walks to one, and one unused pre-write clock per group disappears. Queued disposal and deadline-setup failure retain the control-side fallback that populates every row before publication; final deadline-reset faults remain aggregate facts.

Recovery registration now shares one immutable nonzero-sized generation object containing the existing completion-owner pointer. A registration's former owner pointer plus numeric epoch become one generation pointer; canonical registration slots remain issued once and never manually recycled. Each packet-number-space incarnation obtains one generation lazily after existing validation. Retry's replacement space obtains a distinct identity; old tokens retain the old identity until no comparison is possible. Per-packet registration/eligibility time, PN, delivery ordinal and mutable outcomes remain per packet. Layout checks show 64-byte registrations becoming 56 bytes, and eight-record chunks becoming 448 rather than 512 bytes, with one 8-byte generation object per used incarnation. Completion owner checks gain one indirection. The owner is still an interior pointer into the same local state, so this does not eliminate its existing transitive retention.

The earlier construction-owned recovery packet and cleared single-frame backing are retained. A stale comment now acknowledges that never-registered preparations can also return to the pool. Sharing registration timestamps across arbitrary runs was rejected: short or interleaved runs can fragment headers or add per-packet allocation. ACK-target and mutable frame classification hoists were not added because existing hooks and reused frame storage make their observation interval significant. The still-1792-byte ordinary record and flattened buffer projection are separate hypotheses, not silently bundled changes.
