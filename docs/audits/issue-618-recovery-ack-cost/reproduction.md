# Reproduction recipe

This is frozen local diagnostic evidence for [issue #618](https://github.com/the-sarge/quic-go-fast/issues/618), not a maintained benchmark or CI timing gate. Reproduction is a new execution requiring its own accepted budget; these commands document the captured execution and do not renew its limits. Use Go 1.27.1 on the recorded Darwin arm64 host for the closest reproduction; host load, scheduling, GC and timer quantization remain uncontrolled.

Use a dedicated feature worktree at source `f47e09e3a5b4f9f8efc5de0ea73a01307d3a01f4`. Make the archived audit directory available there without altering the frozen files, and direct new output to a separate directory. The package is `github.com/quic-go/quic-go/internal/ackhandler`. All runs set `GOMAXPROCS=1`, enable the private rich event path, disable both ECN trackers and use one connection worker. No network is used.

## Initial diagnostic capture

Copy `issue618_measure_test.go.txt` to `internal/ackhandler/issue618_measure_test.go` and `issue618_snapshot.go.txt` to `internal/congestion/issue618_snapshot.go`. Run the command in `capture-command.txt`, changing only its output directory. That source is preserved exactly, including the atomic-copy reset defect diagnosed by the retained `candidate-vet.log`. Do not use that defect as a maintained reset pattern. The original capture is diagnostic evidence; corrected paired means own the recommendation.

## Corrected paired comparison

Copy `issue618_measure_v2_test.go.txt` to `internal/ackhandler/issue618_measure_test.go`, `issue618_compare_test.go.txt` to `internal/ackhandler/issue618_compare_test.go`, `issue618_snapshot.go.txt` to `internal/congestion/issue618_snapshot.go` and `issue618_utils_snapshot.go.txt` to `internal/utils/issue618_snapshot.go`. The v2 reset uses atomic load/store methods rather than copying atomic-bearing structs. Both comparison binaries must use this same corrected helper.

Build the baseline with `GOMAXPROCS=1 go test -c ./internal/ackhandler -o .git-issue618-baseline.test`. Decompress `candidate.patch.gz` to `candidate.patch`, verify it with `shasum -a 256 -c candidate-patch.sha256`, then apply that patch, then build the candidate with `GOMAXPROCS=1 go test -c ./internal/ackhandler -o .git-issue618-candidate.test`. Restore the production source afterward. The candidate is a disposable comparison only. The captured binaries' SHA-256 identities are in `comparison-identity.json`; binary bytes are not archived because profiles include symbols and the full build inputs are retained.

For a new, separately authorized capture, create a fresh disposable directory at the same depth under the dedicated source worktree, for example `docs/audits/issue-618-rerun/`, and copy only `compare.py` into it before running that copy. Do not run the driver from the frozen audit directory. The driver writes receipts, logs, tails and the candidate profile beside itself, overrides `ISSUE618_COMPARE_OUT` with that directory, and finds the test binaries through `root.parents[2]`; an arbitrary temporary-directory location will not locate the binaries correctly. Keeping the new directory initially empty also prevents stale pair records from entering profile selection. Do not change the frozen driver.

`compare.py` records the exact argument vectors and sequence in `comparison-execution.json`. It invokes each binary with `-test.run=^TestIssue618Comparison$ -test.v -test.timeout=65s`. The environment selects `ISSUE618_N`, `ISSUE618_RANGES`, `ISSUE618_SAMPLE`, `ISSUE618_IMPLEMENTATION`, `ISSUE618_COMPARE_OUT` and `ISSUE618_PROFILE`. Cell order is ascending N, then 1 / 32 ranges; pair order is baseline/candidate, candidate/baseline, baseline/candidate. Candidate tail collection is 3,333 individual calls per sample, totaling 9,999 per cell; the initial baseline already used its tail budget and collects no additional tails in comparison. Profiles run separately from unprofiled timings, once per implementation, for the highest-mean cell.

## Measurement and analysis boundaries

History is built using actual `SentPacket` and decoded/validated `ReceivedAck` calls. Each prefix batch has at most 32 outstanding 40-byte PING packets, below the initial congestion window. Packet numbers are deterministic and sequential. RTT samples are 10 ms, sends advance by 20 ms between batches, and the final packet is acknowledged after 10 ms. The measured ACK newly acknowledges exactly one packet. A fixed-size sink consumes event values without retaining slices. The parser validates ACK ranges before capture. The contract and JSON trace rows state the exact packet-number layouts.

Before each timed call, restore the previously reached valid fixture: handler and dispatch scalars, packet-space history with a fresh pooled packet, live packet map, outcome-ring states, controller state and atomic statistics. There is no active loss episode, retained delivery entry, crypto space, skipped packet or pending send credit in these fixtures. The existing outcome key map is read-only during these ACK calls and needs no restoration. The controller snapshot includes its pacer and cubic state. Ring copying warms caches; that is identical for both comparison binaries but limits deployment inference.

`time.Now()` immediately precedes `ReceivedAck`; `time.Since` immediately follows it. Assertions, fixture reset, raw CSV formatting and `runtime.ReadMemStats` are outside elapsed ACK timing. Allocation differences surround only that call. Memory-stat reads, snapshot copying and GC effects can still influence the next timed call; unprofiled samples own timing conclusions. The sink and normal Reno processing remain inside the measured boundary. Three samples each accumulate at least two seconds of measured ACK duration, with no automatic retries. Tail values are individual durations, not sample means. The first 3,333 operations of each sample form the tail sample; no independent random sampling or confidence interval is claimed. P99 uses the nearest-rank value `ceil(0.99*n)`.

For arithmetic checks, copy the archive to an analysis directory, extract `tails.tar.gz` there and verify the extracted files with `shasum -a 256 -c tails.sha256`. The tar archive preserves the exact CSV bytes; gzip compression keeps the PR diff readable. The full corrected candidate test log is similarly retained as `corrected-candidate-tests.log.gz`. Run `python3 summarize.py` and `python3 summarize-comparison.py` only against that analysis copy when rechecking arithmetic. They produce `summary.json` and `comparison-summary.json`. Profile summaries were produced with `go tool pprof -top -tagfocus=phase=ack cpu.pprof` and the same command for `candidate-cpu.pprof`; the `phase=ack` filter separates measured recovery work from fixture resets. Pprof percentages retain the full-profile denominator, so conditional percentages must divide by the filtered ACK sample total. Attribution is sampled CPU time, not a conversion of elapsed ACK latency into deployed utilization.

All temporary Go helpers, binaries and the candidate production diff are removed before the evidence PR is committed. Frozen scratch sources have `.go.txt` suffixes and are not part of the Go build. Existing T5 and affected-package tests provide candidate correctness evidence; no new maintained test or timing gate is installed.
