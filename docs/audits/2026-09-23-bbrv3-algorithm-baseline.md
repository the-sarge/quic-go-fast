# BBRv3 algorithm baseline investigation

Research for [Establish the BBRv3 algorithm baseline](https://github.com/the-sarge/quic-go-fast/issues/554), a child of [Design opt-in BBRv3 for GridCast bulk transfers](https://github.com/the-sarge/quic-go-fast/issues/552). Evidence inspected on 2026-09-23. This is a recommendation for the later human design session, not an accepted algorithm selection, implementation, or performance result. The local repository baseline is `c9e687e4ebad69bb9f53e78aae7566d06006b722`.

## Recommended baseline and precedence

Use **published `draft-ietf-ccwg-bbr-06` as the algorithm baseline**, with its source frozen at `6db913f5ec575a8852bea926bd6001884e579496`. It explicitly describes BBRv3, was published on 2026-07-06, and remains an Experimental Internet-Draft. Treat Google's TCP BBRv3 and QUICHE Bbr3Sender as separately pinned implementation evidence; neither is an interchangeable executable definition of the draft. The comparison below identifies the differences that make this distinction necessary. [Published draft][draft06] [Publication status][datatracker]

Recommended source precedence, subject to the owner's decision in [Settle the implementation-ready BBRv3 design](https://github.com/the-sarge/quic-go-fast/issues/558):

1. Preserve QUIC's transport obligations and this fork's accepted ownership and platform boundaries. A BBR algorithm choice does not override packet-number spaces, PTO semantics, packet disposal, or the [managed ECN qualification boundary][local-ecn].
2. Use draft 06's specified behavior, constants and state transitions as the default target. Record each permitted choice, ambiguity resolution and deliberate deviation in the eventual design, with a focused test obligation.
3. Use editor revision `4ce5e87d5f58c34c8fae283367b41913d110b73a` for its explicit statement that the algorithm description defines required behavior. Its post-publication changes are grammar and clarification, not a new probing or filtering algorithm. Do not silently promote unmerged proposals into this baseline. [Editor comparison][editor-diff]
4. Use TCP revision `90210de4b779d40496dee0b89081780eeddf2a60` to understand mature algorithm mechanics and diagnose underspecified pseudocode. Its TCP recovery, packet units, pacing/offloads and optional ECN machinery require translation, not mechanical adoption.
5. Use QUICHE revision `41ee992597583771801dcb8569e1eca71842ef74` for QUIC sampling, event organization and test ideas. Select the actual Bbr3Sender path and enumerate its active defaults/options; a BBR class name or shared Bbr2 helper is insufficient evidence of version equivalence.

An implementation should name this tuple and its deviations, rather than claim compatibility with moving `main` or `v3` branches. Later upstream changes should receive a new evidence comparison and an explicit decision. The optional tsuna BBRv1 lead was not needed to establish this baseline and is not a recommended dependency.

The following are the proposed target behaviors against which to read the TCP/QUICHE differences below, not additional decisions made by this investigation.

### Version identity

Current public Google QUICHE has a distinct `Bbr3Sender`, selected by the `kBBRv3` factory case. It is no longer accurate to describe QUICHE as providing only BBRv1 and BBRv2. Its v3 sender has concrete draft-oriented changes, including derived Startup pacing gain, different Drain/Down gains, Startup ACK aggregation, and a larger ProbeUP congestion-window gain. However, it reuses `Bbr2NetworkModel` and `Bbr2Params`, and retains important behavioral differences from Google's TCP v3 implementation. The factory and behavior establish the version distinction; the filename alone does not establish equivalence to a particular IETF draft. [QUICHE factory](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/send_algorithm_interface.cc#L32-L54), [v3 initialization](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.cc#L32-L76), [v3 congestion window](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.cc#L418-L467), [v3 ProbeBW gain](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.cc#L728-L769).

“Default” in this comparison means checked-in values without connection-option overrides. QUICHE also has runtime-configurable flags; these sources do not establish its production deployment profile. Negative findings concern the controller and shared model paths, not absence of transport loss detection or frame retransmission.

### Sampling and application limitation

**TCP observation.** Transport code snapshots delivered/lost/CE counts, send and ACK timing, app-limited state and inflight volume into each skb. Its sample uses delivered packets divided by the larger send/ACK interval, rejects unusable observations and SACK reneging, and excludes intervals shorter than transport minRTT. The BBR controller converts valid samples to scaled packets per microsecond. Its max-bandwidth filter accepts non-app-limited samples or app-limited samples at least as high as the previous maximum. [TCP snapshots and sample construction](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_rate.c#L55-L214), [controller sample](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L764-L785), [sample admission](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L1475-L1496).

TCP marks the app-limited boundary only when there is less than one MSS queued, the host transmit queues are effectively empty, cwnd is not limiting and lost packets have been retransmitted. The boundary clears only after delivered data passes it. Thus a temporary lack of new application data is insufficient by itself. [TCP app-limited detection](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_rate.c#L217-L232), [boundary clearing](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_rate.c#L146-L148).

**QUICHE observation.** The sampler stores per-packet send state only for packets classified as having retransmittable data, resets its sampling origin when flight is empty, and tracks bytes rather than TCP segments. It calculates `min(send_rate, ack_rate)` and can further cap the sample using receive timestamps when available. Its RTT sample is raw ACK time minus packet send time; it explicitly does not subtract ACK delay. Application limitation is declared by an external callback, gated by `bytes_in_flight < cwnd`; the sampler captures the last-sent packet boundary and clears it on a later ACK. App-limited samples enter the max-bandwidth filter only when strictly greater than the maximum. [Send metadata](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bandwidth_sampler.cc#L173-L255), [rates and RTT](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bandwidth_sampler.cc#L392-L506), [callback gate](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.cc#L505-L514), [boundary](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bandwidth_sampler.cc#L573-L576), [filter admission](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr2_misc.cc#L147-L165).

QUICHE aggregates all valid samples in an ACK event, retaining the maximum bandwidth and minimum RTT, but uses the last relevant send state for congestion decisions. It processes losses first and explicitly skips ACKs marked as spurious loss, requiring their acknowledged-byte count to be zero. This is materially different from treating a later ACK of a declared-lost packet as newly delivered model evidence. [ACK/loss event processing](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bandwidth_sampler.cc#L266-L350).

**Decision implications.** Specify the quic-go packet metadata, byte-accounting domain, send-time clock boundary, app-limited attribution, packet-number-space handling, ACK-delay policy, ACK batching order, late ACK treatment and metadata lifetime before porting formulas. QUICHE's direct packet-number comparisons and TCP's delivered-packet markers are different transport mechanisms for the same broad need. Do not mechanically map the word “retransmittable” to QUIC DATAGRAM exclusion; the quic-go adapter must deliberately define which congestion-controlled bytes produce samples.

### Bandwidth, minRTT and ACK-aggregation filters

**Bandwidth.** Both implementations retain two cycle-oriented bandwidth maxima, rather than a simple ten-RTT BBRv1 window. TCP advances its filter when feedback from probing stops and the sample is not app-limited. QUICHE can advance after one complete round in Down when the last packet was not app-limited, then has a fallback advance on leaving Down if it has not already advanced. An empty newest slot does not evict the older value in either implementation. The accepted sample's app-limited status and the last packet's status are not interchangeable. [TCP filter](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L981-L997), [TCP feedback boundary](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L1661-L1684), [QUICHE filter](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr2_misc.h#L299-L319), [QUICHE Down boundary](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.cc#L774-L793), [QUICHE exit fallback](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.cc#L1223-L1230).

**minRTT.** TCP has a 10-second main minRTT window and a separate 5-second ProbeRTT-min window, with delayed-ACK qualification when replacing an expired probing sample. QUICHE's shared model has a single minimum value and timestamp; ordinary updates only lower it, while expiry force-replaces it with the current event's minimum RTT. Checked-in expiry is 10 seconds. In v3, that expiry check occurs when leaving Down; idle time can postpone the timestamp. These are substantive differences in aging and entry opportunities. [TCP constants](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L183-L193), [TCP filter and entry](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L885-L918), [QUICHE min filter](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr2_misc.cc#L61-L82), [QUICHE expiry](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr2_misc.cc#L362-L377), [QUICHE default](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/common/quiche_protocol_flags_list.h#L133-L144), [QUICHE call site](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.cc#L742-L762), [idle postponement](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.cc#L534-L573).

**ACK aggregation.** TCP adds an excess-ACKed allowance and uses a roughly 1–2-round Startup window, then 5–10 rounds, with the cwnd increment additionally limited by a 100ms bandwidth allowance. QUICHE v3 always adds `MaxAckHeight` before quantization, uses a one-round Startup tracker and changes its window when Startup ends. Its sampler also exposes optional overestimation and ACK-height adjustments; these options are separate behaviors, not automatically implied by selecting v3. [TCP aggregation](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L669-L683), [TCP windows](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L787-L850), [QUICHE initialization](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.cc#L62-L69), [QUICHE cwnd](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.cc#L418-L467), [QUICHE Startup exit](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.cc#L525-L531), [QUICHE options](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.cc#L80-L199).

### State-machine comparison

| Area | Pinned TCP v3 behavior | Pinned QUICHE v3 behavior | Baseline consequence |
| --- | --- | --- | --- |
| Startup gains | Fixed-point approximation to 2.77 pacing; 2.0 cwnd | Sets model gain to 2.773; initial `pacing_rate_` is still initialized using shared parameter 2.885; cwnd gain 2.0 | Initialization and first-ACK behavior must be specified separately from steady Startup gain |
| Startup plateau | While `full_bw_now` is false, a non-app-limited bandwidth sample on any ACK can reset the plateau; three qualifying non-app-limited rounds with less than 25% growth | Checks model max bandwidth at round end; increments no-growth counter even on app-limited rounds but only latches full bandwidth on a non-app-limited final event | “Three rounds without growth” does not fully define identical behavior |
| Startup loss | Requires recovery, a loss-round boundary and at least six loss events, plus excessive sample loss | Default eight loss events and excessive current-round byte loss; checks only when growth failed unless an option changes this | Recovery and loss-event counting need transport-specific definitions |
| Drain | Pacing gain about 0.346; exits after estimated network inflight falls to target | Pacing gain 0.5; exits at target or when `drain_rounds_ > 3` | Preserve exact comparison and event ordering when selecting a duration rule |
| ProbeBW pacing | Up 1.25, Down nominal 0.91, Cruise/Refill 1.0 | Up 1.25, Down 0.9, Cruise/Refill 1.0 | Numerical divergence is explicit |
| ProbeUP cwnd | 2.25 gain, with inflight-hi cap and exponential cap growth when utilized | 2.25 gain; by default ignores inflight-hi in Up and disables explicit slope growth | Similar gain does not establish equivalent congestion response |
| ProbeUP exit | Excess loss/eligible ECN, risky reprobe, or bandwidth plateau unless inflight-hi is limiting growth | Excess loss, risky reprobe, or default queue threshold after a round: 1.25 BDP plus two default TCP MSS units and ACK-height allowance; optional persistent-queue variants | The default QUICHE path retains a fundamentally different probing termination rule |

[TCP scheduling and refill](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L1506-L1594), [QUICHE parameters](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr2_misc.h#L128-L150), [QUICHE flags](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/common/quiche_protocol_flags_list.h#L124-L131), [QUICHE scheduling](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.cc#L918-L974), [QUICHE refill](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.cc#L1181-L1221).

### Congestion bounds, loss and ECN

**Common model.** Both have a filtered maximum bandwidth, short-term `bandwidth_lo`/`inflight_lo` and long-term `inflight_hi`. Default loss response outside probing reduces the short-term limits by approximately 30%, without reducing them below recent delivered bandwidth/volume. A finite inflight-hi leaves approximately 15% headroom in Cruise. Refill clears lower bounds to allow renewed probing. These “lower bounds” describe estimates of available capacity, but are used to cap sending; they are not minimum cwnd floors. [TCP lower bounds and cap application](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L1284-L1409), [QUICHE lower bounds](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr2_misc.cc#L225-L266), [QUICHE bound application](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.cc#L201-L234), [QUICHE headroom](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr2_misc.cc#L439-L443).

**Loss attribution differs.** TCP judges excessive loss using losses over the sample's transmission flight and can derive a precise loss-threshold crossing within a lost skb. QUICHE's shared model compares current-round lost bytes to last relevant packet send-state inflight, explicitly noting the alternative of losses since that packet was sent. QUICHE requires two loss marking events by default in ProbeUP. Aggregate loss per ACK event, loss per round and loss over a sampled flight are not interchangeable. [TCP excessive-loss predicate and threshold-crossing derivation](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L1172-L1262), [TCP per-skb callback](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L2176-L2200), [QUICHE predicate](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr2_misc.cc#L379-L413), [QUICHE event defaults](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/common/quiche_protocol_flags_list.h#L146-L157).

**ECN is not shared behavior.** TCP contains ECN eligibility, EWMA, Startup exit and inflight-bound responses. Eligibility requires TCP ECN flags, a low-latency ECN mode and the configured RTT condition (default 5ms limit). QUICHE v3 ignores `num_ect` and `num_ce` in its congestion callback and returns false from both ECT-enablement methods. Consequently QUICHE v3 is not a reference for adding BBR CE response merely because the enclosing QUIC transport supports ECN. [TCP eligibility](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L368-L372), [TCP ECN setup/update](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L1048-L1113), [TCP ECN defaults](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L262-L313), [QUICHE ignored counters](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.cc#L255-L261), [QUICHE ECT methods](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.h#L97-L99).

### Recovery, undo, pacing and transport boundaries

**TCP recovery.** TCP's controller saves cwnd and congestion bounds on recovery entry and restores bounds by maxima on undo; its undo also resets the bandwidth plateau detector and forces model/control reevaluation. It has separate loss callbacks, loss-probe repair handling, RTO state handling and recovery exit. These depend on TCP's own loss state, sequence/SACK processing, packet accounting and path logic. They cannot be transplanted as QUIC recovery semantics by renaming callbacks. [TCP save/undo](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L2224-L2250), [loss-probe handling](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L2203-L2222), [RTO state callback](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L2315-L2339).

**QUICHE recovery gap.** `Bbr3Sender::InRecovery` always returns false and contains an implementation TODO; retransmission-timeout and migration callbacks are empty. The inspected shared sampler skips spurious-loss ACKs, rather than calling a controller undo path. QUICHE therefore supplies useful ordinary loss accounting and send-state patterns, but does not supply an equivalent implementation of the TCP save/undo contract. The surrounding transport still owns detecting loss and retransmitting frames. [QUICHE recovery/timeout/migration](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.h#L33-L69), [spurious-loss sample exclusion](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bandwidth_sampler.cc#L291-L301).

**TCP pacing.** Pacing is computed from rate, gain, MSS and a 1% margin, then capped by the socket maximum. Its cwnd quantization budget reserves at least three TSO batches and adds two packets in Up. It explicitly estimates packets in the network at the next earliest departure time because “in flight” includes packets still queued in the host's pacing layers. [Rate conversion](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L412-L438), [margin](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L202-L208), [offload budget and departure-time correction](https://github.com/google/bbr/blob/90210de4b779d40496dee0b89081780eeddf2a60/net/ipv4/tcp_bbr.c#L607-L665).

**QUICHE pacing.** The controller exposes a rate and cwnd permission; `PacingSender` separately schedules sends, implements burst/lumpy allowances, accounts for pacing-limited catch-up, and clears burst tokens on loss. Controller rate calculation has a special first-ACK rule and otherwise follows model gain times estimated bandwidth, with Startup generally monotonic. Its quantization budget explicitly has an offload-budget TODO, applies the minimum congestion window and adds two default TCP MSS units in Up. Thus the QUICHE controller's output rate alone does not describe actual burst behavior. [Controller pacing and cwnd](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/bbr3_sender.cc#L380-L467), [pacer send accounting](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/pacing_sender.cc#L40-L132), [pacer permission and timers](https://github.com/google/quiche/blob/41ee992597583771801dcb8569e1eca71842ef74/quiche/quic/core/congestion_control/pacing_sender.cc#L141-L187).

**Decision implications.** Preserve quic-go's packet-emission and pacing ownership while defining the BBR adapter's timestamp and inflight semantics. Specify whether GSO batch construction, send-worker queue residence and kernel queue residence count as measured flight, and whether the algorithm needs an offload allowance or departure-time correction. A Linux `sk_buff`, TCP MSS, TCP SACK state or QUICHE global packet-number ordering is not a portable QUIC API. Specify how timeout/persistent-congestion handling, path migration, PMTU changes and spurious-loss evidence affect model state, bounds, packet metadata and prior cwnd; the no-op QUICHE callbacks cannot settle those choices.

## Reuse and attribution

The recommended implementation route is Go code derived from the documented algorithm, with any reused permissive QUICHE components identified individually. Keep behavioral reference and permission to copy source separate.

- **This fork:** the pinned root [MIT license][local-license] requires retention of its copyright and permission notice for copies or substantial portions. Adding differently licensed third-party code requires retaining that code's applicable notices as well.
- **IETF:** draft 06's copyright notice requires the Revised BSD text for extracted Code Components. The applicable [corrected Trust Legal Provisions 5.0][tlp] supplies the code-component terms and attribution/disclaimer text. Preserve those terms when translating or extracting pseudocode. The source repository's short `LICENSE.md` delegates to its contribution policy; it is not a blanket MIT license. [Published notice][draft-copyright] [Contribution policy][draft-contributing]
- **QUICHE:** its pinned root [BSD three-clause license][quiche-license] requires retaining the copyright, conditions and disclaimer in source, reproducing them in binary distribution materials, and observing the non-endorsement clause. Its [Bbr3Sender header][quiche-bbr3] names the Chromium Authors and points to that license. Record exact originating files and revisions for any translated fragments or tests; audit additional dependencies individually.
- **Linux/Google TCP:** `tcp_rate.c` is explicitly [GPL-2.0-only][tcp-rate-license]. `tcp_bbr.c` ends with [the `Dual BSD/GPL` module tag][tcp-bbr-license], but the tree's [license rules][tcp-license-rules] explicitly say this tag does not determine the exact source license. The [kernel COPYING file][tcp-copying] also does not grant blanket BSD reuse of this tree. Consequently, this investigation does **not** establish a permissive reuse grant for arbitrary TCP code or dependencies. Use the Linux implementation as behavioral evidence; establish file-specific licensing before any proposed code translation/copy. In particular, do not lift the GPL-only rate sampler into an MIT/BSD implementation on the strength of the controller's module tag.

No reference implementation source is vendored or translated in this research artifact. These are the observed source notices and the proposed provenance policy; the eventual implementation's concrete reuse inventory still needs to match the code actually taken.
