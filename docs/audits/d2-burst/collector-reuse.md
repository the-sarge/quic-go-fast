# Retained collector cleanup and reuse

The [issue #18 agent brief](https://github.com/the-sarge/quic-go-fast/issues/18#issuecomment-5631425150) authorizes a narrow cleanup repair of `collect.py`. Supported reuse is the same bounded baseline/head-index experiment and recorded host setup: the existing CPU partition, affinity, binaries and experiment-root layout. This is a retained experiment tool, not a maintained benchmark framework. A different host, workload, CPU topology or broader reuse requires a separate scope decision. Any new collection requires separate explicit authorization and does not reopen completed D2 or justify promoting head-index. Retire the collector from use outside this scope; saved-artifact analysis remains independent of it.

The repaired source is a later revision. Historical scripts can be recovered from the recorded commits; the saved measurements, receipts, profiles, source hashes and conclusions retain their original meaning. No new measurements were taken for this repair. A separately authorized reuse must deliberately stage the repaired collector with the existing helper protocol rather than assuming that a frozen baseline checkout contains this repair.

## Ownership and failure behavior

`main()` owns exactly one isolation-cleanup attempt after `isolation("setup")` returns successfully. Receipt persistence and collection happen inside that lifetime. Failed setup remains the existing isolation helper's partial-setup rollback responsibility; the collector neither writes a successful-setup receipt nor duplicates cleanup after a setup error.

The SIGINT, SIGTERM and SIGHUP handler records the first interruption without raising asynchronously. Explicit checkpoints before setup, inside the protected lifetime and at sample boundaries raise the interruption; finalization also reports a newly pending interruption after cleanup. This deferral covers the setup-return transition and repeated signals during teardown/restoration. Signal response can wait for the current subprocess operation; it is not an immediate cancellation deadline, and the existing isolation helper remains unchanged.

One `stop_process` operation handles each tracked receiver, pacer and monitor. It polls, attempts termination, waits at most 10 seconds, and escalates to kill plus a second wait of at most 10 seconds when the first wait fails. Errors from individual poll, terminate, kill and wait operations are retained while teardown continues for other tracked processes. The outer cleanup `finally` keeps CPU cleanup reachable independently of teardown. Already-exited processes need no termination. The wait bounds apply per tracked process, not to the entire experiment or the isolation helper command.

Cleanup invocation is not confirmation of restoration. Only a successful return from the existing helper confirms its cleanup checks; only then is its receipt written to `isolation-after.json`. Cleanup failures report restoration as unconfirmed. Receipt-persistence failures still fail the collector, even if cleanup succeeded. If collection and finalization both fail, the resulting error includes each operation's diagnostic and chains the initiating exception. A recovered teardown timeout is also reported rather than silently discarded. These guarantees cover ordinary Python unwinding and errors returned by the supported subprocess/filesystem interfaces; forced process death, host failure and an unresponsive isolation helper cannot be repaired by a Python `finally` block.

## Finite acceptance evidence

The supported representation is the existing Python `subprocess.Popen` lifecycle and filesystem exceptions, plus the unchanged setup/check/cleanup helper protocol. Python and the helper own those representations. The guarantee is universal cleanup-attempt ownership within that supported lifetime, backed by the following finite mocked semantic cases; it does not promise successful restoration after a helper failure. `collect.py` is required safety enforcement for retained-tool reuse; `test_collect.py` is a verification aid; this document is scope and traceability metadata. None changes shipped QUIC behavior.

| Semantic case | Expected behavior | Evidence in `test_collect.py` |
| --- | --- | --- |
| Manifest open fails or setup fails | No collector cleanup obligation or false before receipt | `test_manifest_open_failure_never_attempts_setup`, `test_setup_failure_leaves_partial_rollback_to_helper` |
| Initial receipt, process start, sample persistence or collection fails/interrupted | One cleanup attempt, original diagnostic preserved | `test_initial_receipt_failure_still_cleans_up_once`, `test_process_start_failure_still_cleans_up`, `test_sample_persistence_failure_still_cleans_up`, `test_keyboard_interrupt_still_cleans_up` |
| Receiver timeout with a tracked pacer | Terminate/finite wait/kill/finite wait, remaining teardown and one cleanup | `test_receiver_timeout_escalates_and_tears_down_pacer_and_monitor` |
| Monitor ignores termination | Bounded wait, kill and bounded final wait, one cleanup | `test_monitor_timeout_has_bounded_kill_fallback` |
| Each tracked role fails poll/terminate/first wait/kill/final wait | Continue best-effort teardown, retain diagnostics, one cleanup | `test_individual_teardown_errors_preserve_other_teardown_and_cleanup` |
| Normal successful smoke lifecycle | One cleanup and both receipts | `test_normal_lifecycle_cleans_up_once` |
| Handled signals at setup ownership transition, failed setup or finalization | Defer interruption across ownership and cleanup; retain helper-owned failed-setup rollback | `test_signal_at_successful_setup_transition_still_cleans_up`, `test_signal_during_failed_setup_does_not_duplicate_helper_rollback`, `test_repeated_signals_during_teardown_do_not_interrupt_cleanup`, `test_signal_during_cleanup_retains_restoration_failure` |
| Cleanup or final receipt fails, possibly alongside initiating/teardown errors | Report failure, retain initiating/teardown diagnostics, no false after receipt | `test_cleanup_failure_is_not_recorded_as_restoration`, `test_final_receipt_failure_is_reported_after_cleanup`, `test_initiating_teardown_and_cleanup_failures_are_all_reported` |

Run the lifecycle suite with `python3 -m unittest discover -s docs/audits/d2-burst -p 'test_collect.py' -v`. It invokes `main()` with mocked filesystem effects, isolation commands, process creation and waits, signal registration and sleeps. It never runs sudo, touches live cgroups, reserves CPUs, runs measurement binaries or collects samples. The original initial-receipt and child-timeout regressions were observed failing before their corresponding fixes. These direct regressions and the finite lifecycle table terminate cleanup evidence; no additional mutation campaign, platform experiment, live collection or recursive validation of the test aid is required.
