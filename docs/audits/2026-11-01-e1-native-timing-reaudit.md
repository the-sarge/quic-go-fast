## Gates and design-cost comparison

The accepted E1 outcome, private typed request domain, one endpoint control owner/one native writer, inactive activation seam and one-product-PR boundary remain intact. Native return facts are internal Go values owned by the writer; no external grammar, wire format, public API, endpoint provider or representation authority changes. The representation gate remains universal over those typed lifecycle facts, with finite regression evidence rather than a completeness proof. Existing scheduler/qualified-OS caveats remain; no native support or hard-real-time claim is added.

The selected design replaces result-valued channel authority with one immutable return fact on the claimed token, atomically published after the writer's last native/deadline action. The channel becomes a capped coalesced wakeup. Control has one reconciliation operation that inspects that fact before overdue classification, terminal publication or storage release. A current token with no published acknowledgment retains its native fence; a published timely acknowledgment cannot be reclassified from control latency. A genuinely late acknowledgment still faults and preserves actual acceptance. The fact is the current request's reserved completion record viewed at the native boundary, not another unbounded record store.

This replaces two timing representations with one. It adds no execution context, deadline owner, protocol decision or persistent state. Late/coalesced/stale wakeups are harmless because they carry no result or identity; the current token's fact remains authoritative. The writer performs no payload access after publication. Control publishes and retires that token exactly once before another claim; revocation/stop still retain an unacknowledged borrow. Construction and fresh-instance checks, both timing consumers, cancellation/retirement and late-return disposal are inside the same module. The 128-request/8 MiB caps, 256 reserved records, participant/readiness bounds, diagnostic caps and permanent unregistered route are unchanged.

| --- | --- | --- |

| Per-request timeout goroutine that frees storage | Adds execution contexts and can release a live native borrow | Rejected on merit; no revisit trigger |
| Split native phase publication from control reconciliation into separate product PRs | Leaves a mixed authority model that cannot independently satisfy this same invariant | Rejected on merit; no revisit trigger |
| Merge E2 recovery or later shutdown/public activation work | Adds independent protocol/public owners and adjacent slice contracts | Outside E1; no revisit trigger within this execution |

Runtime mechanisms remain shipped behavior; current-token authority/timing guards remain required safety enforcement. The existing named tests remain maintained verification aids owned by the transport suite, with the binding equivalent-replacement/feature-removal retirement policy. The controlled scheduling barrier uses the existing private control mailbox only in a test and observes the endpoint interface; it creates no production hook or new maintained analyzer. This audit, matrix and receipts are process metadata.

The only newly traced effects are one bounded native fact publication/read and coalesced notification on the inactive route. Default-off code, socket-close ownership, protocol registration/recovery, ECN/congestion policy and native-platform qualification are unchanged. There is no untraced effect. The current E1 source plus the two timing reports fit the existing 24k dispatch budget; full historical plans and unrelated closed findings are excluded.

## Termination and publication

The normative matrix covers timely published return with delayed control, actual late return, absent acknowledgment, cancellation/stop, stale/coalesced wakeup and native-control failure. Strengthen the existing return-boundary function with one deterministic scheduling barrier; retain the other existing cases and the 16-function ceiling. Use the one still-reserved focused race run only on the final candidate, plus ordinary root tests/vet/tidy/lint/go-fix and existing portability/hosted checks. No extra native run, timing repetition, platform campaign, mutation or recursive harness validation is added.

The original two-review cycle ended at the approach stop. After default-branch publication and exact child-pointer synchronization, rebase the retained product branch, implement the central correction, and verify the triggering replacement review at the exact pushed head. The implement-architecture-slice review-triggered resume protocol then supplies one fresh closure review; no further replacement or reviewer-exhaustion criterion is added. This finite extra review is justified by the changed central enforcement design, not by a desire for more confidence. A further distinct counterexample at the precise root or any expanded product/representation/authority/PR boundary stops execution under the shared routing rules.
