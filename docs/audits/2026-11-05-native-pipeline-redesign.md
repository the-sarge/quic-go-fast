# Native request pipeline redesign for N3 #1202

**Status:** selected design candidate, not an accepted implementation contract or dispatchable slice. **Date:** 2026-11-05. **Scope:** redesign the private granted endpoint's complete production, admission, native-write and completion cycle. **Related:** [whole-pipeline diagnosis](2026-11-05-native-pipeline-diagnosis.md), [current stopped N-track plan](../adr/2026-11-04-native-endpoint-efficiency-plan.md), [endpoint ownership contract](../adr/2026-10-24-multipath-endpoint-plan.md#endpoint-ownership-contract). Existing N3 #1202 remains stopped. This proposal neither adds a prerequisite issue nor changes the accepted product thresholds.

## Decision and reason

Make one bounded, immutable endpoint request containing several existing packet buffers the unit of admission, native dispatch and terminal exchange. Construct it in the connection owner, submit it once with its exact size, let the native writer drain its members consecutively, and apply the returned packet facts in order in the connection owner. The endpoint remains the single authority for shared capacity, fairness, deadlines, revocation and native borrow lifetime.

The previous design addressed ownership and failure correctness in detail. Its missing argument was the cost of the complete cycle. The adapter makes each GSO buffer a separate endpoint request, reserves from a generic capacity predicate, cancels many empty reservations, polls one result at a time and repeatedly wakes progress. Those choices were not required by the accepted request contract, which already permits up to 32 buffers and 1 MiB per ordinary request. Changing only the mutex, wake source or PTO fold did not repair the product result.

The selected replacement is a deeper request interface, not a larger queue or a collection of special fast paths. Its intended work bound is one admission transaction per prepared request, one terminal transfer per request within a bounded drain, and one fair service decision per request. Packet construction, packet registration, native datagrams and ordered recovery effects remain real work; no cost claim treats them as eliminated.

## Verified basis and feasibility limit

Source references in this document refer to preserved candidate `59b1dddc650be03a98cbd8d7f8e5fb3f34967e0e`; main is `b39389b152a728232b7ec68ed1060c213c6649a8`. The candidate's synchronization is unmerged source material, not an established dependency. Recovery and ordinary-adapter observations also apply to that main tree. Historical measurements and source identities belong in the linked diagnosis.

- `native_ordinary.go:204–253`: `WouldBlock` obtains local and endpoint capacity before knowing whether packing produces a buffer. `native_ordinary.go:123–143` restricts submission to one buffer.
- `packet_emission.go:315–366`: GSO emission can produce multiple buffers in one invocation; receive work, no data, resource pressure and recovery decisions end the turn. It need not wait for future application data to group already-produced buffers.
- `native_ordinary.go:730–786`: each endpoint result is taken through a separate control entry, followed by an empty take. Member receipts, MTU feedback, recovery completion and path failure policy currently live here.
- `native_endpoint.go:302–315`: synchronized control runs progress before and after an operation and always notifies the independent runner. `native_endpoint.go:1138–1284` separates native ownership from control, but its GSO path assumes the one-buffer shape.
- `internal/ackhandler/local_completion.go:143–237`: registration and completion are ordered protocol operations. `internal/ackhandler/sent_packet_handler.go:370–440` updates flight, congestion and ECN state used while building subsequent packets.

The matched pure-binary comparison measured baseline 1.025327 CPU ns/useful byte and granted 1.871869. The unchanged 110% ceiling is approximately 1.127860. About 88% of the current excess must disappear. This is a feasibility warning, not an allocation of independently removable profile buckets. Cumulative profiles overlap; subtracting their apparent costs does not predict a valid end state.

The baseline diagnostic emitted 1,219,857 buffers in 570,730 send invocations, including empty invocations: approximately 2.137 buffers per invocation. Its raw stops were 327,458 no-data, 243,093 receive-pending, 20 queue-full and 159 congestion-limited. This demonstrates that an emission turn is not inherently one buffer. It does not prove that the redesigned schedule will have the same distribution or achieve four-buffer groups for every 64 KiB application write. The failed native candidate emitted 508,340 buffers across 574,559 invocations, including 209,935 queue-full stops; its four per-buffer records truncate production. Do not enlarge those records as a substitute for changing their work unit.

## Request representation and ownership

A prepared request has immutable connection, path, tuple, epoch and request-sequence identity; its original absolute deadline; and an ordered vector of typed members. Each native member names exactly one existing packet buffer, its GSO size, ECN/OOB and endpoint-owned credit. The connection retains a separate, index-aligned sidecar containing packet-token ranges, MTU hooks, terminal receipts and other protocol metadata. The sidecar maps each packet to its member and datagram: several coalesced handshake packets may share one datagram, whereas GSO segments map separately. A token count is not assumed to equal a datagram count. The endpoint and writer never acquire those recovery/protocol fields. Admission transfers the native descriptor storage or copies it into bounded endpoint-owned storage; the connection cannot mutate or reuse it while borrowed, and cannot read a released payload through a retained handle. Heterogeneous GSO shapes or ECN marks are represented per member. Different destinations, tuple generations, epochs or service classes require different requests.

A member result contains its accepted, uncertain and proven-unsubmitted datagram counts, error classification and actual return timestamp. Never-attempted members and locally canceled Building/Staged work instead use a nonzero terminal-decision timestamp no earlier than their registrations; it is a settlement time, not a claimed native return. A separate request-level writer final-return fact fences the whole native borrow and carries native/deadline-control facts. Independent endpoint control owns irreversible overdue/fault status while the writer may still be blocked; eventual publication cannot clear an already recorded fault. Failure of initial deadline setup leaves every member unsubmitted. Failure of final deadline reset faults the endpoint without rewriting member outcomes already observed. This deliberately replaces the ambiguous `buffers + one gsoSize + one result` representation. Simply appending buffers to the present request is incorrect: the native-GSO branch returns after its first buffer and the existing datagram count assumes a singleton.

The same four connection records cover `Free -> Building -> Staged -> EndpointOwned -> TerminalProcessing -> Free`. Cancellation of Building or Staged work settles it locally as unsubmitted before Free. There is one current builder. Other records may hold immutable staged, endpoint-owned or terminal work. There is no fifth overflow record, hidden per-connection worker or additional unbounded producer queue.

Bounds remain those already accepted: at most 32 members and 1 MiB backing capacity per ordinary request; the existing per-path 32-buffer producer allowance and connection-wide 4 MiB payload allowance; four retained local request records; endpoint 128 requests / 8 MiB payload, class limits and 256 completion records. Producer ownership and endpoint ownership charge the payload exactly once through transfer. All non-Free local states count toward local records. With independent endpoint routes, include Building and Staged in the existing at-most-three-records-for-one-endpoint rule so another endpoint retains a slot. Member descriptors allocate only for actual work; do not expand every idle connection into four maximum-sized packet arrays.

The connection owns preparation, staged payload, packet registrations and protocol consequences. The endpoint owns admitted payload, shared admission and service state, and terminal publication. The native writer borrows immutable admitted payload until its final return. Packet recovery registrations retain their existing independent lifetime; a late ACK, ECN or congestion reference must not retain an entire request through a new group allocation.

## Preparation and admission

Before destructive construction, secure a local request slot and bounded local payload/descriptor capacity. Check the existing recovery capacity before each packet, then register each constructed packet immediately. Registration still precedes handoff; flight, pacing, congestion and ECN decisions used by the next packet stay current. A group slot is not permission to exceed the recovery packet allowance.

Start the request deadline with its first preparation. Seal at the end of the natural emission turn, at route/tuple/epoch/class change, at the member or byte limit, at a control/probe ordering barrier, or when local resources require flushing. Preserve receive servicing. Do not wait for a target fill level, a timer or another application write. A zero-member builder is released locally without entering endpoint control.

Offer the complete request with exact backing capacity. Admission and commit form one endpoint transaction: reserve global/class/completion capacity and transfer all members, or refuse and transfer none. There is no endpoint reservation for a guessed maximum payload and no per-buffer permit expansion. Local readiness becomes a local predicate; it cannot create endpoint demand as a side effect.

On refusal the immutable request stays Staged in its existing record. Advertise only the oldest eligible staged head in each existing participant/lane, using that head's immutable sequence and exact size. Keep the existing two data/path lanes and control lane, grant lease, retry floor, circular fairness and capacity accumulation. Replacing or canceling the head withdraws its old demand before publishing a successor. A stale wake is a hint, not authorization for another identity. An unchanged refused head retries only after genuine readiness or relevant capacity change; failure must not create an immediate retry loop.

A staged request on endpoint A must not block construction or admission on endpoint B. This uses the same local records and endpoint head demands; it does not add a waiter per group. One-shot public/stateless callers already supply complete payloads and continue using the same endpoint admission owner with immediate refusal and no persistent waiter or retry.

## Endpoint exchange and writer pump

Use one bounded endpoint exchange to admit a prepared head or withdraw obsolete demand and to detach currently available terminal results for that participant. The exact private type names are implementation details; the behavioral interface is `Exchange(participant, prepared-or-withdrawal) -> admission fact + terminal facts`. No builder, recovery or external callback runs inside it. Returned results are immutable values independent of reusable endpoint record storage.

An event-triggered terminal drain takes the available result batch in one control entry. Consume the connection's shared completion wake before draining its endpoint participants, so a later concurrent publication leaves another pending wake. Permit a bounded stale coalesced observation; do not promise literally zero empty wakes. Empty observation must not generate its own progress/completion wake cycle. Polling from every capacity query disappears.

Keep one canonical synchronized endpoint owner and one independent progress/timer goroutine. The native writer fairly claims one request under that owner, unlocks, performs native deadline/write/fallback/reset operations, publishes its immutable actual-return fact, and enters the same owner to reconcile and claim its successor. Only the writer invokes the claim transition; exchanges and independent progress may reconcile, expire and signal eligible work, but must not retain the old progress function’s final claim-and-token-dispatch block. If work is eligible, continue without the mandatory writer-to-dispatcher-to-writer parking cycle. Re-run fairness, authorization, expiry and fault checks at every request boundary; never privately preclaim a chain of requests.

When there is no eligible request, check emptiness and arm the writer's parked state under the same mutex, then wait on a bounded coalesced wake. Enqueue and relevant state changes wake an armed writer. No busy loop, `Gosched`, governor change, runtime tuning or new per-connection worker is part of this design. The first request to an idle writer still incurs scheduling, which must be measured.

Publish the immutable completion before any potentially delayed control reacquisition, and notify independent progress. Thus writer descheduling does not prevent another owner entry or the timer runner from reconciling a visible timely return. The progress goroutine retains timer operations, queued expiry, overdue inspection and terminal join orchestration; a blocked writer cannot suppress them. Existing visible-timely-fact versus absent-fact-overdue semantics remain unchanged.

Native I/O, external callbacks, diagnostics sinks, writer join and grant-return callbacks remain outside control. Audit internal buffer/credit release for actual reentrancy and lock ordering. Terminal state excludes new claims and producers; waking a parked writer and joining it occur without holding control. A wake channel may close only if every send is serialized by the same terminal state; otherwise retain an open wake channel plus an independently closed terminal signal. Reusing the old token-channel shutdown without this audit is not valid.

## Native and recovery behavior

Apply each member's own GSO/ECN/OOB shape and existing bounded fallback. Check request authorization and original absolute deadline before each actual submission. Preserve accepted prefixes, uncertain attempted portions and proven-unsubmitted tails. Stop according to the existing write-error policy. A middle-member failure must not label all later unattempted members as having received that member's EMSGSIZE result.

Retain each member's existing post-native-sequence return timestamp, including its fallback sequence. Do not substitute the group's final return time for all packet eligibility times. The whole group remains borrowed until final actual return; earlier member timestamps do not authorize early buffer release. This avoids introducing a partial native-buffer reclamation protocol.

The connection applies members and packet facts in original order through the existing recovery interface. Publish a successful member's terminal receipts even if a later member fails. Apply the member's MTU hook before its packet completion, count DATAGRAM drops only for proven-unsubmitted packets, and apply member-qualified handshake/path/error consequences. ACK-before-return, duplicate completion, reset, key disposal, Retry, close and old-epoch results retain their existing token-consumption and replacement-history rules. Missing results after confirmed endpoint retirement remain uncertain.

Do not collect all outcomes and then perform one bulk loss/ECN pass. Completion updates congestion qualification, ECN, loss, callbacks and Reno undo; an earlier fact can affect the next. Registration also remains immediate because the send loop queries recovery and ECN state between packets. A future borrowed completion-vector convenience API may reuse the same ordered primitive, but is not a prerequisite or a performance claim for this replacement.

Do not add lazy alarm invalidation to this candidate. It is not automatically equivalent to eager derivation: a server can retain an alarm then cross its amplification limit through ACK-only registrations that do not request another timer calculation. Recomputing later sees a different state. Reentrant observation during OnPacketSent and externally mutable RTT state create additional snapshot questions. Existing timer derivation stays intact until a separate precise contract and evidence justify changing it.

## Revocation, expiry and close

Prepared ciphertext never changes route or generation. Route selection precedes destructive DATAGRAM extraction. This explicitly changes the old capacity-dependent steering behavior: a DATAGRAM for A can be extracted and frozen while A still refuses endpoint admission. The spare-record rule must let ordinary work on eligible B continue while that request waits or expires; naming the selected route alone does not preserve the old admission-before-extraction behavior. An invalidated unadmitted request is withdrawn and locally settled as unsubmitted under existing reliable-frame/DATAGRAM rules before any replacement construction; it is not relabeled or resent on another tuple. Endpoint-owned work uses generation-qualified cancellation and waits for terminal native facts. A claimed request remains fenced until actual return even if revoked or overdue.

The connection event loop owns the earliest Staged deadline and must service it even while hard-blocked for capacity. Expiry withdraws the exact head, settles its tokens once, releases local payload/descriptor credit and exposes a successor. The endpoint independently owns queued expiry after transfer. Admission never refreshes the first-preparation deadline; it is also no later than admission+B. Drain/close first cancels unadmitted local work, then retains existing admitted-work/close ordering and actual-return fencing.

## Explicit changes to prior choices

This proposal revises two internal decisions rather than hiding them in a refactor. First, local bounded capacity precedes construction; endpoint capacity precedes transfer. The old requirement to reserve endpoint capacity before each destructive pack is replaced. Second, the native writer may enter the canonical endpoint owner to reconcile and fairly claim work. It still cannot run connection recovery or hold control across I/O. The prior prohibition on writer control entry is replaced.

It also replaces per-buffer request/result representation and query-driven progress with typed request members and meaningful bounded exchanges. Numeric limits, request-turn fairness, public activation, wire protocols, native certainty, actual-return fencing and product performance thresholds do not change. Larger legal requests can change control latency and early-ACK timing; existing mixed/control/native qualification must detect those effects.

## Closure and finite design validation

The representation guarantee is universal within the existing private native route's supported request domain; performance evidence is example-level on the accepted Linux host/workloads. There is no new public or persisted format. Fresh endpoint/connection construction, slot reuse and resource re-grant are the reconstruction boundaries. Each following row names one precise owner/invariant and materially different failure classes; this is not a demand for an exhaustive new harness.

| Invariant / owner | Cases that distinguish behavior | Evidence |
| --- | --- | --- |
| One transfer and one terminal disposition / local record and endpoint admission | Exact-size success; refusal retaining payload; staged expiry; head replacement; reset/close before admission; endpoint A blocked while B progresses | Existing real adapter/endpoint tests extended around these local states. |
| Member truth and group borrow / native writer plus endpoint publication | Multiple GSO shapes, ordinary members and coalesced handshake packets; all accepted; middle partial/error with unattempted tail; fallback/revoke/deadline between members; delayed final return | Native fake verifies exact calls, member counts/times and no early release; retained native fence family. |
| Packet identity and ordered protocol consequences / recovery owner | Early ACK; duplicate/foreign/old-epoch completion; successful receipt before later failure; MTU hook; ECN/loss callback order; terminal missing result | Existing local completion, ECN, path/MTU and adapter families, using unchanged ordered recovery as reference. |
| One fair claim and independent expiry / synchronized endpoint | Queued successor; enqueue while parking; revoke/seal while writer runs; timely fact while writer cannot reenter; absent-fact overdue; terminal wake/join | Existing synchronization/native families plus focused pump race cases. |

Before accepting new mandatory slices, a temporary combined source experiment must execute the ordinary STREAM GSO-on path through bounded grouping, exact admission, bounded terminal drain and authorized writer continuation, retaining existing recovery effects and packet/native geometry. This is design falsification, not production implementation or certification. It may explicitly exclude unimplemented routes, but cannot skip the exercised path's registration, callback, native-result or lifetime obligations to manufacture a win. First establish multi-member success, middle failure/member mapping, refused staging expiry or revoke, and early ACK plus epoch disposal through real interfaces.

Then use one matched comparison on the existing failed workload, with the established 10-second warmup/60-second measurement, exact source/binary identities, existing host affinity and contamination/accounting rules, and a finite per-invocation timeout. Record useful goodput and CPU/byte alongside actual group sizes, transactions/results per native call, native geometry and writer gaps. Include every build, failure and observation in the existing ledger. The scoped cumulative waiver remains; no new campaign or repeated same-candidate attempts until passing are introduced. These are existing product metrics, not new thresholds or a permanent benchmark deliverable.

If intended amortization appears but the candidate remains far outside tolerance, reject the claim that this structural change is a sufficient repair. Read the residual profile before selecting at most the next discriminating representation question; do not publish a queue of guessed prerequisites. A passing experiment establishes feasibility only. Final implementation still needs the accepted semantic/race/native families, STREAM GSO-on/off comparisons and downstream R18 #1038 qualification.

## Handoff disposition and provisional decomposition

Keep N0 #1199, N1 #1200, N2 #1201 and N4 #1213 complete. Preserve N3 #1202 and its source as rework material; retain its independent progress and immutable native-fact logic where they satisfy this replacement. Replace its per-operation orchestration and single-buffer adapter assumptions. Do not merge the preserved candidate as an established baseline. The withdrawn N5 PTO cache remains withdrawn.

A possible decomposition is (A) executable typed member requests/results, complete grouped native-write behavior and a singleton production caller; (B) bounded local preparation, exact-size admission and event-driven result exchange through all actual callers/lifecycle paths; (C) reworked N3 #1202 synchronized writer pump plus integrated qualification. A must not grant a dormant second representation authority: if both old and new forms must remain, it fails the seam test and belongs with B. B must be independently correct under the existing owner and fit one fresh context; otherwise return to design rather than declaring a broad migration slice ready. C genuinely consumes B's request interface. Recovery optimization has no speculative blocking edge.

This decomposition is not an audited slice graph. No new stable identities, child issues, ready labels or OmniFocus tasks are assigned. The outstanding work is empirical feasibility and a final context/seam audit of the vertical migration. Under the architecture-handoff workflow, these must precede a dispatchable plan, default-branch publication and tracker synchronization. The current proposal stays in draft PR #1230; the existing stopped plan remains the live dispatch contract. R17 #1037 and R18 #1038 remain blocked by N3 #1202; R19 #1039 remains inactive.

The shared review-loop and contract-closure baselines, composed with [the repository overlay](../REVIEW-LOOP.md), govern any accepted replacement. This document is design/traceability metadata. Agent memos and future temporary experiment sources are diagnostic artifacts, not shipped code or new maintained verification aids. No production implementation was started for this redesign review.

## Design-review receipt

Independent endpoint, recovery and skeptical whole-pipeline reviews examined this proposal against the pinned source and frozen measurements. The review clarified protocol-sidecar ownership, packet-to-member/datagram mapping, writer-only claim authority, request-level faults versus member outcomes, settlement times for never-submitted work, and the DATAGRAM admission-order change. The selected structural candidate is coherent as a proposal; empirical feasibility and final slice context fit remain explicitly unresolved. The provisional decomposition is not an accepted dispatch graph, and this review does not certify a runtime candidate.
