## Narrowed or rejected requests

Completion-pool partitioning/enlargement (C-005/C-013) is **rejected** as a requirement: four records per connection is a cap, not a reserved entitlement for all 4,096 participants. The 256-record global admission reservation, finite per-consumer cap and fairness precondition of available completion capacity are coherent. A stronger service guarantee would be new scope. Revisit only on measured evidence that the accepted service/cost gate fails.

Automatic watchdog-policy replacement (C-020/C-021) is **deferred to the selected native qualification**, not accepted as a proved design failure. The deadline plus 20 ms bound is conditional on a responsive qualified environment, includes nonblocking local publication and excludes suspension/wedged-kernel real-time promises. Preserve irreversible quarantine, retained borrow and late-return cleanup/join. Do not silently enlarge the timeout or reopen an endpoint after a late return. Failure to qualify the declared domain blocks support and returns to a scoped design decision.

Changing immutable snapshot addresses back to pointer inputs (C-001) is **rejected**: `netip.AddrPort` values deliberately prevent aliasing; input signatures and observation representations serve different owners. Reopening key-update initiation timing (C-017) is **rejected as a defect claim** because the core already requires confirmation. The current wording is nevertheless clarified: the three-largest-PTO spacing starts at ACK confirmation of the preceding update. These dispositions do not change accepted product policy.
