# Packet-emission construction: investigation and improvement plan

Date: 2026-09-08. Source: **a5bb7f9145755a6c40482eda8cdde4c9a68b4dbf** in the-sarge/quic-go-fast. Status: investigation complete; proposed implementation has not been performed or authorized by this session. Initiating checkout was clean main at that revision. Source links below refer to the pinned investigated revision; this preserved assessment is historical evidence, not the current dispatch contract.

## Recommendation

Make a small, connection-owned initialization change: construct the packet packer in a local variable, then pass it to the existing final-binding helper, renamed `initPacketEmission`. That helper creates the initial queue and assigns the complete emission value once. Remove the queue assignment from `preSetup` and stop using `c.emission` as temporary storage during construction. Keep the recovery and path references, packet-time methods, worker startup, and test substitution behavior unchanged.

This earns its cost by removing a specific hidden requirement: today, callers must first write two fields of an object that a later helper reads while replacing that same object. It does not earn a broad new factory, dependency container, path abstraction, or recovery optimization. The selected production change fits in `connection.go`, touches two constructor sites and two setup helpers, and leaves `packet_emission.go`, `packet_packer.go`, and `send_queue.go` behavior intact.

No initialization race or emission-construction failure was demonstrated. This is a modest maintenance improvement, worth doing as a small follow-up after the concrete correctness defects from the existing audit. It does not justify delaying those defects or reopening Track E's performance campaign.

### Failure returns and what they do not prove

`StartHandshake` and the initial `handleHandshakeEvents` can return errors before worker launch. `run` then executes its context-cancellation and received-packet-drain defers; it does **not** enter the normal tail that closes crypto, drains the send queue, stops the timer and installs a closed handler. At these sites emission is complete but its queue has not run. No ordinary queued emission was identified before those returns. This is a lifecycle distinction to preserve, not evidence that a partially initialized emission escaped. In particular, adding an unconditional deferred `queue.Close` during this refactor would wait forever on an unstarted worker. A general early-error cleanup correction requires its own diagnosis and scope.

A second existing lifecycle concern is visible on the server publication-collision branch: failed `AddWithConnID` invokes `closeWithTransportError` before `go conn.run`; that close waits for context cancellation. Without an independently cancelled context this appears capable of waiting indefinitely. This was **not reproduced**, frequency/reachability under real transport scheduling was not established, and it is not caused by staged emission initialization. Do not bundle a collision-path fix into the constructor change or claim this plan fixes it.

Errors before the connection constructor (configuration/context rejection, connection-ID generation, transport setup) have no emission to tear down. Neither connection constructor nor `newSendQueue` has an ordinary error return. Panic/OOM rollback is not an existing construction contract and is not introduced here. Failure during actual packing, direct writes, queued writes or retained-close construction occurs after binding and remains governed by the existing emission/queue methods and tests.

### Observability conclusion

The partially populated emission is reachable to the constructor's own code but no production packet-emission observer of it was found. Callback storage, handler-map publication, receive enqueueing, pre-worker handshake work and worker launch were traced separately; worker launch alone was not used as the proof. This is a source-backed conclusion for the pinned implementation, not a universal proof against future reentrancy or a general concurrency certification.

## 3. Test construction and substitution census

All ordinary connection fixtures start with one of the real production constructors (`newServerTestConnection`, `connection_test.go:120`, and `newClientTestConnection`, line 179), then apply options. They do not independently build a zero-valued emission. `connectionOptSender` and `connectionOptSentPacketHandler` replace already-bound slots. Other options replace crypto/lifecycle, RTT, flow-control, tracer, unpacker or handshake facts for the scenario being tested; they are not promises that all dependent objects automatically follow those replacements.

The full `newPacketPacker` census also includes the direct packer fixture in `packet_packer_test.go:58`; connection rebuilding in `useLifecyclePacketPacker` (`connection_test.go:117`), `newEmissionTestConnection` (`connection_emission_test.go:31`) and `newHandshakeEmissionConnection` (`connection_emission_handshake_test.go:41`); and intentionally mismatched packet-number construction in `packet_packer_lifetime_test.go:60,82`. The latter is an error injection, not setup duplication to normalize away. `packet_packer_lifetime_test.go:111` and `connection_emission_close_test.go:58` also substitute `pnManager` directly. Fatal-append and close fixtures replace `cryptoSetup`. Path rebinding fixtures replace the queue and Conn path together before use.

### Recovery contracts to retain

- `schedulingRecoveryInputs` (`connection_scheduling_test.go:16–39`) controls SendMode, TimeUntilSend, loss timeout and ECN while embedding real recovery. It wraps before rebuilding the transparent packer. Number allocation, registration, ACK processing and probe storage still use the real handler.
- `emissionRecoveryOutcome` (`packet_emission_test.go:52`) and its handshake/fallback users choose mode/deadline after packer construction. `emissionECNTransition` (line 151) changes ECN based on the real packet-number progression. `emissionPTOOpportunity` (`connection_emission_handshake_test.go:158`) stops after real packet numbers advance and preserves real probe retransmission callbacks. These are necessary controlled inputs for deterministic claims, not disposable mock coupling.
- Full recovery replacement in `TestHandshakeMTUFallbackCongestionGrowth` controls ACK handling and forwards the congestion-size effect to the retained real handler; it does not claim normal outgoing packet registration. Generic full-handler options are legitimate for isolated receive/lifecycle tests but must not be reused as evidence of real emission registration.
- `mismatchedConstructionNumber` intentionally breaks Peek/Pop consistency while consuming the real packet number. Replacing it with an emission-level mock would stop exercising the constructor-failure release path.

**Selected contract:** retain the pointer to Conn's recovery field and the packer's captured packet-number manager. A fixture which substitutes emission scheduling must forward real SentPacket, Peek/Pop, QueueProbePacket and ACK behavior unless the specific test explicitly targets one of those failure seams. Do not add a production proxy to make packer numbering dynamically follow arbitrary handler swaps. Keep assertions that ACKs are accepted before socket completion, numbers advance, and registration survives failed handoff.

The accidental coupling is the implicit *order* required to achieve this setup and tests that recompose production send dispatch. The legitimate variation is transparent sealing, controlled scheduling, and precise failure injection. The selected change documents the former while preserving the latter. It does not force tests to rerun initialization, allocate a second queue or discard queued data.

## 4. Path identity is a separate contract

Client replacement proceeds in this exact order: `switchToNewPath` advances generation and updates recovery/MTU; `replacePath` writes the new Conn path through its alias; old queue Close joins/drains the worker using its captured old path; then a new queue is allocated/published with the same feedback owner; Conn starts that returned queue's worker and handles fatal errors. There is deliberately an interval when the Conn path is new and the old queue still drains. Preserve it; “join before replacement” refers to the queue, not every path reference.

Server rebinding retains queue and socket-wrapper identity and atomically changes the wrapper's destination. A queued packet uses the destination current when the worker performs its write. Direct client probes use their requested alternate transport; server probes use explicit destination/address metadata. Close output uses the current active path after ordinary worker join. These are coordinated references with different lifetimes, not evidence of three competing protocol-policy owners.

Keep `Conn.switchToNewPath`, `packetEmission.replacePath`, `rebindPath`, `Conn.prepareEmission`, generation changes and both worker launch sites byte-for-byte unchanged for the selected implementation. Removing the alias or centralizing worker launch is an independent change with no required edge to this plan. An existing native capability field or public-address-read concurrency defect, if confirmed elsewhere, also needs separate disposition; it is not solved by claiming the constructor makes all references safe.

### Intended code shape

At the existing packer/bind position in each constructor:

```go
packer := newPacketPacker(/* the same explicit arguments in the same order */)
s.initPacketEmission(packer)
```

The replacement for `bindPacketEmission` stays in `connection.go`:

```go
// initPacketEmission installs the initial emission before token setup or publication.
// Recovery, path and feedback must already exist. Call only once, before use.
func (c *Conn) initPacketEmission(packer *packetPacker) {
    queue := newSendQueue(c.conn, &c.handshakeSendFeedback)
    c.emission = packetEmission{
        packer: packer,
        recovery: &c.sentPacketHandler,
        queue: queue,
        version: c.version,
        policy: c,
        conn: &c.conn,
    }
}
```

This is illustrative design, not an applied patch. Remove only `c.emission.queue = newSendQueue(...)` from `preSetup`; keep feedback wakeup initialization there. Preserve all current packer arguments, client token-store ordering, server/client crypto differences and everything after construction. Document the deliberate live-slot versus captured-manager distinction at the binding or field declaration without changing the representation.

`initPacketEmission` is the existing connection composition helper with an explicit input, not an emission factory that receives unrestricted Conn. `packetEmission` still stores only its existing narrow policy interface and dependency fields. The result is complete initial assembly by construction convention. It is not an atomic transaction, a usable zero value, a runtime initialization guard or enforced package-level privacy. No new error return, reflection-based nil check, builder state machine or initialized boolean is needed.

## 7. Tests through the shipped entrypoint: exact prerequisite

Production dispatch is already tested: `TestEmissionResultConnection` uses `triggerSending`; `TestEmissionFullQueueResume` uses `Conn.run`; ACK allowance, ACK/full-queue pacing and PTO tests use `triggerSending`; lifecycle/scheduling/migration tests use real construction. The gap is not “emission is untested.”

**Before the setup rewrite, add or sharpen one bounded client/server constructor characterization using the real constructor-owned packer and queue.** For both perspectives, make eligible Initial work, supply server anti-amplification credit, call `triggerSending` before starting the worker, and inspect the resulting real Initial header and queued output. Assert expected source/destination IDs, version, packet-number advancement and actual recovery registration before a mock socket write. For the client include present/absent stored-token cases and check the next real Initial's token; preserve returned token RTT behavior. Exercise normal initial worker startup and joined teardown with the existing queue contract, keeping recovery assertions on the test/connection goroutine rather than racing a worker callback with recovery mutation. Existing transparent-packer fixtures cannot substitute for this constructor characterization because they rebuild the dependency we are checking.

Keep the existing `TestEmissionPTOOutput`, `TestEmissionAckAllowance`, `TestEmissionAckFullQueuePacing`, `TestEmissionECNBatchBoundary`, `TestEmissionFullQueueResume`, `TestEmissionPathReplacement`, `TestEmissionPathRebinding`, close-lifetime, handshake/key/0-RTT/Retry/version and migration tests as preservation gates. These exercise real effects of the live recovery/path bindings. The ECN test may continue to call `advance`: it checks an internal batch contract, and no internal send method changes here. A useful bounded startup characterization also confirms that an injected StartHandshake/initial-event failure returns without starting or trying to join an unstarted send worker; it must not relabel broader early-error cleanup as repaired.

The following helper migration is **independent**, not a blocking prerequisite to the chosen setup-only change:

Use a narrow forwarding recovery wrapper to select sufficient SendAny opportunities while leaving real numbering/registration intact; do not delete the second-append case or weaken expected release/ACK assertions to get green results.
