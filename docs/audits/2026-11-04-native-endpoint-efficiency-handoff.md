The recommendation below uses explicit application-call terminology rather than claiming native-send completion.

The endpoint contract explicitly permits an event loop plus native worker “or an equivalent mechanism.” The selected synchronized module keeps a single endpoint state owner, an independent progress goroutine, the same writer and the same protocol owner. Short caller-executed transactions are therefore an execution-mechanism change within the closed ownership/deadline contract. The grant registry lock currently surrounds endpoint initialization and installation of its stop callback (`native_transport.go:44–60`); terminal callback execution must remain outside endpoint control to avoid introducing its reverse lock edge. Public completion waits (`native_response.go:60–72`) and close-retirement waits (`native_endpoint.go:515–538`) must also remain outside control.

The sparse index is maintained at canonical slot construction/retirement, not cached eligibility or a new admission queue. A retiring participant remains indexed until its real retained lifetime ends. Native-result interpretation remains the existing central `reconcileCurrent` rule. Timer rearming and publication shutdown are the new concurrency families the synchronized design must own together. These decisions favor changing the state owner's core over adding side-channel mailboxes.

The separately approved issue #1141 contract and documentation PR #1194 introduce local send admission in the glossary. This handoff consumes that term and amendment after their default-branch publication; it adds no separate domain term. Endpoint write grant, local send backpressure, packet registration, transport detachment and application goodput retain their current meanings. Synchronization and an occupied-slot index are implementation mechanisms, not domain vocabulary.
