## Source and representation

The exact candidate is `78fac7ec3cd60d0dfc03c14dded71ed66c5bf0b2`, based on the unmeasured fresh-registration initialization cleanup `2dabc2cbdd5a6e6ad8eb471e3fda3d72cf5f53e1` and retained [ECN/writer source](2026-11-05-native-ecn-writer-prototype.md) `35b83b13a3b94ec3665889c0f6a0844d0f851060`. The [reviewed design](2026-11-05-native-protection-placement-design.md) keeps irreversible key policy, packet-number commitment, logging and ordered recovery registration at their existing connection-owned observation points. A concrete immutable key capability and full packet number allow the existing isolated writer to perform only AEAD and header protection.

Eligible native buffers now contain committed protection input with reserved tag space and final wire geometry. They are exclusively owned; the writer reads no live frame, preparation object, recovery sidecar or mutable key-policy owner. Generic/mock sealers, FIPS, multipath, long/coalesced headers and reusable close paths retain synchronous protection. Production key getters expose no packet-byte observer. Arbitrary private test closures capturing an exclusively owned raw buffer are outside the amended ciphertext-visibility guarantee; this limit is explicit rather than another capability interface.

A standalone per-buffer plan survives metadata retirement and early ACK. The construction owner consumes its handle before callback-capable handoff, which transfers it into a staged group; successful endpoint admission is the second ownership transfer. Refusal retains the staged plan. Changed sender/group bindings or unsupported later packets materialize the already-reserved prefix and follow existing ciphertext handoff, without double key accounting. The writer transforms a member once, clears used key references and reuses ciphertext for native retries. Local disposal preserves callback ordering; admitted disposal waits for the actual-return fence. No worker, queue, capacity, deadline, threshold or outcome relaxation is added.

## Correctness and cost evidence

Seventeen new native tests cover exact recipe geometry and byte equivalence, key reservation before writing, early ACK and metadata reuse, replaced receivers/groups, unsupported fallback observation, partial construction failure, admission refusal, cancellation, retries and actual-return ownership. Nine handshake tests cover AES-128/AES-256/ChaCha byte equivalence, an independent ChaCha vector, key policy and encryption limits, unsupported/FIPS fallback, old-generation concurrency, capability probes and layout. The ordinary handshake run skips the FIPS-only case; a separate actual local FIPS-mode run passes. No new production timing hook or per-packet diagnostic counter was added.

Root full tests pass, as do the full handshake race suite, broad native/packer/emission race suite, canonical lifetime race checks, vet and tidy-diff. The final portability tag and equivalent admission row/count refinement are covered by an additional focused race pass. Linux ordinary-cost builds and Windows/OpenBSD default compilation pass; compilation is not platform qualification. Earlier sandbox bind failures and fixture failures are preserved alongside their corrected checks.

The transform has no per-packet nonce/mask/ticket heap allocation. Real costs remain: a writer scratch allocation, lazy separate fallback scratch, an 80-byte immutable key view per generation and a plan pool operation per eligible buffer. Common packet/recovery/preparation layouts do not grow. Logical plans are 64 or 1,648 bytes, occupying 64/1,792-byte allocator classes; the common AEAD owner grows 472→504 bytes. A lazy scratch pointer keeps the native sender at 8,184 bytes within the 8,192-byte allocation class. Inline scratch would have crossed that class. Common emission stack frames grow by 152/160 bytes even though native-only initialization is guarded. Final admission reads owned rows directly and stays frameless; the earlier avoidable 136-byte row copy was removed. Moving crypto does not itself remove CPU cost.
