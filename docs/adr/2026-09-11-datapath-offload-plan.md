# Adopt platform datapath offloads through the sys-layer seam

The fork adopts three datapath improvements in order: Linux coalesced receive (UDP_GRO), a Windows datapath rebuild with segmented send (USO) and coalesced receive (URO), and macOS batch send over `sendmsg_x`. All three platforms carry equal weight; the order follows evidence-per-effort, with the receive-side seam built once on Linux and reused on Windows. The supporting discovery evidence is in [2026-09-11-keibisoft-gso-discovery](../audits/2026-09-11-keibisoft-gso-discovery.md) and [2026-09-11-quic-stack-datapath-comparison](../audits/2026-09-11-quic-stack-datapath-comparison.md).

Every change stays inside the sys-layer send/receive path. No public API is added or changed, preserving [ADR 0001](0001-upstream-compatibility.md); each slice remains an independently reviewable patch against the upstream base per [ADR 0003](0003-follow-stable-upstream-releases.md). Offloads are enabled by runtime capability probes and disabled by environment kill switches following the existing `QUIC_GO_DISABLE_GSO` convention: that switch also governs Windows segmented send, `QUIC_GO_DISABLE_GRO` governs coalesced receive on both Linux and Windows, and `QUIC_GO_DISABLE_SENDMSG_X` governs the Darwin batch send. When a probe fails the connection keeps today's behavior.

Coalesced receives are split back into individual UDP datagrams inside the sys-layer connection, before any packet parsing. `ReadPacket()` keeps its contract of returning exactly one UDP datagram per call; segment views share one backing buffer through the existing reference-counted `packetBuffer.Split()` machinery from [ADR 0005](0005-incoming-packet-lifetime.md), and each view inherits its read's ancillary data. Splitting above the sys layer was rejected because QUIC's coalescing rule consumes the remainder of a datagram after a short-header packet, so an unsplit super-buffer silently swallows every following segment; per-segment copy-out was rejected because it reintroduces the copy the offload exists to remove. Coalescing-enabled reads use a dedicated 65535-byte buffer tier allocated only when the probe succeeds, because the 20 KiB large-buffer tier truncates coalesced reads and datagram truncation silently loses data, while growing the shared tier would tax every connection that never coalesces.

The Windows work lands as three separately revertable slices. First a dedicated Windows connection implements the existing raw-connection interface over `WSARecvMsg`/`WSASendMsg` from `golang.org/x/sys/windows` with behavior otherwise unchanged, replacing the plain read/write connection; the shared seam with Linux is the platform-neutral split helper and the capability flags, not the Linux connection type, because `golang.org/x/net` provides no Windows control-message support. Second, segmented send probes `UDP_SEND_MSG_SIZE` and reuses the existing platform-neutral segmented-send logic through the capability flag. Third, coalesced receive probes `UDP_RECV_MAX_COALESCED_SIZE` and feeds `UDP_COALESCED_INFO` segment sizes to the split helper. Windows version sniffing was rejected in favor of probes; msquic documents a Windows Server 2022 defect when segmented send and coalesced receive combine, and the kill switches are the operator mitigation if it reproduces.

The macOS slice ports only the send half of KeibiSoft/quic-go commit `24ecf34c` (MIT, with attribution): batch submission over the private `sendmsg_x` syscall with v4-mapped destinations for dual-stack sockets, partial-acceptance resend, preserved message-size-error handling for MTU discovery, and per-packet fallback on any error. The build constraint is `darwin && !ios`, because `ios` implies `darwin` in build constraints and private syscalls in iOS builds are an App Store rejection risk; a compile-time opt-out tag serves Mac App Store distributors, since review flags private-syscall symbols even when unreachable at runtime. The port adds the ABI struct-layout tests and loopback coverage the source commit claims but does not ship. The `recvmsg_x` receive half is deferred to a separate experiment: as committed upstream it can never batch, and raising the Darwin batch size is its own decision. No production QUIC stack batches UDP on macOS, so this slice carries the program's highest risk and lands last with no precedent to lean on.

Each slice is adopted only with a protocol and results pair under `docs/audits` demonstrating syscall reduction and loopback throughput on the target platform and no regression with the offload unavailable or disabled. Kernel-bypass and ring datapaths (io_uring, XDP) are outside this plan: even msquic ships them off by default or platform-locked, and they do not fit a Go library's portability contract.
