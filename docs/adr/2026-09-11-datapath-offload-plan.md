# Adopt platform datapath offloads through the sys-layer seam

The fork adopts three datapath improvements in order: Linux coalesced receive (UDP_GRO), a Windows datapath rebuild with segmented send (USO) and coalesced receive (URO), and macOS batch send over `sendmsg_x`. All three platforms carry equal weight; the order follows evidence-per-effort: Linux coalesced receive has the fewest unresolved feasibility questions and the cheapest evidence path because the batch receive machinery and offload-capable CI already exist there; the Windows foundation is bounded work on standard-library message I/O but segmented send and coalesced receive queue behind it; and macOS batch send carries private-ABI qualification cost that produces no seam any other slice reuses. The supporting discovery evidence is in [2026-09-11-keibisoft-gso-discovery](../audits/2026-09-11-keibisoft-gso-discovery.md), [2026-09-11-quic-stack-datapath-comparison](../audits/2026-09-11-quic-stack-datapath-comparison.md), and the consideration synthesis for this plan.

No public API is added or changed, preserving [ADR 0001](0001-upstream-compatibility.md). Offloads are enabled by runtime capability probes and disabled by environment kill switches following the existing `QUIC_GO_DISABLE_GSO` convention: that switch also governs Windows segmented send, `QUIC_GO_DISABLE_GRO` governs coalesced receive on both Linux and Windows, and `QUIC_GO_DISABLE_SENDMSG_X` governs the Darwin batch send. When a probe fails the connection keeps today's behavior. Receive coalescing is a socket-wide option, so it is enabled only on sockets the transport creates and owns; a caller-supplied socket never has coalescing enabled without an explicit future opt-in, so reads the caller performs after transport close cannot receive silently truncated coalesced payloads — the buffer-semantics obligation ADR 0001 prohibits.

Coalesced receives are split back into individual UDP datagrams before any packet parsing, and `ReadPacket()` keeps its contract of returning exactly one UDP datagram per call, each segment parsed as a distinct datagram under QUIC's rule that a short-header packet consumes its datagram's remainder. Splitting above that seam was rejected because an unsplit super-buffer silently swallows every segment after the first short-header packet; per-segment copy-out as the default was rejected because it reintroduces the copy the offload removes. The shared backing storage is not the existing `packetBuffer` reference count, which does not support concurrent use: sibling segments from one read can carry different connection IDs and route to different connections, Initial handling, stateless-reset, overflow, and shutdown paths that release concurrently. The slice therefore extends the [ADR 0005](0005-incoming-packet-lifetime.md) machinery with an atomically reference-counted slab for coalesced storage, audits every terminal release path for exactly-once release under the race detector, and bounds slab lifetime to the routing-and-processing pass: any segment that enters a count-bounded retention queue — undecryptable, unprocessed, or otherwise held past that pass — is copied into the standard buffer tier when it fits, whether it arrived alone or as one segment of a multi-segment slab, because a lone retained segment otherwise pins its entire slab after every sibling is released. This storage contract touches the buffer pool as well as the sys layer, and the plan says so rather than claiming a sys-layer-only diff.

Coalescing-enabled reads use a dedicated third 65535-byte pool tier — the buffer pool currently accepts only its two existing capacities and must gain this tier explicitly, with slabs returned to that pool on final release and never retained by the standard tiers — because the 20 KiB large-buffer tier truncates coalesced reads and datagram truncation silently loses data, while growing the shared tier would tax every connection that never coalesces. The allocation shapes are fixed here, not delegated: Linux keeps its batch of eight preposted reads, so a coalescing socket preposts 8 × 64 KiB ≈ 512 KiB against 8 × 1452 bytes today; Windows coalesced receive preposts one 64 KiB buffer per read, since its message call delivers a single coalesced buffer. The queue-copy rule above bounds retention: without it, the 32-undecryptable plus 256-unprocessed per-connection queue limits could pin about 288 × 64 KiB ≈ 18 MiB of slabs per connection, and with it those queues hold standard-tier copies while slab occupancy is bounded by the preposted count plus segments still in the routing-and-processing pass. Each slice's protocol declares per-socket and per-process memory budgets and measures third-tier pool misses, allocation counts, GC churn, queued bytes, post-close retention, and resident-set size against them.

The Windows work lands as three slices with an explicit dependency and revert graph: segmented send depends on the foundation; coalesced receive depends on the foundation and the shared coalesced-storage contract; reverts run in reverse order without leaving an invalid intermediate state. Each slice remains independently reviewable against its named parent, which is how this plan reads [ADR 0003](0003-follow-stable-upstream-releases.md)'s reviewability requirement for dependent patches. The foundation replaces the plain read/write connection with the standard library's `net.UDPConn.ReadMsgUDP` and `WriteMsgUDP`, which already execute `WSARecvMsg` and `WSASendMsg` through the runtime's IOCP poller with standard deadline, cancellation, and close semantics; the slice adds only Windows control-message encoding and parsing. A direct `x/sys/windows` overlapped path was rejected: it would block OS threads or duplicate inaccessible runtime completion machinery, and `golang.org/x/net` offers no Windows control-message support. The foundation's gate is correctness and noninferiority — deadline, close, and concurrent-close behavior plus no throughput regression — not syscall reduction, which a behavior-preserving rebuild cannot show; segmented send and coalesced receive carry the performance gates. Segmented send probes `UDP_SEND_MSG_SIZE` and reuses the existing platform-neutral segmented-send logic through the capability flag; coalesced receive probes `UDP_RECV_MAX_COALESCED_SIZE` and feeds `UDP_COALESCED_INFO` segment sizes to the split seam. The pinned msquic report for Windows Server 2022 restricts TTL and DSCP ancillary receive features while these offloads are enabled — it does not establish general packet corruption — so affected ancillary features stay disabled while offloads are active unless functionally qualified per platform, and kill switches remain recovery controls, never qualification evidence.

The macOS slice ports the send half of KeibiSoft/quic-go commit `24ecf34c` (MIT, with attribution): batch submission over the private `sendmsg_x` syscall with v4-mapped destinations for dual-stack sockets and preserved message-size-error handling for MTU discovery. Batching necessarily modifies the send queue's error attribution, so the slice touches `send_queue.go` and `send_conn.go` under [ADR 0004](0004-packet-emission-ownership.md) ownership and defines partial acceptance precisely: accepted entries are never resent; the first unaccepted entry is retried through the existing per-packet path so message-size errors and handshake MTU feedback attach to the correct entry; the remaining tail is sent without loss or duplication. The build constraint is `darwin && !ios`, because `ios` implies `darwin` in build constraints, with a named opt-out tag `quic_go_no_private_syscalls` selecting a fallback stub for distributors whose policies exclude private-syscall use; the risk is dependence on a private raw syscall number and ABI, not a scannable symbol, since a raw syscall imports none. Qualification fails closed: functional loopback qualification on each supported macOS version and architecture with a recorded tested version floor (a tested ceiling proves nothing about future releases), accepted-count bounds checks, the capability latched off for the process after `ENOSYS` or structurally invalid results, and observable engaged/fallback counters. The port adds the ABI struct-layout tests and loopback coverage the source commit claims but does not ship. No production QUIC stack batches UDP on macOS, so this slice lands after the receive-side slices with no precedent to lean on.

macOS receive batching over `recvmsg_x` is a fourth slice, run as a bounded experiment with its own adoption gate rather than folded into the send port. The KeibiSoft receive code has never batched in practice — its commit leaves the Darwin batch size at one, so a port would be new development, and enabling it requires raising the Darwin batch size, a separate decision that multiplies per-connection receive-buffer memory and changes shared receive-path behavior. An inconclusive outcome retires the slice without touching the adopted send half, which is why the two halves do not share a gate.

Each slice is adopted only through a protocol and results pair under `docs/audits`, with the protocol committed before measurement. Every protocol fixes the base and candidate commits, the qualified host, OS build, architecture, and Go toolchain, the syscall-counting method, the bulk-transfer workload using 1071-byte application records (the externally owned application sweep stays out of scope), warmup and repetition counts, the statistical analysis method with confidence bounds, a predeclared minimum useful effect for the primary metric and predeclared resource and noninferiority bounds for the others, an explicit pass, fail, or inconclusive disposition rule mechanically derivable from those bounds, an engagement metric such as coalesced segments per read or packets per batch submission so a silently unengaged offload cannot pass, and measurements for the engaged, available-but-unexercised, disabled, and unavailable configurations where they apply. Each slice also carries its own correctness gate alongside the performance gate: Linux coalesced receive requires the mixed-connection-ID, short-header-remainder, and rejected-sibling split tests to pass under the race detector, with the peer's segmentation-offload state fixed and reported and the distribution of coalesced segments per read and receive syscalls per delivered datagram published; Windows segmented send and coalesced receive require payload and ancillary-metadata validation (coalesced-info, destination packet info, and ECN separately) across the offload on/off matrix; Darwin batch send requires the partial-acceptance and error-attribution suite and the functional syscall qualification described above. Kernel-bypass and ring datapaths (io_uring, XDP) are outside this plan: even msquic ships them off by default or platform-locked, and they do not fit a Go library's portability contract.
