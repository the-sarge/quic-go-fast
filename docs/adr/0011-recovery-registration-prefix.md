# Order Reno recovery by registration prefixes

Default Reno must compare transmissions across Initial, Handshake and application packet-number spaces without comparing their raw numbers. Following the [accepted #961 brief](https://github.com/the-sarge/quic-go-fast/issues/961#issuecomment-6331591220), use typed space-qualified identities and constant-sized complete registration prefixes. 0-RTT and 1-RTT share application identity. A registered identity is after a prefix when its space is absent or its number is strictly greater than that space's prefix maximum; equality remains in the old prefix. Existing recovery ACK/ECN validation admits identities, including a CE anchor whose live packet record has retired.

Every registration supplies facts. Only ACK-eliciting non-path sends advance the eligible frontier, with MTU sends included. Each eligible send copies the complete registration prefix, including earlier excluded registrations in other spaces. The controller freezes that frontier only on an accepted congestion event; suppressed events do not move it. Excluded registrations trailing the frontier classify as after it, even if registered before processing the congestion event. Freezing all registrations at cutback time would be a different policy. Recovery ACK eligibility and no-prior-ACK reporting are preserved, and an old ACK cannot reactivate recovery after exit. HybridSlowStart separately owns its receive-round prefix and RTT samples.

The typed private callbacks convert together. Registration, model decisions and feedback stay on the connection goroutine before socket-worker I/O, preserving [ADR 0004](0004-packet-emission-ownership.md). Path-registration facts do not charge pacing or flight. Wire numbering, history ownership, pooling, skip validation, per-space loss distance, coalesced reservation, Retry and disposal contracts remain as before. No per-packet ordering field, retained mapping ledger or sampler-retention dependency is added. BBR keeps its ordinal and rich-event accounting; only its inert compatibility callback signatures change.

This narrow default-Reno correctness correction supersedes the literal “Reno unchanged” restriction in [ADR 0009](0009-opt-in-bbrv3.md) and its design D04, retaining Reno selection, parameters and opt-in BBR metadata. It preserves [ADR 0001](0001-upstream-compatibility.md)'s public, wire and ownership contracts and does not reopen [ADR 0003](0003-follow-stable-upstream-releases.md)'s upstream-selection policy. The shared Cubic sender and HybridSlowStart use the same ordering correction. [The implementation contract](../agents/recovery-send-order-961.md) owns finite acceptance evidence; The separately accepted [#972 undo](0012-reno-spurious-loss-undo.md) uses this single controller-owned boundary.

A shared generator/history rewrite was rejected because it changes numbering, reservation and disposal contracts beyond this correction; revisit only if a future accepted contract widens those boundaries. A mandatory ordinal or retained map was rejected because it adds packet or retention obligations avoided by snapshots; revisit only if admitted ordering requirements cannot be represented by prefixes. A split conversion was rejected on merit because mixed raw/typed ordering cannot ship safely. This choice adds only synchronous prefix bookkeeping and constant sender state, without a new execution-context handoff. Final layout is recorded with the implementation evidence; throughput and total connection memory are not inferred from it. Initial construction still allocates Reno even when BBR is selected. Frozen prototype captures remain historical evidence.

Measured production layout on Go 1.27.3 darwin/arm64 is packet 80 → 80 bytes and Reno sender 208 → 328 bytes (+120 constant bytes), including embedded HybridSlowStart 40 → 88 bytes (+48 already included). The frozen prototype measured packet 80 → 80, sender 208 → 352 and embedded slow start 40 → 112 (+144 total). Production removes its compatibility scaffolding. This is a layout observation, not an allocator, CPU, throughput or total-connection-memory measurement.

[ADR 0012](0012-reno-spurious-loss-undo.md) records the separately accepted #972 undo behavior and its additional constant sender cost. It reuses this prefix policy and preserves HybridSlowStart's independent round ownership.
