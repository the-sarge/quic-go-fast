# Undo the latest fully spurious Reno cutback

The owner accepted [#972](https://github.com/the-sarge/quic-go-fast/issues/972) and its one-PR implementation plan after the independent [history correction](../agents/spurious-loss-history-970.md) and [typed registration-prefix correction](0011-recovery-registration-prefix.md) landed. Default Reno restores the latest cutback's saved congestion window, slow-start threshold, additive-increase credit and appropriate prior boundary only when surviving admitted receipts resolve every supporting loss. A saved prior prefix is a snapshot; the controller's current cutback remains the sole active boundary. Eligible ACK progress against the snapshot prevents restoration from reactivating an already exited recovery period.

Count real supporting losses even when another cut is suppressed. Missing, evicted, expired or disposed receipts cannot complete undo; a genuine Initial/Handshake loss has no application receipt that can discharge it. Validated CE invalidates the candidate even when its own cut is suppressed. Process current-ACK CE and real losses before spurious receipts; a newer cutback supersedes the old candidate. Retain the candidate after recovery exit, but discard it without restoring state if the congestion window has already grown above the saved value. Undo preserves historical loss statistics and never repeats flight subtraction or frame callbacks.

The handler owns validated, once-only, unexpired receipt delivery and lifecycle invalidation. Preserve the 64-record legacy history and strict three-PTO send-age bound; diagnostics still consume matching records before cleanup, while undo admission checks age before using them. Retry and rejected 0-RTT clear disposed legacy history, key discard invalidates pending undo, and migration retains its existing fresh-sender and history reset. BBR's compatibility callbacks are inert: its independent ordinal, episode, CE/ProbeRTT and persistent-congestion evidence and reset owners retain their contracts and bounds.

This separately accepted default-Reno change narrowly amends [ADR 0009](0009-opt-in-bbrv3.md) and design D04 beyond ADR 0011's ordering correction. Preserve default selection and Reno parameters, [ADR 0001](0001-upstream-compatibility.md)'s public/wire contracts, [ADR 0003](0003-follow-stable-upstream-releases.md)'s adoption policy and [ADR 0004](0004-packet-emission-ownership.md)'s registration and I/O ownership. Adaptive thresholds remain separate work. The [execution contract](../agents/reno-undo-972.md) owns finite acceptance evidence; frozen assessments and prototypes remain historical evidence.

An inline controller snapshot and unresolved-loss count add only synchronous, constant-sized sender state. A BBR-store dependency or per-packet reconstruction ledger was rejected because it adds retention and cross-owner consistency obligations; revisit only under a separately approved evidence-ownership redesign. Importing upstream's shared numbering/history rewrite was rejected because it changes accepted transport contracts; revisit only if those contracts are explicitly reopened. Splitting callbacks and restoration into separate product PRs was rejected on merit because no useful intermediate behavior requires it.

Measured on Go 1.27.3 darwin/arm64, packet layout remains 80 bytes; Reno sender layout changes from 328 to 400 bytes (+72 constant bytes), including unchanged embedded HybridSlowStart at 88 bytes. Initial Reno construction occurs even when BBR is subsequently selected. These structure sizes imply no allocator, total-memory, CPU or throughput improvement.
