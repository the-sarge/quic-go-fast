# Server path validation retries — implementation plan

**Status:** approved by the maintainer in this chat. **Issue:** [#963](https://github.com/the-sarge/quic-go-fast/issues/963). **Shape:** one cohesive product PR, then the required administrative journal PR. **Source contract:** [agent brief](https://github.com/the-sarge/quic-go-fast/issues/963#issuecomment-6330988101). The brief owns the complete timing, staged validation, emission, response and cleanup behavior; the acceptance criteria below are copied verbatim.

## Outcome and boundary

Recover the three confirmed acknowledged-challenge stalls and retain candidates across individual probe losses, with bounded outstanding tokens and absolute stage expiry. Preserve per-path byte allowance, replay rejection, buffer/recovery ownership, public API, existing migration eligibility, connection-ID ownership, path generation, congestion/recovery reset and MTU/DATAGRAM-limit reset. Change server candidate state, private probe emission/packing, response handling and connection timer integration only, with associated tests and glossary updates. No client-probe redesign, public configuration, timer-driven challenge sends, generic path framework, CI redesign, platform expansion or performance campaign is included.

## Implementation and design cost

1. Express retry/loss/reordering regressions at the approved path-manager, concrete emission/recovery and connection receive seams. Preserve the triage reproduction as frozen baseline evidence; new successful responses arrive before expiry.
2. Keep protocol state in the connection goroutine. Snapshot the conservative PTO base and five-second-minimum stage timeout at admission; retain at most 16 committed challenge records among at most three candidates. Stage progress is monotonic; duplicate/expired/unsent tokens cannot renew an attempt. Commit token metadata and backoff only after concrete byte reservation, before recovery registration and synchronous socket handoff. Preserve peer-response priority and local-error reservations.
3. Add the earliest incomplete-attempt expiry to the existing connection timer and process expiry on loop progress and before response matching. Policy uses current monotonic processing time; existing receive timestamps retain their recovery role. Preserve normal successful-candidate idle eviction, path-switch cleanup and terminal connection-ID ownership. Complete the real-loop and UDP/TLS composition tests before review.

No worker, channel, lock, mirrored policy or cross-thread feedback is introduced. The state owner's synchronous design is preferred over per-path workers or completion notifications: those add stale/late/shutdown delivery obligations without an accepted benefit (rejected on merit; revisit trigger: none). The existing private emission boundary remains the sole construction/registration/buffer owner. Material effects are bounded candidate storage, repeated probe traffic, timer wakeups and cleanup order; these are confined to the server candidate lifecycle. The packer may reorder frame slices, so control frames must be selected by type. The native test filter is fixture-local and may use existing trace metadata; invasive production test hooks require a plan revision.

## Representation and artifacts

Supported inputs are authenticated, parsed server 1-RTT packets after the existing duplicate/replay gate, internal candidate state, concrete send outcomes and connection-loop time/terminal events. Existing QUIC parsers are authoritative; there is no new grammar scanner. Behavioral requirements apply universally within that declared internal domain; finite regression evidence is not a formal completeness proof. Material safety consequences exist, but the named owners and finite transitions are reasonably covered by focused tests, so a separate contract-closure campaign is not triggered.

Runtime retry/migration behavior is shipped behavior. Byte-budget, token-validity, capacity and expiry guards are required safety enforcement. The named regression tests are maintained verification deliverables approved with the plan: payoff is preventing recurrence at the affected owners, supported domain is the declared server lifecycle and the controlled NAT scenario, owner is the transport test suite, retirement occurs when equivalent coverage replaces them or the behavior is removed. Frozen triage artifacts are historical verification aids, not a new blocking harness. This plan, certification receipts, review dispositions and journal entries are process metadata. Do not recursively validate verification aids as product parsers or expand their domain.

## Acceptance criteria

- [ ] All three reproduced stall cases recover using a response to a retry before stage expiry, with the existing real packer and recovery handler. The archived 61-second positive control is baseline evidence; the new implementation must reject an abandoned attempt's response instead.
- [ ] Deterministic timing tests establish before/exact retry boundaries, actual-send-based doubling, no catch-up burst, absolute expiry, slower-path timing, no unsolicited timer retry and overflow-safe bounded behavior.
- [ ] Earlier/latest token responses work on candidate or active paths; compact/padded ordering and duplicates cannot grant the wrong validation, downgrade success or renew a lifetime. Unsent/expired/previous-attempt tokens are ignored.
- [ ] One challenge loss leaves the candidate eligible for a later retry without connection-ID churn; ACKs alone never validate it.
- [ ] Real-emission tests preserve independent per-path budgets, replay rejection, compact/expanded sizes, no-send deferral, peer-response priority, conservative local-write reservations and buffer cleanup.
- [ ] Candidate and token caps are enforced. Existing-candidate activity works at capacity; cap exhaustion waits for expiry; a new attempt after expiry has a fresh identity. Success, switch and close release the appropriate tokens/resources.
- [ ] A real connection-loop test using virtual time proves expiry under silence and send blocking. Continuous traffic, ACKs and duplicate responses do not extend a deadline.
- [ ] A controlled UDP/TLS NAT-rebinding test withholds the first response, requires a later challenge, then proves validation, migration and continued application delivery. Existing amplification, migration and MTU regressions remain green.
- [ ] Focused unit/connection tests, focused race coverage, the controlled integration case and repository-required checks pass on the resulting implementation revision.

## Terminating evidence and review contract

| Family | Evidence and ceiling |
| --- | --- |
| Retry/timing | Three real-packer/recovery stalls; before/exact deadlines; delayed triggers without bursts; snapshot timing, slower paths and overflow-safe arithmetic. |
| Response validity | Earlier/latest tokens and both receive paths; compact/padded reordering and duplicates; unsent, expired and previous-attempt rejection. |
| Emission | Independent budgets/replay rejection, actual padding metadata, no-send deferral, response priority including expiry during packing, local-write reservations and buffer cleanup. |
| Lifetime/capacity | Three-candidate/sixteen-token bounds, existing-candidate activity, successful idle eviction, renewed admission, loss retention, switch/close cleanup and timer expiry during silence or blocked sending. |
| Native composition | One controlled UDP/TLS NAT-rebinding case withholding the first actual response, requiring a later challenge on the same candidate and complete application delivery; retained NAT cleanup and MTU regressions. |
