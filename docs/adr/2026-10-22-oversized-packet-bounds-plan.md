# Reject oversized packets before serialization — implementation plan

**Status:** approved by the maintainer in this chat. **Issue:** [#960](https://github.com/the-sarge/quic-go-fast/issues/960). **Shape:** one product PR, followed by the administrative journal PR. **Source contract:** [completed agent brief](https://github.com/the-sarge/quic-go-fast/issues/960#issuecomment-6330374473). The acceptance criteria below are copied verbatim. Adapt upstream quic-go/quic-go#5937 without importing its packet-number API.

## Outcome and boundary

Reject a nonempty construction whose complete calculated serialized size, including protection overhead, exceeds its caller's packetization budget, before acquiring output storage or serializing any component. The close and ordinary coalesced checks own the aggregate UDP datagram; the PTO check owns Initial and Handshake probes. Return no packet and a descriptive error with actual and allowed sizes. Equal-sized constructions succeed with existing padding.

Production scope is packet_packer.go and strictly necessary cleanup within its existing owner. Preserve successful serialization/packet-number ordering, registration before handoff, queued frame ownership, close conversion/cause/outcome policy, existing constructor-error cleanup and retained-close lifetime. Preserve explicit InitialPacketSize floors, unset-only MTU fallback, its two triggers and phase/path guards. ADRs 0001, 0003 and 0004 apply. Public APIs, wire formats, recovery/PTO ownership, token/reason truncation, fallback additions, receive parsing, DATAGRAM admission, socket-error classification, upstream synchronization, handshake-write redesign, new dependencies and historical evidence changes are out of scope.

## Implementation and design cost

Use TDD at the approved concrete packer/emission seams: ordinary coalesced output, pre-confirmation ACK-only output, Initial PTO and transport/application close. Keep native Initial protection where available. Add the three size guards immediately before getPacketBuffer in packConnectionClose, PackCoalescedPacket and long-header PackPTOProbePacket, retaining the 1-RTT branch and existing length/padding helpers. Existing emission callers already propagate packing errors before registration, handoff and retained-close storage; no production emission change is expected.

The change adds synchronous arithmetic comparisons in the existing construction owner, with no new handoffs, mirrored state, concurrency mechanisms or external contracts. Late serialization checks and caller-side checks are rejected on merit because they cannot enforce the required construction boundary (revisit trigger: none). A broad upstream ownership or handshake rewrite is outside scope; revisit only under a separately approved ownership/policy change. Trace selected-frame lifetimes on each new rejection exit; cleanup must remain owner-local with a failing regression. If safe rejection needs broader ownership or protocol changes, stop for a revised decision.

## Representation and artifacts

The supported domain is nonempty output selected through these typed packet constructors, using supported encryption levels/versions, valid internal frames and the existing caller packetization budgets. Inputs include peer-supplied address-validation tokens and local close reasons. Existing wire length helpers, frame lengths and sealer Overhead own the serialized representation. Bounds apply universally inside this domain; finite tests are regression evidence, not a protocol completeness proof. Material lifetime consequences exist, but the finite paths and ownership states fit focused tests, so a separate contract-closure campaign is not triggered.

Returned rejection behavior is shipped behavior; size guards are required safety enforcement. The named regressions are maintained verification deliverables approved with the plan: payoff is preventing recurrence of oversize output, panic and ownership failures; domain is the constructor/emission cases below; owner is the root transport test suite; retire only when equivalent coverage replaces them or the behavior is removed. Existing fixtures remain verification aids, with no new general harness. This plan, review records, certification receipts and journal are process metadata. No recursive harness completeness obligation is accepted.

## Acceptance criteria

- [ ] Oversized tokens produce an error and no packet in all three construction paths, without panic, output-buffer allocation, serialization or packet-number consumption for the rejected construction. Include both a size above the selected packet budget but within the backing-buffer ceiling and a size above that ceiling.
- [ ] Oversized transport-close reasons and excessive aggregate close size are rejected, including a coalesced case whose individual components fit. Exercise the shared application-close route and retain its existing encryption-level/error-conversion rules.
- [ ] Calculated sizes immediately below, equal to and immediately above the limit demonstrate the boundary. Below/equal cases retain expected padding and decodable output; above-limit cases fail. Preserve Handshake PTO, 1-RTT and normal multi-level coalesced success behavior with relevant existing coverage.
- [ ] Tests enter through the real packer/emission seam and demonstrate rejection propagation, no registration or queue/socket handoff for rejected output, and no retained close payload. Use native Initial protection where already available; do not replace the concrete packer with a mock.
- [ ] Ownership regressions show that rejection leaves no live output buffer and causes no leaked or reused acquired pooled frame/storage or duplicate callback. Retain existing constructor-error cleanup and successful retained-close lifetime coverage. Resolve any needed cleanup within the current owner; do not introduce transactional rollback or a new frame/recovery owner.
- [ ] Successful packet-number consumption, registration-before-handoff and close handling retain their existing ordering. Size rejection does not lower an explicit floor or add a fallback trigger; relevant existing handshake-fallback coverage remains green.
- [ ] Run the focused new regressions and relevant existing packer/emission/lifetime tests on the final candidate, with affected-package race validation and the repository's applicable checks. Record exact base/head and results; expand validation only for a changed candidate, failure or concrete unresolved concern.

## Terminating evidence and review contract

| Semantic class | Expected behavior and evidence |
| --- | --- |
| Oversized Initial token | Ordinary, ACK-only, empty-PING PTO and close reject at sizes above the 1200-byte budget both within and beyond the 1452-byte backing-buffer ceiling; no panic, construction buffer, serialization, packet-number consumption, registration or output. |
| Close payload and aggregate | Transport reason, application-close shared route and multi-level aggregate overflow reject before any component is serialized; no retained bytes or socket write. Preserve application-error conversion/suppression. |
| Boundary success/failure | Independently specified serialized sizes 1199/1200/1201 for ordinary, ACK-only, Initial PTO and transport-close reason; below/equal output is padded to 1200 and decodes, above rejects. |
| Ownership and recovery | Pending application frames remain owned when an oversized Initial prevents selection; rejection acquires no output storage and produces no duplicate callback. Pending PTO recovery retirement remains effective. Retain constructor-error cleanup and successful retained-close tests. |
