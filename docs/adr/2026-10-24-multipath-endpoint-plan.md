## Goal and current shape

Make an explicitly granted native endpoint own its complete asynchronous send lifetime behind one boundary. This supplies local ownership completion for ordinary and later multipath traffic while leaving unregistered I/O intact.

Verified source seams: `send_queue.go:149` transfers buffers, `:170` currently borrows probes synchronously and `:188` returns worker errors; `send_conn.go:92` and `:116` own authorization/fallback; `packet_emission.go:546` commits probes; `transport.go:533`, `:540` and `:580` own public writes, replies and Close. `internal/utils/log.go` can synchronously invoke a sink. These are distinct producers of one endpoint authority, not independent cancellation mechanisms.

## Endpoint ownership contract

The first support domain is an exact, unconnected `*net.UDPConn` on a qualified OS/Go combination. Merely implementing `net.PacketConn`, exposing `SyscallConn`, embedding a UDP socket or forwarding through a managed lease is insufficient. Reject custom wrappers, registered external callbacks and managed packet-I/O registrations for multipath in this milestone, even when a callback usually forwards to a native helper. Do not unwrap them or bypass their policy. Linux is the first required interop/qualification target; macOS and Windows become supported only after the same semantic cases pass in their native venues. Other platforms remain ordinary-QUIC-only until qualified. Only Linux amd64 on the selected Go/kernel venue is initially supported after qualification; other platforms require a separately accepted future scope.

Use additive `Transport.ConfigureMultipathIOV1(maxWriteDuration time.Duration) error` before initialization. It binds to the exact current `Transport.Conn`, validates a finite positive budget B and grants exclusive write/deadline coordination until the observable transport-wide join below. It does not transfer socket-close ownership or change read deadlines. The caller must stop direct writes, duplicate-descriptor writers and external `SetDeadline`/`SetWriteDeadline` calls during the grant; sharing the endpoint means sharing this one Transport. Initialization may clear the prior write deadline under the grant, without promising to restore a value Go cannot query. Replacing `Conn`, late registration, duplicate ownership or unsupported socket/configuration fails locally before multipath advertisement or path attachment. Exact-pointer ownership is checked; undisclosed duplicate descriptors and direct caller interference remain explicit contract violations.

An opted-in endpoint uses this writer for all traffic, including ordinary peers, QUIC v2 and public non-QUIC writes; only wire negotiation is per connection. Unregistered transports retain their existing I/O behavior. The owner has selected **local queue and write timeouts as backpressure, not path failure**. Neither ordinary nor multipath peers may enter the existing fatal send-error path solely because a local deadline expired. Sustained lack of peer progress can still trigger ordinary handshake, idle or validation deadlines; local timeout events do not themselves advance a path-failure counter or fabricate network loss evidence.

One endpoint coordinator owns all native submissions and socket write deadlines. Go deadlines affect pending and future writes on that socket ([PacketConn contract](https://pkg.go.dev/net#PacketConn)); path workers never set them independently. The coordinator contains a control path that continues processing timers, admission, revocation and completion independently of the one potentially blocked native writer. It can be an event loop plus native worker or an equivalent mechanism, but neither native writes/deadline calls nor diagnostics/application callbacks may block the control path. First-profile server paths all use the original endpoint, so socket backpressure affects their shared capacity. Distinct client endpoints can progress independently.

#### Request lifetime, expiry and diagnostics

Each admitted request captures endpoint/connection/path/tuple generations, its payload owner, protocol-registration reference, one reserved completion record and an absolute deadline no later than admission+B. Queue wait, native calls and every GSO/batch fallback or retry share that deadline; partial progress never extends it. Completion for this bound means the native borrow has ended, local queue/buffer ownership has been resolved and the terminal result has been published. Connection-owned recovery processing can follow asynchronously in its bounded completion mailbox; it is not required for the endpoint fence to progress. Completion capacity is reserved before admission, so a stalled consumer cannot require blocking publication or unbounded result allocation.

The control path serializes transitions `queued → claimed/current → completed` and `queued → completed-unsubmitted`. The claim installs the current token before work leaves the queued owner, including deadline setup before the first syscall. Exactly one transition wins against expiry or revocation. Only a still-queued entry may be removed and reclaimed by the expirer/revoker. Claimed entries remain part of the current-request fence; their memory is not reclaimed until the writer acknowledges that no native operation can still reference it. The worker checks token permission and remaining time before every actual submission. A completion racing connection/path teardown remains generation-qualified and cannot update a replacement owner.

An independently serviced timer completes expired queued requests even while another request is in native I/O. Revocation uses that same control path and does not wait its turn behind unrelated queue service. For the A1/A2/C1 counterexample, A1 may occupy the writer until B and then C1 until 1.5B; A2, admitted at epsilon, must still complete unsubmitted at B+epsilon plus qualified control overhead. Once an entry has been claimed, expiry marks cancellation and waits for native acknowledgment rather than pretending the entry was queued. No unrelated queued work can extend a retiring generation's native fence.

Before dispatch the native writer installs only the current request's deadline, and retains its token until native return and completion handoff. Successfully clear/replace an expired deadline before another request is dispatched. Stale cancellation/completion cannot change a successor's deadline. Cancellation may shorten a matching current request's deadline only if the mechanism is qualified and token-serialized; simply waiting for its existing deadline is sufficient for this first profile. An acceleration is enabled only when all its native operations and fallbacks obey the same lifetime; otherwise choose a qualified ordinary-send path before dispatch. A goroutine timeout wrapper is not native cancellation.

Diagnostic publication inside admission, expiry, native submission, fallback, completion, fence and shutdown paths must be bounded and nonblocking. This includes the baseline GSO-failure `Debugf`/`log.Printf` dependency, logging locks, tracers and qlog sinks reached from those paths. Publish copied bounded metadata to a capped diagnostic queue or drop/coalesce it with a counter when full; never retain payload pointers. Sink execution is outside both the request/fence lifetime and subsequent endpoint/control progress. A blocked sink cannot backpressure these owners, and diagnostics are not joined as a prerequisite for returning write authority. Do not spawn one sink goroutine per event. This requirement is scoped to the bounded I/O chain, not a redesign of every repository logger.

An independently progressing overdue-token check runs even with no new producers. If a current native/deadline operation exceeds its absolute deadline plus the qualified tolerance, atomically mark that endpoint faulted, stop admission, resolve still-queued entries as unsubmitted and publish the fault nonblockingly. The current token and borrowed storage remain quarantined until actual return. A completion fact visible at overdue inspection is classified by its writer timestamp and native-control error facts. If inspection at or after the cutoff finds no published acknowledgment and records an overdue fault, later publication cannot erase that fault even when its completion timestamp precedes the cutoff. The acknowledgment still reconciles actual acceptance and releases ownership exactly once; an unpublished acknowledgment remains fenced. This is a violation of the qualified local-I/O contract, distinct from a normal returned deadline/backpressure result. The guarantee assumes a responsive scheduler and qualified OS; it is not hard real time during suspension or a wedged kernel.

#### Admission and capacity notification

The endpoint count/byte cap includes queued plus current requests. Producers retain their existing bounded connection/path queues until successful admission; do not copy packets into another unbounded waiting queue. Endpoint completion records, waiter metadata and diagnostic storage have separate finite allowances. Attachment reserves one bounded readiness record per admitted connection, with at most the supported path/control subqueues; if the participant budget cannot reserve that record, reject new attachment/setup rather than let an existing participant lose its notification slot. Stateless replies and public non-QUIC writes use fixed endpoint classes with their own caps. The selected endpoint parameters below fix these bounds.

Arbitrate admission as well as service: eligible ready connections take bounded turns, with round-robin selection among their paths. A producer continuously refilling cannot seize newly free capacity ahead of an already-ready peer. Bound the number of privileged control turns before ordinary work receives a turn. Connection controls, including PATH_ABANDON and CONNECTION_CLOSE, use a connection-control allowance; stateless reset, Retry, version-negotiation and refusal traffic use a separate capped class and cannot consume that allowance. Avoid fixed positive reserved capacity for every possible connection; fairness is over admitted participants with pending eligible work, under finite population and continued native progress, not a universal latency promise under arbitrary demand.

Register readiness and observe the capacity-generation counter in one serialized control operation. On capacity release, advance that counter and grant/wake an eligible registered producer; recheck after registration so a release racing the registration cannot be lost. Readiness is coalesced, with no list entry per retry. Any temporary capacity grant has a bounded lease and is reclaimed on cancellation, teardown or failure to consume it, so a paused producer cannot indefinitely reserve the endpoint. When the selected request cannot yet fit available bytes, accumulate released capacity for its turn instead of repeatedly admitting smaller later arrivals ahead of it; a legal request must fit its class and endpoint caps by itself. The bounded grant lease begins once sufficient capacity is available, and existing queued/current requests continue draining while capacity accumulates. Local backpressure also schedules bounded retry/backoff rather than a tight expiry/repack loop; this scheduling state is independent of network-path health. The control allowance, grant lease and retry floor are finite D0 parameters.

#### Submission outcomes and backpressure

The endpoint result is richer than an ordinary send error. It identifies definitely accepted packets, definitely unsubmitted packets and unresolved acceptance separately. QUIC adapters consume local backpressure as a nonfatal completion event and keep their send service alive; they must not return it through the baseline `sendQueue.Run` fatal-error channel. Public `Transport.WriteTo` instead returns its documented synchronous result to the application. Neither route equates a timeout or a zero returned byte count with proof that a native attempt was unsubmitted.

| Outcome | Payload/recovery disposition | Ordinary and multipath consequences |
| --- | --- | --- |
| Queue admission refused | No ownership transfer; producer retains its entry and reservation. Register readiness for retry, or use the route's explicit best-effort drop/error rule. | Local backpressure only. No path retirement, connection destruction or congestion-loss sample. |
| Queued expiry/revocation, or native result proving zero submission | Resolve the registered packet as locally unsubmitted without PN reuse, peer acknowledgment or network-loss/RTT evidence. Return still-needed reliable information through its existing logical owner; discard an admitted unreliable DATAGRAM with bounded drop observability. Reclaim packet storage/local credit once no borrow remains. Probe accounting follows the conservative rule below. | A local deadline is nonfatal backpressure; revocation follows its already chosen lifecycle action. A non-timeout native rejection retains its distinct meaning, such as PMTU feedback for a known size rejection. |
| Known accepted prefix, including a prefix followed by timeout | Keep accepted packet flight/delivery evidence. Resolve only a proven-unsubmitted tail as local disposal; retain any uncertain tail separately. Native buffer references end only on actual return. | A following local timeout remains backpressure. Do not replay the accepted prefix or declare a path failed from local latency. |
| Uncertain native submission | Preserve possibly submitted packet registration and congestion/recovery evidence until ACK/loss/retirement resolves it. Do not relabel it unsubmitted, refund its amplification allowance, or immediately retry its encrypted bytes as fallback. Reliable information can later be retransmitted through ordinary logical recovery; DATAGRAMs are not retransmitted. | Nonfatal local timeout/backpressure when that is the error class. Ordinary peers remain alive. Duplicate or early feedback still resolves ownership exactly once. |
| Destination-specific failure other than local timeout | Resolve definite/uncertain submission separately, after bounded permission/GSO fallback; size errors go to PMTU. | Connection-owned policy makes only the matching multipath tuple suspect and preserves survivors; no survivor uses bounded recovery/no-progress termination. Ordinary non-timeout error behavior is preserved. The selected native error table fixes the classes; socket sharing does not prove endpoint failure. |
| Endpoint-fatal error, or failed deadline control | Stop that endpoint's admissions/submissions, preserve unresolved ownership, and notify all affected users. | Paths on that endpoint become unavailable under endpoint-failure policy; ordinary connections there can terminate. Other endpoints may survive. Explicit Transport.Close remains a separate caller action. |

The connection owns the generation-qualified local-disposal transition for already registered packets: retire their local registration/flight obligations exactly once without treating local disposal as peer ACK or a congestion-loss event, return only reliable information still owed, and preserve consumed PNs. The endpoint releases its native buffer/queue credit independently; protocol accounting uses its reserved completion record containing immutable identity/outcome metadata and independently owned recovery references, never a pointer into a released packet buffer. Accepted or uncertain outcomes retain normal packet evidence. A PATH_RESPONSE or packet ACK can arrive before local completion; the later completion may reconcile ownership but cannot undo validation/delivery or mutate a new generation. Standard connection-level no-progress timers remain effective during sustained local backpressure; they are not reset by unsuccessful local retries.

For co-admitted A and C with deadline t0+B, a native A lasting until that deadline leaves C expired and definitely unsubmitted. C must not be dispatched merely because A returned. A later request D whose deadline remains in the future may be dispatched after deadline replacement. None of those local deadline events alone retires either server-side path or destroys an ordinary peer. Both server paths share this endpoint; the design promises finite ownership resolution and fair admission under stated conditions, not independent socket capacity for those paths or bounded restoration of redundancy.

#### Pending-local recovery eligibility

Pre-I/O registration remains in the connection-owned emission/recovery path, preserving consumed packet numbers, immutable registration ordinal/time, frame ownership, congestion/pacing send notification and capacity reservation. On granted endpoints, registration additionally starts in `pending-local`; that reservation prevents oversending but is not evidence of network transmission. One connection-owned eligibility state gates packet/time-threshold loss, loss/PTO alarm construction, PTO probe-candidate selection/requeue, persistent-congestion spans, ECN transmission evidence and RTT/delivery sampling. A pending-local packet cannot be declared network-lost merely because a higher PN is ACKed. `QueueProbePacketAt` must skip pending-local records even when another accepted packet legitimately arms PTO; it cannot use an unfiltered FirstOutstanding result to retire/requeue pending work. Pending-only work has the endpoint deadline and normal connection no-progress deadline, not a fabricated network PTO. Unregistered behavior is unchanged.

| Connection-owned transition | Recovery consequence |
| --- | --- |
| Pending → known accepted | Record the writer's immutable native-return timestamp as conservative network-recovery eligibility time. Preserve registration-time sampling provenance; do not rewrite it to that timestamp. ACK/loss/PTO processing can now consider this packet, with loss/PTO elapsed time starting no earlier than eligibility. |
| Pending → uncertain | Retain possible transmission and flight; use native-return time for conservative recovery eligibility. No immediate encrypted-byte replay. Uncertainty alone supplies neither a path-failure PTO attempt nor a valid new RTT/rate sample; invalidate intervals bridging excluded sampling and require a fresh eligible anchor. |
| Pending → proven unsubmitted | Remove its local flight/reservation and return still-needed reliable information exactly once, without ACK, network-loss, ECN or persistent-congestion evidence. Preserve PN consumption and conservative amplification charges. |
| Valid authenticated ACK before completion | Reconcile delivery/flight exactly once through the registered identity; the ACK supplies delivery evidence, never native-buffer release. Suppress timing/rate sampling whose local outcome is unresolved. Keep a bounded completion tombstone until the native result arrives; later completion only reconciles local ownership and cannot resurrect flight or undo delivery. A contradictory proven-unsubmitted result is an owner-contract fault, not permission to erase authenticated delivery. |
| Close/retirement before completion | Preserve the same terminal/tombstone owner and bounded record until completion. Old-generation results cannot restore current eligibility. |

Retry/reset is also a consumer of this state: ResetForRetry suppresses an RTT estimate based on unresolved local evidence, invalidates old request epochs/queued authority, and moves unresolved completion references to bounded terminal tombstones before replacing histories. Existing protocol Retry requeue/discard and PN continuation remain exact-once; a late result cannot requeue frames again, mutate replacement histories or reclaim a current native borrow. The eligibility timestamp is distinct from existing raw registration-to-ACK `DeliverySample` semantics. Registration snapshots and congestion send ordering remain intact; only the explicitly granted endpoint's network-evidence eligibility changes. ACK-confirmed early delivery is usable for logical delivery but excluded from unresolved timing/rate intervals. ECN validation defers transmission-dependent conclusions while local outcomes needed by those counters remain unresolved; missing evidence is not clean congestion evidence. Writers publish facts only. Draining already published completions first is useful but cannot replace the pending-local guard because a result may not yet be published.

Paper trace: A registers and waits locally; D later submits and is ACKed while A's expiry result is still unpublished or unconsumed. Loss detection skips pending A even below D's ACK watermark. A's subsequent unsubmitted transition releases its reservation without a loss signal. If accepted B instead arms PTO while lower A remains pending, probe selection skips A and selects eligible work or the existing no-candidate probe path without retiring A. In the alternate trace, A reaches the peer and is ACKed before native completion: delivery settles once, its timing sample is excluded, and completion releases the native token without a second ACK/flight transition. These are future deterministic acceptance cases, not executed tests.

#### Send-route adaptation and probe accounting

All routes below use the same endpoint admission/result contract. Successful admission transfers packet storage or a retained immutable reference until completion; refusal leaves ownership with the producer. Existing anti-amplification/local-send reservations are distinct from storage ownership. No connection event loop, endpoint control path or listener receive loop waits for native completion. Dedicated producers may wait only where explicitly listed; no waiting producer can hold an endpoint control lock or be needed to expire/revoke another request.

GSO/batch retries stay inside this one request lifetime. |

Preserve conservative baseline probe charging: once an attempt reserves amplification bytes and commits challenge/backoff state, rejection, local expiry or zero-submission completion does not refund that allowance or decrement the committed challenge attempt. If admission is refused before those commitments, there is nothing to refund. The producer prepares and commits amplification/challenge state before offering a dispatchable request; successful admission cannot race ahead of that publication. Refusal after commit keeps the conservative charge. A queued probe's challenge remains recognizable even if a response arrives before the completion notification. Accepted and uncertain outcomes stay charged. An absolute validation deadline and challenge cap still bound retries; local send backpressure is not path-failure evidence, but it does not promise validation success. Teardown/generation change owns eventual challenge disposal. This choice avoids adding a refund protocol to the first profile.

For public WriteTo, a normal queued/native deadline result is returned within the qualified budget and finite completion overhead. If the native contract is violated and the call never returns, the synchronous adapter must also retain the caller's borrow until actual return; an overdue fault notification does not make the bytes reusable. This explicit exceptional limitation does not authorize an early return, hidden copy outside the memory budget or false successful cleanup. Native uncertainty remains visible as an error and is never represented as proof of zero submission. The exact grant surface below fixes identifiable backpressure, local-deadline, uncertain-result and closed error semantics for opted-in transports; unregistered WriteTo behavior is unchanged.

#### Shutdown, grant return and entry points

Keep Transport.Close's explicit connection/listener destruction semantics and add a separate selected `Transport.WaitMultipathIOStoppedV1(ctx context.Context) error` observation for opted-in transports. Close first seals endpoint admission and invalidates producer/response epochs, then performs existing logical shutdown. It requests asynchronous writer shutdown; its return alone does not return write/deadline authority. Post-close writes and attachments are rejected. Discard queued work through exact-once local completion, let the current native operation return under its existing budget, and join every possible producer/current submission/deadline action before publishing the stopped state. There is no obligation to send queued close replies on this abrupt-close path. Close ownership of the socket is unchanged.

WaitMultipathIOStoppedV1 observes that requested shutdown; before Close is requested it reports an identifiable not-stopping result, and on a transport without the grant it reports not-configured. Context expiry only stops waiting. Success means no old coordinator, captured producer, native call or stale cancellation can perform a future write/deadline mutation and all native borrows have ended. It returns the grant; it does not certify that past writes succeeded or restore the old deadline. The caller sets its desired write policy after success. Prior endpoint faults remain observable through their result/fault records. A native fault with unresolved references cannot produce successful join, even after connection termination. An eventual late return permits cleanup/join without reopening admission. The observer concerns transport-wide write authority; Conn.WaitTransportDetachedV1 remains the separate condition for safely closing a transport without destroying that connection's survivors.

Do not infer a grant merely from a multipath-enabled Config reaching a constructor. Validate every explicit origin/target and every server-selected configuration before advertisement or attachment. If a dynamic server configuration first enables multipath on an ungranted initialized transport, reject that selected configuration locally; never retrofit the writer. Socket-owning constructors may explicitly install the same grant on their private native transport using the D0-selected finite default B. All budgets are fixed before transport initialization. ## Selected endpoint parameters

Retain one endpoint control owner plus one native writer. The control owner arbitrates admission, expiry, revocation, readiness and exact-once terminal publication; it never performs native I/O or calls sinks. The writer reports outcome facts tagged with immutable endpoint/connection/path/tuple identities. The connection loop alone applies protocol policy and recovery disposal. Claim includes deadline setup and every fallback operation. Queue expiry progresses independently of current native submission. Do not add a second protocol state machine in the writer.

The following are initial engineering limits, selected to bound ownership rather than claim measured throughput. Refuse unsupported values or work before transfer; a legal request must fit its class cap. Later implementation cannot silently relax these accepted engineering limits.

| Resource | Selected initial limit | Reason and accounting |
| --- | --- | --- |
| Native request duration B | Explicit registration accepts 1 ms through 1 s; socket-owning constructors use 100 ms. | Covers admission through native return and nonblocking local completion. Queueing, retries and partial progress share one absolute deadline. No hard real-time claim during suspension or a wedged kernel. |
| Completion tolerance | 20 ms on the initial native qualification venue. | An overdue current token after its deadline plus tolerance faults admission independently of native return. This is a selected supported-environment bound to qualify, not measured evidence. Queue-expiry observation uses the same tolerance. |
| Endpoint queued plus current requests | 128 entries / 8 MiB of retained payload capacity, both enforced. | Charge backing capacity, not only payload length. Ordinary data gets at most 104 entries / 6 MiB; connection control 8 / 1 MiB; stateless responses 8 / 512 KiB; public non-QUIC writes 8 / 512 KiB. Class maxima do not create additional storage. |
| Request size | Ordinary batch at most 1 MiB and the existing 32-buffer batch cap; control/stateless/public at most 64 KiB. | Baseline large buffers are 20 KiB (`internal/protocol/protocol.go:114`); a 32-buffer batch fits the ordinary cap. Public oversize datagrams fail locally with a size error; no fragmentation or hidden copy is introduced. |
| Participating connections | 4,096 readiness records per endpoint; two path queues plus one control queue per participant. | Reserve before attachment/connection setup; reject admission if unavailable. No per-retry waiters. Stateless and public classes have fixed readiness records. |
| Completion metadata | 256 records per endpoint; at most four unconsumed records per connection. | Reserve before request admission and retain through protocol consumption or terminal-owner disposal. Native payload release does not wait for consumption. A stalled consumer exhausts only its bounded allotment; fairness requires eligibility and available completion capacity. |
| Producer queues | Existing 32-entry queue per supported path; 4 MiB connection-wide pending local payload capacity across producer plus endpoint ownership. | Account each retained buffer once across transfer; accepted/recovery application-data retention is a separate existing budget. The endpoint does not allocate an overflow queue. |
| Admission turns | Round-robin ready participants and their paths; at most two privileged control turns before ordinary eligible work. | Separate connection control from stateless pressure. Accumulate released bytes for a selected legal request instead of allowing smaller arrivals to overtake indefinitely. |
| Capacity lease and retry floor | A capacity grant lasts 10 ms once enough space exists; local-backpressure retry floor 1 ms. | Reclaim on cancellation/teardown/expiry. No native submission after a request deadline. Timer arithmetic saturates rather than wraps. |
| Diagnostic publication | 128 copied records of at most 256 bytes per endpoint, with drop/coalescing counters. | No payload or mutable protocol pointers; no per-event goroutine. A fixed sink consumer may block outside endpoint progress and is not a write-authority participant. Stop publication on teardown; a blocked sink never acquires native authority. |

The limits bound the new endpoint mechanism, not all memory in an application process. Received packets, streams and existing controller stores retain their own aggregate limits. Path controllers share connection-level ceilings: do not multiply the baseline live delivery, retained delivery and recovery-outcome maxima by two. Reserve per-path use from the shared budget; exhaustion causes a bounded defer/decline or existing controlled degradation, never loss of required ownership evidence. Before public support, measure idle, backup, saturated and retired-path memory against these ceilings.


The 4,096 participant cap applies to ordinary as well as multipath connections attached to a granted endpoint. Local setup refusal returns ErrMultipathResourceLimitV1 before attachment. On a server, reuse the existing bounded CONNECTION_REFUSED response path (`server.go:1035,1187`) through the capped stateless response class; when that class is full, drop the response under its existing best-effort rule. One cap-plus-one case and its response-cap-full variant cover admission without a new load campaign. Unregistered endpoints keep their existing admission behavior.

## Exact grant surface and errors

The additive surface is `Transport.ConfigureMultipathIOV1(maxWriteDuration time.Duration) error` before initialization and `Transport.WaitMultipathIOStoppedV1(ctx context.Context) error` after Close. Pre-init registration grants writes/deadlines on the exact socket, not read deadlines or close ownership. Equal deadline means expired. Explicit grants require B in [1 ms, 1 s]; owning helpers use 100 ms. Successful join is the only return of write/deadline authority; caller restores its desired deadline afterward. Context cancellation only stops waiting. Native-contract violation leaves public borrowed bytes unavailable until actual return.

Use `ErrMultipathInvalidConfigV1`, `ErrMultipathUnsupportedV1`, `ErrMultipathBackpressureV1`, `ErrMultipathDeadlineV1`, `ErrMultipathUncertainV1`, `ErrMultipathResourceLimitV1`, `ErrMultipathNotConfiguredV1` and `ErrMultipathNotStoppingV1` as applicable. Deadline also matches `os.ErrDeadlineExceeded` and backpressure; uncertain may coexist and never means unsubmitted. Closed operations match `net.ErrClosed`; canceled waits preserve `ctx.Err()`. Preserve identifiable native size errors. Snapshot/error categories never replace accepted-prefix/uncertain-tail/unsubmitted-tail metadata held by the completion owner.

Public `ErrMultipathBackpressureV1` identifies a local capacity/deadline cause only; it says nothing about accepted bytes, safe replay or delivery certainty. Match sets are: capacity refusal → Backpressure; queued expiry → Deadline + `os.ErrDeadlineExceeded` + Backpressure; accepted prefix with deadline on the remaining request → those deadline/backpressure identities plus the internal accepted-prefix/proven-tail facts; uncertain native timeout → Uncertain + Deadline + `os.ErrDeadlineExceeded` + Backpressure. Add Uncertain whenever a remainder is ambiguous. Neither `errors.Is(Backpressure)` nor `n == 0` authorizes replay. Only the internal per-portion completion enum can prove non-submission.

### Native error classification

Submission certainty and error cause are independent axes. Preserve existing first-send permission retry and GSO fallback only while the same absolute deadline and authority permit them (`send_conn.go:92–134`); classify the final result after those bounded operations. The connection loop, not the writer, applies the following policy to immutable endpoint/path/tuple-qualified facts.

| Final result class | Policy |
| --- | --- |
| Queued expiry, native timeout, temporary capacity exhaustion (`EAGAIN`/`EWOULDBLOCK`/`ENOBUFS`) | Nonfatal local backpressure; no failure-counter increment, path retirement, backup promotion or congestion-loss event solely for this cause. Resolve accepted/pending/uncertain portions separately. |
| Definite size rejection (`EMSGSIZE`) | Notify the affected PMTU owner and reschedule still-needed fitting reliable information; no blanket path failure. A partial/uncertain remainder retains its independent submission state. |
| Destination error (`ECONNREFUSED`, `EHOSTUNREACH`, `ENETUNREACH`, final `EACCES`/`EPERM`) or other send error without endpoint-wide failure evidence | For negotiated multipath, mark only the matching current tuple suspect/ineligible and use the selected promotion policy. Keep healthy survivors. With no survivor, retain bounded validation/recovery until recovery or ordinary no-progress termination. A late old-tuple result cannot demote its replacement. Ordinary/non-negotiated connections preserve baseline non-timeout error policy. |
| Closed/invalid endpoint (`net.ErrClosed`, `EBADF`, `ENOTSOCK`), failed deadline control or overdue qualified-native token | Quarantine that endpoint and stop admission; affect all its paths/users, preserve unresolved borrows, and retain healthy paths on other endpoints. Never infer successful join from the fault. |

A destination error does not automatically send PATH_ABANDON or spend another wire ID. The fallback class is deliberately path-scoped unless the endpoint owner has concrete endpoint-wide evidence; sharing a socket does not establish that every destination failed. Paper cases cover destination error with a survivor, without a survivor, stale tuple, size rejection, local timeout and endpoint-fatal failure within the existing deterministic slice budgets.
