# Packet-emission construction Implementation Plan

**Date:** 2026-09-08. **Status:** Accepted; not implemented. **Track:** C in QGF-AD-2026-09. **Depends on:** Nothing outside this track. **Normative scope:** Current outcome, boundaries, invariants, acceptance evidence, blockers and stops. **Audit history:** [Construction receipt](https://github.com/the-sarge/quic-go-fast/blob/3db9121a2c91bce8acb7b6f871adfcaf51bc560b/docs/audits/2026-09-08-emission-construction/README.md). **Related:** [Program](2026-09-08-architecture-deepening-program.md), [T test-entrypoint plan](2026-09-08-emission-entrypoint-tests-plan.md), ADRs [0001](0001-upstream-compatibility.md), [0003](0003-follow-stable-upstream-releases.md) and [0004](0004-packet-emission-ownership.md).

## Goal

Make initial packet-emission assembly explicit at the existing connection composition interface: build a local packet packer, create the initial queue in the final-binding helper, and install the complete emission value once before token setup or publication. Maintainers no longer need to prepopulate fields of the same object that the helper reads while replacing it. This is setup maintenance, not a demonstrated initialization-race fix or performance improvement.

## Current shape and ownership

Verified production sites are `connection.go:372–373` and `:499–500`: both constructors first assign `s.emission.packer`, then call `bindPacketEmission`. `preSetup` assigns `c.emission.queue` at `:521`. `bindPacketEmission` at `:2502–2511` constructs the value by reading those two fields back from itself. There are only two production packer/bind routes. The constructor has no ordinary error return; `newSendQueue` only allocates state and four channels, without starting a worker.

The client uses `emission.setToken` at `connection.go:508` before returning. Client publication is later at `transport.go:303–329`; server construction, first receive enqueue, handler-map publication and worker launch are at `server.go:815–858`. Connection-ID constructors store rather than invoke publication callbacks. `Conn.handlePacket` enqueues and signals; it does not pack. `Conn.run` processes initial handshake events before launching the worker at `connection.go:585–597`. No production observer of the partially populated emission was identified. Complete assembly and a running worker remain different lifecycle states.

## Decision

At each existing constructor packer/bind site, assign `packer := newPacketPacker(...)` using the unchanged explicit arguments and call `s.initPacketEmission(packer)`. Rename the existing `Conn.bindPacketEmission` to `Conn.initPacketEmission(packer *packetPacker)`. It creates a local queue with `newSendQueue(c.conn, &c.handshakeSendFeedback)` and assigns `packetEmission{packer: packer, recovery: &c.sentPacketHandler, queue: queue, version: c.version, policy: c, conn: &c.conn}`. Remove only the emission queue assignment from `preSetup`; leave feedback initialization and the other producers there.

Keep the helper in `connection.go`, where the existing connection composition lives. This is not an opaque emission factory receiving unrestricted Conn. Document that producers/recovery/path/feedback must already exist, the helper runs only once before use, and recovery uses a live slot while the packer captures its packet-number manager. No initialization flag, runtime nil validator, new error return, additional interface, closure or module allocation is needed.

Preserve client token installation/RTT update before return, distinct client/server crypto setup, publication and worker ordering. StartHandshake/initial-event errors still occur before worker start; this change does not add unconditional deferred queue Close, which would wait on an unstarted worker. Early-error cleanup and failed server publication are outside C; the latter is already owned by I8. Existing path generation/MTU/worker decisions stay with Conn. Preserve the exact `replacePath` order: update Conn path slot, close/join old queue, allocate/publish replacement queue, then Conn starts its returned worker. Server rebinding retains queue identity and uses current destination at syscall time. Direct probes and retained close output keep their current paths and ownership.

### Recovery and fixtures

Retain `schedulingRecoveryInputs` forwarding real registration/numbering while controlling scheduling, `emissionRecoveryOutcome`, `emissionECNTransition` and `emissionPTOOpportunity`. Some are installed after packer construction; capturing recovery by value changes their meaning. Do not replace real SentPacket/Peek/Pop/QueueProbePacket/ReceivedAck behavior merely to get tests green. Full mocks used for isolated receive/lifecycle tests are not real registration evidence. `mismatchedConstructionNumber` remains intentional constructor-error injection; transparent sealing fixtures may rebuild only the packer before use. They must not rerun initialization and allocate or abandon a second queue. No common fixture migration is required by this plan.

### Alternatives and non-goals

**Do not do this:** A six-argument complete `newPacketEmission` constructor is a shallow literal-returning function here; there is no independent production caller needing it. Passing both packer and queue locals removes self-reading but duplicates queue creation or makes unrelated preSetup return a sender. Prefer queue creation within the existing final binder. A source-ID/sealing factory hiding eleven packer dependencies risks turning test substitution into live queue reinitialization. A generic bag, broad builder or send-path owner adds an unjustified interface. Leave explicit packer argument lists visible.

**Do not do this:** Capture recovery/path by value, add dynamic packet-number proxies, change packet-time methods/results/hooks, move worker launch, reset live emission, force all tests through the loop, weaken second-append/ACK assertions, redesign path policy or repair unrelated startup lifecycle. Zero-state type safety and blanket concurrency safety are not promised. Comment-only clarification plus C1 is the fallback if C2 cannot remain a small setup change.

**Non-goals:** Production send-helper migration (already completed in Track E), maintained test-helper migration (separate T1), #72/#73 fixture conventions, #103 pacing diagnosis, I8 failed-publication cleanup, native capability races, parser/HTTP/3 fixes, public API/wire changes, packages, capacity/scheduling/congestion changes, new platform/support or performance campaigns. Completed Track E and its accepted uncertainty remain intact; upstream acceptance is not a prerequisite. Higher-priority correctness work is preferred scheduling, not a synthetic blocker for C.
