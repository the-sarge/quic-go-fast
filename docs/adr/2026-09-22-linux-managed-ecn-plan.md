# Linux managed ECN implementation plan

**Date:** 2026-09-22
**Status:** Accepted; not yet implemented

**Depends on:** Nothing — safe to start first

## Goal

Deliver a complete Linux managed ECN metadata path through the existing managed endpoint, exact lease and registered policy-wrapper seams. The endpoint retains native socket and lifecycle authority while QUIC receives the correct per-datagram ECN value and emits requested marks through ordinary and registered batch sends.

## Current shape (verified 2026-09-22)

`managedPacketEndpoint` owns the private socket, retained receiver, generation and active-I/O joins (`managed_packet_endpoint.go:63-100,121-172`). Its public `ReadFrom` uses the retained native reader when present but copies only payload and address, releasing the internal packet and discarding ECN metadata (`managed_packet_endpoint.go:174-213`). Its ordinary `WriteTo` has no ancillary-mark channel, while `WriteBatchV1` accepts shared OOB and remains generation checked (`managed_packet_endpoint.go:216-237`).

Managed registration records buffer and coalescing facts but wraps the caller's outer `net.PacketConn`; a policy wrapper therefore becomes `basicConn`, whose packets contain no ECN and whose marked writes panic (`external_packet_io.go:88-131`; `transport.go:387-409`; `sys_conn.go:127-167`). The external batch path already appends one IPv4 or IPv6 ECN control message and invokes the registered policy-checking callback with definite-prefix semantics (`send_conn.go:138-168`; `external_packet_io_oob.go:11-19`).

Linux `oobConn` is already the native representation owner: it enables `IP_RECVTOS` / `IPV6_RECVTCLASS`, parses kernel control messages into `receivedPacket.ecn`, appends outgoing IPv4/IPv6 ECN messages and reports ECN capability (`sys_conn_oob.go:57-178,240-317,335-362`; `sys_conn_helper_linux.go:157-159`). Managed receive setup currently retains that reader only when GRO activation succeeds, coupling metadata ownership to coalescing and using the coalesced receive storage policy for a path that must also preserve full ordinary UDP datagrams (`managed_packet_receive_linux.go:7-38`). Existing generation, deadline, cleanup, selected-peer and batch-progress tests establish the seams that must remain authoritative.

## Decision

Add one private managed raw-connection adapter published from successful `bindQUIC`. It composes the caller's registered outer connection with the exact lease's endpoint-owned native reader/writer; it does not expose a descriptor or promote native methods. This adapter becomes the sole boundary that correlates native receive metadata, chooses a policy-safe marked-send route and reports managed ECN capability.

Calling `ConfigureManagedPacketIOV1` with a wrapper is an authority-bearing declaration: an ECN-capable wrapper must synchronously delegate `ReadFrom` to the exact lease using the caller-supplied backing buffer and return the same datagram range and source address, and its checked batch callback must synchronously forward the exact borrowed payload/OOB after policy validation. The adapter does not attempt to prove arbitrary wrapper honesty. Buffering, substitution, reordering, synthetic addresses or delayed callback forwarding are outside the supported ECN domain and must not produce a capability claim.

For receive, the endpoint retains Linux `oobConn` for an ECN-only path only when receive qualification succeeds for every usable admitted family, independently of GRO. On a partial-family failure it records the failed family, publishes no correlated ECN and retains the decoder only when coalescing normalization independently activates; otherwise it uses the ordinary reader. A route-level capability failure such as a missing checked output callback does not by itself retire a family-qualified receive reader. When GRO is off and ECN is usable, the retained reader performs one `ReadMsgUDP`-class kernel receive into storage large enough for a full UDP datagram; it must not batch-read ahead, silently truncate a valid payload or strand a prefetched datagram at lease release. When both GRO and family-complete ECN are disabled, no decoder is retained solely for unusable metadata; when GRO remains enabled under ECN opt-out or partial-family failure, the existing decoder remains only for coalescing normalization and reports ECN false. Each lease `ReadFrom` records an operation-scoped metadata result from the exact native read before releasing its internal payload storage. The managed adapter invokes the registered outer `ReadFrom`, then consumes metadata only when the final delegated lease read is from the current generation, used the same backing buffer supplied to the wrapper, and returned the same payload range and source address as the wrapper. A selected-peer wrapper may discard foreign datagrams by repeating lease reads; only the final returned lease read is eligible. If the predicate does not match, the returned datagram is ordinary and `ECNUnsupported`; stale metadata is never reused. Correlation carries ECN only: packet-info and other native metadata remain cleared under existing managed behavior.

For send, unmarked packets, including explicit Not-ECT, retain the existing outer `WriteTo` path. Marked direct-lease writes use the endpoint-owned native `oobConn.WritePacket` under the lease generation/active-I/O guard. Marked writes through a policy wrapper enter an operation-scoped checked-singleton route: the adapter supplies the exact borrowed payload/OOB and current generation to the registered callback, the wrapper validates the selected destination, synchronously delegates that same singleton to the lease and returns the lease's `(count, error)` result unchanged, without the zero-progress normalization allowed for general batches. Every checked-singleton call has a distinct operation identity; overlapping calls preserve their own payload/OOB, generation and native-result association without cross-association or stale-token reuse. The implementation may serialize native writes and gains no new parallel-throughput guarantee. The endpoint recognizes each operation identity and performs an error-preserving native single write. One centralized result translator accepts only `(1, nil)` as success, preserves the original terminal error from `(0, err)`, preserves message-size feedback and the send connection's first-send permission retry behavior, and rejects `(0, nil)`, counts outside `[0,1]` or count/error combinations that violate the singleton contract without silently retrying or fabricating success. A wrapper without that callback cannot advertise managed ECN. Registered multi-datagram batches retain the existing shared-OOB callback and definite-prefix/terminal-error contract; the singleton translation is not a license to change batch semantics.

Managed ECN capability is true only when the retained Linux native reader reports ECN, every usable socket family in the endpoint's admitted domain completed family-specific receive and send setup, and every supported marked-send route for the registration is policy-safe. An exact direct lease with a nil batch callback uses the endpoint path directly; a direct registration with a non-nil callback qualifies only when that callback synchronously forwards the exact payload, OOB and destination through the exact lease under the existing registered-batch definite-prefix and terminal-error contract. A registered wrapper additionally requires the checked callback and synchronous forwarding contract above. Endpoint-managed setup owns and retains the per-family record consumed by adapter capability projection: refactor the shared private OOB constructor to return detailed receive-option outcomes and encoder availability to managed setup while its existing `newConn` wrapper discards the detail and preserves unregistered behavior. The record includes the socket's actual family domain, `IPV6_V6ONLY`, IPv4-mapped behavior and failure reason per admitted family. A single-family endpoint may ignore an unavailable other family; a dual-family endpoint must qualify both, and any family failure makes managed ECN false for that endpoint. The endpoint also owns a coalescing/normalization activation fact distinct from retained-reader presence. The adapter projects only managed facts: ECN is gated as above, GSO remains false, GRO reflects that explicit activation fact rather than the existence of an ECN-only reader, and DF plus every other capability retain current managed behavior. Every diagnostic consumer uses the same activation fact. When it is false, including for an ECN-only retained reader, diagnostics report `receive_mode=ordinary`, `coalescing=false` and `receive_enabled=false`; `receive_enabled` continues to mean native GRO/URO or persistent managed coalescing normalization. The adapter must not forward the native connection's capability set wholesale. `QUIC_GO_DISABLE_ECN`, ancillary setup denial, unavailable native representation, absent or malformed metadata, an uncorrelated wrapper read and a wrapper without checked marked output all remain usable ordinary paths without claiming managed ECN.

Malformed ECN control data must not publish a partial or stale mark. Preserve the payload only when the native representation can classify the read as an ordinary datagram without weakening the existing native parser's structural checks; otherwise discard that consumed malformed datagram and continue reading. Managed drop-and-continue is selected by endpoint-retained managed-reader mode or equivalent endpoint-owned private state, not by the published GRO capability, so it applies to a managed ECN-only reader. The existing unregistered non-GRO reader remains fatal on ancillary decode failure. Do not turn malformed ancillary data into a transport-wide capability claim or a copied previous mark.

**Rejected alternative (do not do this):** Do not expose `SyscallConn`, `ReadMsgUDP`, `WriteMsgUDP` or raw descriptors on the managed lease. Do not bypass the outer selected-peer wrapper for marked output. Do not infer capability from socket-option success, GRO, GSO, the presence of a promoted method or the batch callback alone. Do not project all native capabilities through the managed adapter. Do not split receive and send into independently advertised half-capabilities.

**Non-goals:** Darwin, FreeBSD, OpenBSD or Windows qualification; new public signatures; wiremux packet-profile ownership; QUIC ECN recovery-policy changes; receive-coalescing redesign; segmented-send redesign; DF/PMTU; throughput claims or a benchmark campaign.

## Implementation slices

### Slice L1 — Deliver and qualify Linux managed ECN

**Stable identity:** `QGF-ECN-20260922/L1`. One intended PR; GitHub child pending default-branch plan publication.

**What it delivers:** The decision above through `ConfigureManagedPacketIOV1`, direct managed leases, registered selected-peer wrappers, QUIC receive processing, ordinary sends, registered batch sends, fallback, generation reuse and terminal cleanup.

**Existing-work disposition:** New implementation slice. No open PR or implementation branch exists. The unmerged `codex/triage-354` branch contributes only glossary/ADR draft evidence and is replaced by this audited package; no code from it is an accepted baseline.

**Blocked by:** None. It is the first implementation frontier.

**Single owner after merge:** `managedPacketEndpoint` owns the native reader/writer, ancillary setup, operation-scoped metadata, socket lifetime and generation. The private managed raw adapter owns correlation and route selection for the exact registration. The caller's outer wrapper owns peer policy, and the send worker retains ordering, definite-prefix fallback and terminal-error attribution. `Transport` owns only admission and publication under `packetIO.mutex`.

**Authority completeness:** No persisted fact or restart format is introduced. Construction, admission, generation validation, receive correlation, marked-send route validation, capability publication, lease reuse and destructive cleanup land in this slice. No alternate native metadata owner or generic mutation path remains.

**Transitional-seam budget:** Zero new temporary seams. The permanent adapter composes endpoint metadata authority with supported outer policy wrappers; it is not a migration shim. Existing ordinary `net.PacketConn` behavior remains a permanent fallback.

**Blast radius:** `managed_packet_endpoint.go`, `external_packet_io.go`, `managed_packet_buffers.go`, Linux managed receive setup, the private OOB constructor/setup result, existing OOB parsing/sending, `ConfigureManagedPacketIOV1` documentation, [external receive diagnostics](../agents/external-receive-diagnostics.md), [Linux managed fallback](../agents/linux-managed-fallback.md), managed diagnostics and focused tests. Shared state includes the serialized per-read metadata handoff, distinct concurrent checked-singleton operations, per-family setup record, explicit normalization activation fact and lease generation; concurrency includes Close/read/write/batch joins. Public method signatures remain unchanged, while the existing public configuration comment must document the synchronous exact-read and exact-callback forwarding preconditions, direct-registration callback rule and unchanged singleton-result requirement for ECN-capable wrappers. Wrapper ownership, full UDP payload preservation, deadline restoration, send ordering, progress/error semantics, diagnostic meaning, ancillary-denial fallback and non-managed connections are preserved. No dependency, schema or performance contract changes. No untraced effect is accepted; a need to alter QUIC recovery, wiremux ownership, public topology or another platform invokes the stop conditions.

**Artifact classification:** Managed runtime behavior is shipped behavior. Generation checks, exact-read metadata correlation, capability gating, policy-safe route selection and cleanup are required safety enforcement. Unit/native tests and any temporary fault injector are verification aids; none is an approved maintained product or recursively complete harness. Plans, native receipts, review history, issue pointers and journal entries are process/traceability metadata.

**Representation contract:** Supported input is a factory-created Linux UDP managed endpoint and current exact lease, registered directly with either no batch callback or a callback that synchronously forwards exact payload/OOB/destination through that lease under the existing general-batch result contract, or registered through a policy wrapper that declares and satisfies synchronous exact forwarding. The wrapper's `ReadFrom` must delegate using the caller-supplied backing buffer and return the final lease read's same range and source address; its checked callback must validate the destination, synchronously delegate the exact borrowed singleton payload/OOB to that lease's `WriteBatchV1`, and return the lease result unchanged. The endpoint-retained `oobConn` and `unix.ParseOneSocketControlMessage` own kernel control-message representation; endpoint-managed setup owns the private admitted-family/outcome record and normalization activation fact; the private managed adapter owns the current-generation buffer/range/address correlation, distinct checked-singleton operation identities and family-complete capability projection. The guarantee is universal over this typed/correlated managed domain and Linux kernel-emitted IPv4 `IP_TOS` / IPv6 `IPV6_TCLASS` messages, including IPv4-mapped traffic only when the admitted dual-stack socket passes its explicit native row. Unknown, buffering, reordering, copying/substituting, result-normalizing or synthetic wrappers are outside the ECN guarantee and must not cause a capability claim. Finite terminating evidence is the matrix below plus focused race and repository gates.

**Contract closure:** Triggered. Misattributing or emitting an ECN mark can corrupt congestion-control validation and cross a policy/lifecycle boundary, and the invariant has independently reachable IPv4/IPv6, direct/wrapped, ordinary/batch, current/stale and metadata-validity states. Invariant: a managed packet carries or emits an ECN value only when the endpoint-owned native representation and the current lease operation establish that exact value for that exact datagram and selected destination. Enforcement owner: the endpoint-owned reader/writer plus the single private managed raw adapter.

## Acceptance criteria

- [ ] Native Linux IPv4 and IPv6 tests deliver Not-ECT, ECT(0), ECT(1) and CE from the endpoint-owned native reader through a current managed lease to QUIC with no stale metadata.
- [ ] Non-GRO managed receive preserves full accepted UDP payloads, consumes one kernel datagram per outer lease read, does not strand read-ahead across release and retains no ECN-only decoder when ECN and GRO are both disabled.
- [ ] Native Linux ordinary and registered batch sends apply each requested supported ECN class to the selected destination for IPv4 and IPv6, while foreign destinations remain rejected.
- [ ] ECN-capable wrappers return checked-singleton lease results unchanged; injected native `EPERM` and `EMSGSIZE` preserve first-send retry and message-size handling, while normalized `(0,nil)` and other invalid results fail without retry or fabricated success.
- [ ] Direct registrations advertise ECN only with a nil batch callback or synchronous exact payload/OOB/destination forwarding through the exact lease under existing batch semantics; supported policy wrappers additionally satisfy exact read and checked-singleton forwarding, and every usable admitted socket family plus both directions qualify.
- [ ] Endpoint-managed setup supplies the adapter's private per-family outcome record while preserving unregistered `newConn`; a partial-family failure disables managed ECN and identifies the failed admitted family.
- [ ] A partial-family failure publishes no correlated mark and retains no ECN-only reader when GRO is inactive; active coalescing normalization may retain its decoder independently.
- [ ] Managed capability projection changes only the qualified ECN fact, derives GRO, `receive_mode`, `coalescing` and `receive_enabled` from explicit coalescing/normalization activation rather than ECN-reader retention, preserves existing DF/other facts and never gains native GSO or packet-info by composition.
- [ ] Overlapping checked singletons preserve distinct payload/OOB/generation/result association without stale reuse; no parallel-throughput guarantee is added.
- [ ] Managed ECN-only receive drops one consumed malformed ancillary datagram and returns a following valid datagram, while unregistered non-GRO ancillary failure remains fatal.
- [ ] Lease release/reacquisition, stale generations, transport Close and endpoint Close preserve generation authority, join I/O and release retained metadata/socket state.
- [ ] `QUIC_GO_DISABLE_ECN`, ancillary setup denial, unavailable routes, malformed/absent/unmatched metadata and unsupported wrappers remain usable without claiming managed ECN or replaying a prior mark.
- [ ] `ConfigureManagedPacketIOV1` documents synchronous exact forwarding and unchanged checked-singleton result propagation; public signatures, ordinary one-datagram behavior, unregistered callers, selected-peer policy and batch definite-prefix/terminal-error semantics remain unchanged.

Every quantified criterion is limited to the representation contract above, owned by the endpoint/native parser and managed adapter, and terminated by the matrix/evidence budget rather than wrapper or ancillary-language exhaustiveness.
