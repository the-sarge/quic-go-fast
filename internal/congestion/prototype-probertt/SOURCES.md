The draft target pseudocode calls `BDPMultiple` with two arguments although its definition takes gain alone. This prototype deliberately interprets the documented half-BDP operation as `bandwidth * minRTT / 2`; this is an explicit translation choice. The proposal's saved cap is a volume, not a saved RTT that gets recomputed using a new bandwidth. Bandwidth is held fixed here.

The QUICHE `roundDone` display is a **diagnostic draft-style delivered boundary**, not a field read by QUICHE's exit logic. Upper/lower congestion bounds are assumed nonbinding; only the mode cap and four-packet floor are represented. In real QUICHE additional caps may dominate. Down-exit times are supplied by the harness; its Down/Up state machine is not executed. Startup, Drain, exit-to-Startup, restart during ProbeRTT and invalid/no-RTT events are outside this model. All runs begin in ProbeBW, already past pipe filling.

The integration investigation's [RTT/event contract](../../../docs/audits/2026-09-23-bbrv3-transport-integration.md#rtt-and-clocks) is respected as a boundary: all updates consume an explicit fresh ACK sample; BBR's minimum is separate from recovery's lifetime minimum and smoothed RTT. Registration equals modeled send time in this harness. Worker residence, batch timing, ACK eligibility in the real transport and ACK-delay policy require the other prototype and final design; this experiment selects none of them.
